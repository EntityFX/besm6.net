# besm6.net — симулятор ЭВМ БЭСМ-6

Архитектура программной модели, компоненты и правила исполнения: [ARCHITECTURE.md](ARCHITECTURE.md).

Достаточно точный симулятор советской ЭВМ **БЭСМ-6** на C#/.NET.
Проект воспроизводит архитектуру, набор команд, память, супервизор и систему
программирования «Дубна».

- **Зачем:** запускать настоящие программы и системное ПО БЭСМ-6 (в формате`.dub`
  задания, компиляторы Фортрана/Алгола, различные бенчмарки Dhrystone/Whetstone/
  STREAM/MP-MFLOPS), исследовать аппаратное поведение
  процессора, памяти и устройств.
- **На чём:** C#, платформа `net8.0`, без внешних рантайм-зависимостей. Собирается и
  работает на Windows, Linux и macOS.

## Внутреннее устройство

| Проект | Роль |
|---|---|
| `src/Besm6.Architecture` | Модель слова (48 бит), команд, АУ, режимов. Интерфейсы базовых типов. Без зависимостей. |
| `src/Besm6.Assembler` | Ассемблер БЭСМ-6: текст → восьмеричное слово. |
| `src/Besm6.Processor` | Реализация процессора: декодер, исполнение команд, тики, события. |
| `src/Besm6.Runtime` | Загрузчик, экстракоды, супервизор, устройства, память. |
| `src/Besm6.Cli` | Консольный симулятор `besm6` (`run`, `asm`, `disasm`, `check`). |

Граф зависимостей строгий и без циклов:
`Architecture → (Processor → Architecture) → (Assembler) → (Runtime) → CLI`.

## Требования

- [.NET SDK 8.0+](https://dotnet.microsoft.com/download) (сборка целится в `net8.0`).
- Для вспомогательных сценарных тестов необходим Python 3.12 (`tools/run_all_examples.py`).

## Сборка

```bash
# Восстановить и собрать всё решение
dotnet build Besm6.sln -c Release

# Только консольный симулятор
dotnet run --project src/Besm6.Cli -c Release -- <аргументы>
```

> Проекты `Besm6.BitVisualizer.WinForms*` компилируются только под Windows.
> На Linux/macOS для сборки остального решения они отключены автоматически.

## Использование (CLI)

После сборки исполняемый файл:
`src/Besm6.Cli/bin/Release/net8.0/besm6.dll`. Вызов через `dotnet <путь> <команда>`.

```bash
DLL=src/Besm6.Cli/bin/Release/net8.0/besm6.dll

# Выполнить задание .dub (файл с программой на Фортране/Алголе/Ассемблере)
dotnet $DLL run examples/algol.dub

# Режимы скорости: max — быстрый (по умолчанию), original — темп как на железе
dotnet $DLL run examples/algol.dub --speed original

# Производительность эмуляции на текущем хосте через гостевой CTIME
dotnet $DLL run examples/dhrystone-dmips.dub --speed virtual --guest-clock --stats --no-wall-clock

# Со статистикой исполнения и профилем горячего пути
dotnet $DLL run examples/algol.dub --stats --profile

# Ассемблировать и дизассемблировать отдельные команды
dotnet $DLL asm "сч 5"
dotnet $DLL disasm 05010

# Пакетно проверить все .dub в каталоге
dotnet $DLL check examples --limit 100000
```

Полный список ключей `run` — `dotnet $DLL help run`.

Псевдографика перфокарт с номерами колонок и рядов, например:
`dotnet $DLL punch --text "      A=B+3" --encoding upp`.
Поддерживаются форматы IBM/УПДК, УПП и вывод grid / ASCII / Braille;
[примеры и форматы](docs/punchcards.md).

Hosted-запуск `--speed original` использует статистическую модель УУ/АУ и МОЗУ
для гостевого таймера и замедления хоста. Стоимость математических экстракодов
оценена отдельно. `max` сохраняет прежний табличный таймер, `virtual` — таймер
хоста. [Источники, допущения и ограничения модели](docs/original-timing.md).
Калибровку original можно переопределить в JSON полями `originalTimeFactor`
и `originalMathFactor`; [пример настроек](examples/original-timing.json).

Для функционального исполнения с активными memory watchpoints доступна
опциональная настройка JSON `{"memoryWatchpointBatching": true}` (`--config`).
Пример конфигурации: [memory-watchpoint-batching.json](examples/memory-watchpoint-batching.json).
Она разрешает быстрые блоки с сохранением проверок чтения/записи и перехода
по watchpoint. По умолчанию выключена; fetch watchpoints, наблюдатели и
аппаратная модель сохраняют существующие ограничения исполнения.
Замеры и проверки: [быстрые блоки с memory watchpoints](reports/misc/dhrystone-memory-watchpoint-batching.md).

### Формат `.dub`

`.dub` — задание для системы «Дубна»: заголовок `*name`, тело программы
(Фортран/Алгол/Ассемблер в кавычках или управляющие строки) и `*execute`.
Более 50 примеров лежат в `examples/` (включая порты Dhrystone, Whetstone,
STREAM, MP-MFLOPS и матрицу CERNlib).

## Гостевые показатели производительности

`examples/memspeed-forex.dub` и `examples/mpmflops-forex.dub` выполняются
настоящим ФОРЕКС 4.13 и используют блочный `IF` для выбора ядра. Значение
`data kpart/1/` выбирает первый тест; замените 1 на 2 или 3 для остальных
ядер, на 0 — для запуска без ядра. Число итераций и арифметические
выражения сохранены из проверенных портов `*ftn`.

Программы самостоятельно печатают рейтинг после проверки результатов:
Memspeed — `GUEST MB/S` (copy/add/multiply-add, 6 байт на слово БЭСМ-6),
MPMFLOPS — `GUEST MFLOPS` (2/8/32 операции на слово).
CTIME измеряет только исполнение ядра; компиляция, подготовка, проверки
и печать находятся вне измеряемого интервала. При неверных контрольных
значениях, выключенном таймере или времени менее 40 мс рейтинг не выдаётся.

```sh
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/memspeed-forex.dub --guest-clock --speed original --stats --no-wall-clock --limit 200000000
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/mpmflops-forex.dub --guest-clock --speed virtual --stats --no-wall-clock --limit 200000000
./tools/verify_forex_kernels.ps1 -CheckGuards
```

Проверочный скрипт запускает все шесть ядер в `original`/`virtual`/`max`,
сверяет независимые численные результаты, объём данных, число операций,
формулы рейтингов и конечное состояние `original`/`max`. Защитные сценарии
проверяются в `max`: нулевое/недопустимое ядро, короткая нагрузка,
выключенный таймер и испорченный элемент. Для отдельного семейства:
`-Benchmarks memspeed` или `-Benchmarks mpmflops`.

`examples/dhrystone-forex.dub` — Dhrystone 2.1 для настоящего ФОРЕКС 4.13:
восемь подпрограмм и три функции, строки `CHARACTER*30`, подстроки,
сравнение строк, блочный `IF`, глобальные данные через `COMMON` и
двумерный целочисленный массив. Записи представлены полями массивов,
указатели — индексами двух узлов. Все 18 основных значений и четыре строки
проверяются после измерения. В отличие от старого варианта `*ftn`, тело
содержит реальные вызовы процедур; показатели разных портов зависят от
представления данных и сгенерированного кода.

```powershell
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/dhrystone-forex.dub --guest-clock --speed original --stats --no-wall-clock --limit 200000000
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/dhrystone-forex.dub --guest-clock --speed virtual --stats --no-wall-clock --limit 200000000
./tools/verify_forex_dhrystone.ps1 -CheckGuards
```

Скрипт проверяет 5000 и 10000 проходов в `original`/`virtual`/`max`,
независимые контрольные значения и строки, формулу DMIPS, одинаковое
состояние `original`/`max` и защитные сценарии: нулевая/короткая нагрузка,
выключенный таймер, неверное числовое значение и испорченная строка.
```

Параметры нагрузки находятся в исходниках: `numberofruns=5000` и `nruns=100`. Проверочный инструмент создаёт варианты во временном рабочем каталоге; исходные задания не переписывает. Рейтинг публикуется после контроля и при времени не менее 40 мс. Whetstone суммирует квантованные интервалы секций, поэтому для сравнительных измерений нужны повторные прогоны и достаточно длинная нагрузка.

## Веб-консоль

Запуск веб-консоли ASP.NET Core:

```powershell
dotnet run --project src/Besm6.AspNetCore.Web -c Release
```

Откройте локальный адрес, выведенный `dotnet run`, загрузите файл `.dub` и выберите отладку или полный запуск. Отладка начинается с паузы: можно смотреть регистры, память и текущую команду, затем выполнять команды по одной или продолжить работу. Каждое подключение браузера получает отдельный рабочий процесс и временный каталог; при отключении они удаляются. Bootstrap и SignalR раздаются из локальных файлов.

Интерфейс состоит из двух колонок: слева компактная карточка Job, регистры и память, справа — вкладки устройств. На узких экранах колонки располагаются друг под другом.

- **Machine** в заголовке Job выбирает Dubna, Dubna с буферной памятью БРЗ/БРС или supervisor в functional/hardware режиме. Первые два режима принимают `.dub`, supervisor — конфигурацию `.json`. При выборе Supervisor без загруженного образа подходящий готовый JSON загружается автоматически, с выбранным Full run: достаточно нажать **Run**. Свой загруженный JSON сохраняется при переключении functional/hardware. Доступны также Debug, шаги и продолжение.
- Расширенные регистры находятся слева под памятью: БРЗ/БРС, адресные буферы и регистры управления; supervisor также показывает специальные регистры, РП и РЗ. Четыре БРЧ и аппаратное время доступны в hardware. Снимки снимаются на границах инструкций; адресованные записи буферов показаны в порядке MRU, отдельно от физических слотов.
- **Auto-refresh** включает обновление регистров и памяти каждые 300 мс; по умолчанию выключено. На паузе, после шага и завершения состояние обновляется автоматически; **Go** запрашивает его вручную. Вывод устройств поступает независимо от галки.
- **Decode** у памяти показывает две декодированные инструкции рядом с каждым словом. Декодирование выполняется только при запросе состояния; отключённое Auto-refresh исключает периодическое чтение памяти и регистров во время работы.
- **Guest Clock** включает гостевые часы CTIME/STIME. **Statistics** собирает время, число инструкций, модельные циклы, MIPS и выделенную память; отчёт появляется после завершения или остановки.
- **Reset** останавливает задание и очищает машину и вывод. Загруженный `.dub` и настройки сохраняются для повторного запуска.
- **OCT / DEC / HEX** переключает регистры, память и адреса, включая поле перехода. Исходная система — OCT. 48-битные значения сохраняются точно.
- **Examples** содержит встроенные задания из `examples/`: поиск, просмотр исходника, **Load into machine** и **Run example**. Запуск использует настройки Job; Debug начинается с паузы. Обычная загрузка собственных `.dub` также доступна.
- Готовые JSON выбираются в том же списке: [Dhrystone Maximum](examples/web-jobs/dhrystone-max.json), [Original](examples/web-jobs/dhrystone-original.json), [Virtual](examples/web-jobs/dhrystone-virtual.json), [Debug](examples/web-jobs/dhrystone-debug.json), [Supervisor functional](examples/machines/supervisor-functional.json) и [Supervisor hardware](examples/machines/supervisor-hardware.json). Введите `web-jobs` или `machines` в поиск, выберите файл и нажмите **Run example**. JSON можно также загрузить файлом или вставить в Editor.
- **Edit copy** переносит пример в **Editor**. В редактор можно вставить своё полное задание `.dub`, просмотреть подсветку и выполнить **Run text**. Подсветка распознаёт управляющие карты, Fortran/ФОРЕКС, Algol и мнемоники ассемблера; исходники выводятся как текст. Правка редактора во время исполнения готовит следующее задание.
- **Card generator** кодирует текст и декодирует ручную пробивку IBM/УПП, проверяет нечётность и сохраняет SVG точного физического размера и PNG 600 dpi. [Описание форматов и геометрии](docs/punchcards.md).
- **Instructions** кодирует и декодирует 24-битную инструкцию или 48-битное слово: Автокод (`СЧ M3 00123`), БЕМШ (`сч 3,00123`) и Madlen (` ,xta,3 00123,`). Доступны поля команды, кликабельные биты и OCT/HEX/DEC/BIN; при изменении одной половины слова другая сохраняется.
- **Punch cards → Format** переключает Braille, ASCII, Grid и физический вид карт после пробивки. Выбор меняет представление уже полученных карт.
- **Terminal** принимает строки для гостевого `*71` и телетайпа. Когда программа ждёт ввод, статус меняется на **WaitingInput**, открывается вкладка терминала; **Send line** продолжает выполнение. Можно заранее передать строку гостевому терминалу, остановить ожидающую программу или выполнить Reset.
- **Storage** показывает штатные ленты и загруженные образы: чтение слов и текста KOI-7, дизассемблирование, **Copy to memory**, **Mount / Unmount**. Свои образы — плотные 48-битные слова big-endian, 6 байт на слово, до 8 MB; в зоне 1024 слова. Поля адресов и смещений используют выбранную OCT/DEC/HEX, идентификатор тома задаётся в HEX. Единицы лент/дисков — `30–67` OCT, барабанов — `0–37` OCT. Доступны диапазоны до 128 слов; дизассемблер трактует каждое слово как пару команд.

Монтирование, просмотр носителя и копирование в память выполняются на паузе, после остановки или до запуска. **Read only** включён по умолчанию; занятый накопитель заменяется с галкой **Replace**. Загрузчик использует устройство `30` OCT для MONSYS и барабан `1` для задания; другие устройства позволяют подключать данные к исходной программе. Свои смонтированные образы сохраняются между запусками в пределах сессии, гостевая запись изменяет их сессионные копии. Подключение другого браузера создаёт отдельный набор носителей.

**Dubna + БРЗ/БРС** использует согласованные hosted-буферы: создаваемые и изменяемые MONSYS команды видны при выборке, включая ещё не вытесненные записи БРЗ. Контрольные разряды формируются для нетипизированных слов Dubna; аппаратная изоляция команд и чисел в этом режиме не моделируется. Строгий `new MachineCore(MemoryModel.Buffered)` и supervisor сохраняют прежние правила контрольных разрядов и видимости буферов. Дополнительная работа буферов делает этот режим медленнее обычной Dubna. Supervisor использует самостоятельную модель и явные параметры аппаратного времени из JSON; накопители и устройства задаются в его конфигурации. Элементы монтирования Dubna к нему не применяются. В веб-конфигурации разрешены только файлы образов внутри каталога текущей сессии.

JSON с `"kind": "web-job"` — настройки веб-запуска: `example` ссылается на встроенный `.dub`, `machineModel` выбирает `dubna`/`buffered`, далее задаются `mode`, `speed`, `instructionLimit`, `guestClock`, `statistics`, `autoRefresh`, `decodeMemory`. Настройки применяются при загрузке; затем их можно изменить в Job. Dhrystone запускает 5000 проходов FOREX, проверяет 18 числовых и 4 строковых результата, включает гостевые часы и статистику; автообновление и декодирование отключены. Такой JSON разрешается до старта worker и не добавляет обработчиков в цикл CPU. Это формат веб-консоли; самостоятельные supervisor JSON сохраняют прежний формат команды CLI `machine`.

Для Dhrystone с БРЗ/БРС готов отдельный [JSON buffered](examples/web-jobs/dhrystone-buffered.json). Он использует ту же программу и гостевые часы Maximum; результаты и модельные циклы сравниваются с обычной Dubna.

В CLI `run --buffered-memory` включает ту же буферную модель, а `--machine-state` у `run` и `machine` выводит расширенные регистры после выполнения. `--dump-mem FILE` сохраняет прежний бинарный формат (6 байт на слово) и соседний `FILE.disasm.txt`. Снимок `--dump-at` делается на заданной инструкции, после чего обработчик отключается; текстовая расшифровка сохранённого снимка формируется после выполнения.

Вкладки устройств показывают принтер, перфокарты, плоттеры Watanabe/Calcomp/Tektronix, терминал и накопители. Шрифт Braille поставляется локально. Непрерывное выполнение работает блоками на отдельном потоке; вывод объединяется в порции, а доставка сообщений вынесена из потока машины. Для сравнения скорости с консолью используйте одинаковую конфигурацию **Release**, скорость и галки Statistics/Guest Clock.

Для воспроизводимой проверки интерфейса, экспорта, примеров и нескольких сессий используйте [браузерные проверки](tools/Besm6.Web.UiChecks/README.md).
