# Текстовая визуализация перфокарт

## Генератор в веб-консоли

Вкладка **Card generator** содержит редактор одной перфокарты. **IBM** размещает символ в колонке (80 символов), **УПП-IBM** — семь бит кода и бит нечётности по горизонтали, 10 символов в ряду (120 символов). Таблицы поступают из того же `PunchCardCodec`, который использует CLI. Панель символов показывает алфавит выбранного исторического формата; неподдерживаемые знаки и превышение вместимости вызывают сообщение, без замены на ASCII.

Ввод текста меняет пробивку, клик по ячейке — текст. Доступны выбор ряда и колонки, клавиши со стрелками и пробел. Неизвестное сочетание отверстий обозначается `�`; для УПП отдельно отмечаются ошибки нечётности. Кириллические и латинские буквы с общим кодом декодируются в канонический знак. В IBM непробитая колонка и пробел неразличимы, поэтому при ручном декодировании незаполненный хвост убирается.

Физическая геометрия соответствует заданным размерам:

| Параметр | Миллиметры |
|---|---|
| Карта | 187.325 × 82.55 |
| Срез слева сверху под 45° | 6.35 |
| Прямоугольное отверстие без скругления | 1.397 × 3.175 |
| Шаг колонок / рядов | 2.2098 / 6.35 |
| Левый верхний угол первого отверстия | x = 4.5466, y = 4.7625 |

SVG задаёт `width` и `height` в миллиметрах, `viewBox` в тех же единицах. Подписи колонок 1, 2, 4…80 находятся между рядами 11 и 0; линии сетки отсутствуют. Экспорт исключает интерактивные области редактора. Для печати 1:1 выбирайте 100%, без подгонки к странице. PNG создаётся размером 4425 × 1950 пикселей с метаданными 600 dpi; срез угла остаётся прозрачным.

Символ `⑩` соответствует десятичному показателю: IBM — ряды 0, 7, 8; УПП — код ГОСТ `020` с нечётностью. `◊` в УПП использует код ромба ГОСТ; `␣` — явное обозначение пробела. В колонном формате `␣` имеет отдельную пробивку, как в исходной таблице.

## Команда CLI

Команда `punch` переводит текст в матрицу отверстий 80 × 12 и выводит её
без графики. Запуск после сборки `dotnet build src/Besm6.Cli -c Release`:

```powershell
$besm6 = 'src/Besm6.Cli/bin/Release/net8.0/besm6.dll'

# Одна строка FORTRAN, включая шесть ведущих пробелов
dotnet $besm6 punch --text '      A=B+3' --encoding ibm
dotnet $besm6 punch --text '      A=B+3' --encoding upp

# Файл UTF-8: одна строка — одна карта; результат тоже UTF-8
dotnet $besm6 punch examples/punchcard-expression.txt --encoding upp --output tests-run/cards.txt

# ASCII для терминала без Unicode; компактный восьмиточечный Braille
dotnet $besm6 punch --text '      A=B+3' --encoding ibm --format ascii
dotnet $besm6 punch --text '      A=B+3' --encoding upp --format braille

# stdin и справка
'      A=B+3' | dotnet $besm6 punch - --encoding upp
dotnet $besm6 punch --help
```

## Кодирование

| `--encoding` | Размещение | Вместимость | Метки рядов в сетке |
|---|---|---|---|
| `ibm` (синоним `updk`) | один символ в колонке; сочетание отверстий по таблице IBM/УПДК | 80 символов | 12, 11, 0, 1…9 |
| `upp` (по умолчанию) | восемь соседних позиций вдоль ряда: старший бит контроля и семь бит кода | 120 символов | 01…12 сверху вниз |

В УПП каждый закодированный символ содержит нечётное число отверстий.
Пробел — `10001111`; непробитая группа `00000000` обозначает неиспользованное
место. В колонном формате обычный пробел не пробивается.

Регистр переводится в верхний. Совпадающие по начертанию кириллические и
латинские буквы используют общие коды; например, `А` и `A`, `В` и `B`.
Кодировки не являются ASCII. Непредставимые символы (включая табуляцию),
а также превышение вместимости вызывают ошибку с номером строки.
Переноса или усечения длинных строк нет.

Ведущие и завершающие пробелы сохраняются. Пустая строка файла создаёт пустую
карту; завершающий перевод строки не добавляет лишнюю карту. Пустой файл даёт
пустую колоду, а `--text ''` — одну пустую карту. Без файла и `--text` читается stdin.
Для FORTRAN следует передавать нужные отступы явно: команда не форматирует программу.

## Вид вывода

`--format grid` (по умолчанию) показывает все 12 рядов и 80 колонок.
Номер колонки складывается из цифр в строках `Tens` и `Units`.
`●` — отверстие, `·` — картон. Промежутки между группами по восемь позиций
добавлены для удобства чтения и не обозначают дополнительные колонки.
В ASCII используются `O` и `.`. Braille занимает три строки по 40 символов
и пустую строку между картами, без заголовков и координат.

Для `      A=B+3` расположение символов получается таким:

| Формат | Ряд | Колонки | Символы |
|---|---|---|---|
| IBM/УПДК | по всей высоте карты | 1–6 | шесть непробитых колонок |
| IBM/УПДК | по всей высоте карты | 7–11 | `A=B+3` |
| УПП | 01 | 1–48 | шесть пробелов |
| УПП | 01 | 49–80 | `A=B+` |
| УПП | 02 | 1–8 | `3` |

Это визуализация текстового содержимого: служебные карты задания, признаки
конца массива и прочее оформление колоды конкретной ОС автоматически не добавляются.
Результат команды — текст для просмотра, а не готовая колода для загрузчика.

## Связь с эмулятором

`PunchCardCodec.Encode` возвращает `PunchCardImage`. Его методы
`FromMemoryImage` и `ToMemoryImage` работают с форматом `Puncher`: 144 байта,
24 слова по 48 бит. Каждый физический ряд занимает два слова с 40 полезными
битами и восемью старшими битами заполнения. Это 960 позиций карты,
а не 1152 полезных бита. Методы `IsPunched` используют индексы с нуля.

`PunchCardRenderer` предоставляет сетку и Braille. Существующий `Puncher`
использует тот же Braille-рендерер для `punch.out`; формат файла сохранён.
Обработка стандартных и COSY-массивов остаётся отдельной задачей `Puncher`.

Источники таблиц: [колонный код из книги о ДИСПАК, с. 74](https://sergev.org/besm/upp-ibm),
[описание УПП и таблица символов Леонида Брухиса](https://www.mailcom.com/besm6/encoding.html).
