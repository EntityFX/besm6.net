# Математическая память и границы аппаратной модели

`MemoryModel.Mapped` подключает приписку, защиту и адресные буферы к
существующему `Processor`. Обработчики команд, АУ, округление и правила
авоста Dubna остаются общими. Выбор памяти независим от `original|max`.
Это функциональный, последовательный уровень памяти: нет предвыборки,
занятых запросов, перекрытия АУ/УУ и времени банков.

```csharp
var machine = new MachineCore(memoryModel: MemoryModel.Mapped);
var memory = machine.MappedMemory!;
memory.SetPhysicalPage(0, 8);
memory.SetPhysicalPage(1, 9);
// Memory у машины — физический, согласованный загрузчик/наблюдатель.
machine.Memory.Write(8200, new Word48(Besm6.Asm.Assembler.Asm("xta 2000, stop")));
machine.Memory.Write(9216, new Word48(123));
memory.Supervisor = false;
memory.AssignmentBlocked = false;
memory.ProtectionBlocked = false;
machine.Cpu.StartAt(8); // Математический адрес начала, левая половина.
var loader = new DubnaLoader(machine) { Speed = ExecutionSpeed.Max };
loader.RunLoaded();
```

Размер — 32768 слов. Начальные правильные числовые нули, пустые буферы,
нулевая приписка и установленные Supervisor/БлП/БлЗ — программная
инициализация адаптера, **не установленное состояние холодного сброса**.
Флаги управляются хостом: они пока не являются регистрами M17/РУУ CPU.
Привилегированные команды и переходы диспетчера относятся к этапу 4;
CLI-флаг аппаратного профиля до их реализации не вводится.

## Адреса, попадания и публикация

БАЗ/БАС представлены `MemoryRequestAddress`: 15-разрядный адрес и отдельный
признак физического запроса. Для операнда признак задаётся БлП, для команды
— режимом Supervisor. Попадание сравнивает весь тег; два математических
адреса одной физической ячейки и одинаковые адреса с разными признаками
не сливаются. БРЗ содержит только записи, БРС — целые командные слова из
МОЗУ или пульта. Команда никогда не выбирается из БРЗ.

Трансляция математического тега выполняется при чтении МОЗУ или публикации
БРЗ. Поэтому низкоуровневый `Assignment.SetPhysicalPage` без синхронизации
может перенаправить ожидающую запись. Для согласованного изменения нужно
использовать `MappedMemoryBackend.SetPhysicalPage/ImportAssignmentGroup`:
они сначала проверяют все параметры, затем публикуют БРЗ по старой
приписке и только после этого меняют РП. Опубликованные записи освобождаются;
сохранённая «чистая» копия не может выдать старый операнд после remap.

Восемь БРЗ и четыре БРС имеют независимый порядок давности без таймера.
При заполнении БРЗ следующая новая запись публикует самый давний элемент.
`FlushOperands` публикует от давнего к свежему. Это последовательная
функциональная граница, а не расписание выталкивания физической машины.
Особое поведение занятого старшего БРЗ (ТО-2 §4.19) требует учёта запросов
в полёте и относится к модели времени этапа 5.

При смене РП БРС автоматически не очищается: тёплый тег сохраняет старое
слово. Закрытие страницы РП=0 всё равно запрещает команду **до** попадания.
`ClearInstructionBuffer` — явная операция хоста. Снимок БРС дополнительно
сохраняет физический адрес исходной выборки, включая контрольную ошибку
старого слова после remap.

## Защита, ноль, пульт и контроль

Защита операнда проверяется по математической странице до изменения БРЗ,
проверки контроля и чтения МОЗУ; БлП и БлЗ независимы. Для команд матрежима
РП=0 закрывает страницу независимо от БлЗ. Supervisor выбирает команду
напрямую без защиты припиской. Числовой ноль не обращается к памяти;
общий CPU сохраняет запрет перехода на адрес ноль.

При БлП=1 адреса 1–7 обращаются к отдельным пультовым словам. Чтение
использует 50-разрядное слово с обычной проверкой контроля. Запись не меняет
пульт: девять последовательных записей гарантируют публикацию восьми БРЗ.
В этой модели первая запись начинает последовательность, последующие
публикуют по одному самому давнему элементу; обычная запись начинает счёт
заново. Точные моменты выдачи запроса и аппаратные пакеты пульта здесь
не моделируются. Пультовые слова устанавливаются только `SetPanel` хоста.

Выбранное правило освобождения от защиты для Supervisor и адресов 1–7
следует буквальному тексту ТО-8 §4.26 и существующему `PageAssignment`:
оно не требует БлП. SIMH дополнительно требует БлП; это расхождение явно
сохранено. Математическая трансляция в физические ячейки 1–7 остаётся
доступом к МОЗУ, как в существующей спецификации `PageAssignment`;
SIMH перенаправляет её на пульт. Нет молчаливой смены ранее принятого правила.

ATX формирует числовые контрольные разряды и оставляет результат на БРЗ.
Хост может отдельно задавать инверсию каждой половины для проверки
смешанного контроля. Контроль команды проверяется по выбранной половине;
операнд — по всему 50-разрядному слову. Контрольное нарушение команды
после промаха оставляет выбранное слово на БРС, как обычная выборка.

`StoreCommand`, используемый hosted CTX (`*75`), проверяет адрес и защиту
операнда, публикует старые записи, формирует командный контроль, записывает
МОЗУ и согласует следующую выборку. Настройка контроля ATX сохраняется.
Это результат экстракода из книги 1976 года §6; автоматическое согласование
БРС — контракт существующего диспетчера Dubna, **не утверждение об аппаратном
CTX или последовательности супервизорных команд**. Такой последовательности
предстоит выполняться через ОС на этапе 4.

## Ошибки и жизненный цикл

`LastFault` сохраняет запрос, вид доступа, источник (защита, БРЗ, БРС,
МОЗУ или пульт) и доступный физический адрес. Защита и контроль остаются
разными типами исключений, не `ProcessorException`. Они не расходуют
перехват гостевого авоста, не начисляют тик и уведомление за незавершённую
команду. Ранее выполненные команды остаются учтены. Позиция CPU сохраняет
существующее правило продвижения половины до обработчика операнда.

Сигнал остаётся до `ClearFault`, в том числе после успешного доступа.
Аппаратная доставка прерывания и сохранение регистров диспетчера — этап 4;
этот сигнал ещё не означает выполнение аппаратного входа в прерывание.
`ResetCpu` не меняет память, приписку, режим адаптера, буферы, сигнал,
часы и очередь. Повторная загрузка через физический HostMemory заменяет
МОЗУ и удаляет совпадающие копии, не проверяя гостевую защиту или контроль.
Для математического запуска адрес начала задаётся отдельно через `StartAt`.

## Источники и роль SIMH

Первичные источники: ТО-8 редакции 1–67, §4.2–4.11, §4.15,
§4.19–4.28; ТО-2 редакции 1–65, листы 50–51, 62–66, 69, 95;
[книга по Фортрану 1976 года, §3/6](../book/fortran-1976/01-besm6.md).
Ссылки и SHA-256 сканов закреплены в
[спецификации запросов](besm6-memory-requests.md) и
[спецификации регистров](besm6-memory-registers.md).

Дополнительная модель — [SIMH BESM6 MMU](https://github.com/simh/simh/blob/9e318d16a203a3efae3420ea3f5700a8d7e3bec3/BESM6/besm6_mmu.c),
закреплённая ревизия `9e318d16a203a3efae3420ea3f5700a8d7e3bec3`.
Сравнение полного тега подтверждается `mmu_match` и `mmu_prefetch`, поздняя
трансляция — `mmu_flush`, проверка закрытой страницы до БРС — `mmu_fetch`.
В книгах подтверждены адресные регистры и отдельные физические признаки;
полный состав входов всех сравнителей пока не доказан схемой. Поэтому
выбор полного тега дополнительно опирается на SIMH, а не выдаётся за
независимый результат чтения аппаратной схемы.

`mmu_flush_by_age` содержит явно описанный авторами подбор алгоритма для
теста УУ. Его нельзя принимать как доказательство точного аппаратного
расписания. Из SIMH также не перенесены проверка контроля всего командного
слова вместо выбранной половины, дополнительные адресные разряды расширенной
памяти и прерывания. Выполнена сверка исходного кода; сравнительный запуск
гостевых заданий в SIMH в эту приёмку не входит.

## Приёмка

Проверяются alias и различие тегов, поздняя трансляция, согласованный remap,
атомарный отказ изменения РП, БлП/БлЗ, тёплая защита, половины команд,
публикация/устаревание БРС, пульт, CTX, watchpoints, ошибки, события, STOP,
сброс и повторный запуск. Все 32767 ненулевых математических адресов операнда
проверены через новый backend. Книжные векторы АУ и авостов выполняются
с реальной припиской в обоих режимах скорости. Совместимый CERN-гейт
проверяет профиль Dubna; он не заменяет будущую приёмку аппаратной ОС.

Результаты полной проверки и замеры сохранены в
[отчёте математической памяти](../reports/memory-mapped-report.md).
