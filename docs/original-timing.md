# Статистическое время hosted-заданий в original

`besm6 run job.dub --speed original` использует отдельную статистическую
модель УУ, АУ и МОЗУ для CTIME/STIME и замедления хоста. Модель наблюдает прежнее
функциональное исполнение, сохраняя арифметику, память и число инструкций.
Supervisor-запуск `machine --execution hardware` сохраняет свою модель.

## Источники и допущения

Длительности компонентов команд взяты из существующей
[`BookTimingSpecification`](../src/Besm6.Runtime/Timing/Specifications/BookInstructionTiming.cs):
Салтыков/Макаренко, «Программирование на Фортране», 1976, приложение 1,
стр. 247–249; [транскрипция](../book/fortran-1976/05-appendices.md).
Такт этого источника — 110 нс. Средние интервалы АУ: сложение 11 тактов,
умножение 18, деление 50. Это компонентные времена, не полная стоимость команды.

Раздельные времена УУ и АУ позволяют независимым индексным командам
перекрываться с арифметикой. Последовательные операции АУ ожидают предыдущую;
записи сумматора и переходы по нему ожидают готовность АУ. ATI/STI/WTC должны
завершить передачу в индекс-регистр/модификатор до следующей команды.
Это выбранная схема зависимостей, не реконструкция очереди микрокоманд.

После калибровки выборка команды перекрывается с УУ на величину до 900 нс;
возврат операнда задерживает АУ, а не независимую работу УУ. В теневом буфере
операндов сохраняется адрес записанного слова после окончания записи, пока
запись не вытеснена. Размеры буферов остались 8 + 8 слов. Для сложения,
вычитания и умножения с выключенной нормализацией используется книжный минимум
вместо среднего. Полное скрытие задержки выборки, политика сохранения записей
и выбор минимума по режиму — статистические допущения, не доказанная схема БЭСМ-6.

Из двух опубликованных интервалов условного перехода выбран больший для
взятого перехода и меньший для невзятого. Учитывается условие команды, включая
переход на следующий адрес. Книжный источник не устанавливает соответствие
интервалов исходам; это допущение согласовано с комментариями
[SIMH cpu_one_inst](https://github.com/besm6/simh/blob/master/BESM6/besm6_cpu.c).
SIMH сейчас не использует эти `delay` для собственного счётчика времени.

МОЗУ: восемь банков по младшим трём битам адреса, занятость банка 2000 нс,
возврат чтения 900 нс; основания сохранены в
[`MramReadTiming`](../src/Besm6.Runtime/Timing/Memory/MramReadTiming.cs).
Буферный доступ оценён в 220 нс. Приняты восемь записей буфера команд,
восемь операндов и восемь ожидающих записей, FIFO-замещение. Эти теневые адресные
буферы считают время, не подменяя функциональную память. Чтение ожидающей записи
использует forwarding; запись сбрасывает совпадающую запись буфера команд
и сохраняет актуальный адрес в буфере операндов.
Полный буфер записи заставляет УУ ждать свободное место. Банковый арбитраж
и замещение — выбранная логическая политика, не доказанная электрическая схема.

ASN использует расстояние сдвига: 4 + |n| тактов АУ. ASX использует верхнюю
границу 68 тактов: ради тайминга гостевая память повторно не читается.
Для команд вне книжной таблицы и обычных hosted-сервисов сохранён прежний
запасной интервал. Экстракод — последовательная граница; после него теневые
буферы сбрасываются, поскольку сервис может заменить произвольный код/данные.

## Математические экстракоды

По выбранному пользователем варианту результаты функций вычисляет прежний
код, а время учитывается статистически. Базовые оценки на вызов:

| Функция | мкс |
|---|---:|
| SQRT | 40 |
| SIN, COS | 50 |
| ATAN | 80 |
| ASIN | 120 |
| LOG | 80 |
| EXP | 60 |
| FLOOR и прочие hosted-сервисы | 5 |

**Это допущения, не найденная таблица измерений БЭСМ-6.** Отдельных доказательств
точности значений нет. Оценки различают стоимость программных функций вместо
прежних одинаковых 5 мкс; зависимость от аргумента, ОС и версии библиотеки
не восстановлена. SQRT принят дешевле LOG, ASIN дороже ATAN; эти соотношения
также являются допущениями. Это не исполнение исторических подпрограмм.

[Whetstone 2017 года](https://retrocomputing.stackexchange.com/questions/3267/how-to-compute-performance-of-a-cpu-in-flops)
используется для сравнения секций и, после прямого запроса пользователя,
для явной калибровки к 0.809 MWIPS (см. отдельный раздел ниже).
В нём другая ОС, версия ФОРЕКС и численные результаты. Сводные N5/N8 не позволяют
независимо определить стоимость каждой функции. Рейтинг original — оценка этой
модели; совпадение численных контролей не доказывает историческую точность времени.

## Режимы и статистика

- `original`: новое статистическое время CTIME/STIME, квантованное по 20 мс;
  замедление хоста по тому же времени и абсолютным дедлайнам.
- `max`: прежнее быстрое исполнение и табличное время CTIME/STIME.
- `virtual`: прежнее быстрое исполнение и CTIME/STIME по времени хоста.

`--guest-clock` по-прежнему нужен для ненулевого таймера. DATE* определяется
`useWallClock` независимо от CPU-времени. В original появляется
`statisticalModelSeconds`, и `modelSeconds` использует его. `modelCycles`
сохраняет прежний счётчик для совместимости: переводить его в новое время
original умножением на 100 нс нельзя. В JSON max/virtual новое поле отсутствует.

У таймированных заданий original и max теперь отличаются время и рейтинги.
Проверка Whetstone должна сопоставлять вычисленные значения и нагрузку,
сохраняя независимые проверки формул для каждого режима.

## Проверки

Тесты проверяют перекрытие УУ/АУ, ожидание результата, конфликты банков,
попадания, forwarding, ожидание места записи, адресную модификацию математического
вызова и снятие наблюдателей. Runtime-корпус проверяет совместимость состояний
функциональных моделей памяти; CTIME-тесты отдельно проверяют новое время
original и прежнее время max.

Первый прогон до калибровки `whetstone-longbottom-forex.dub` от 12.10.2026:
все восемь независимых значений и формулы рейтингов прошли в трёх режимах.
Новый original: 0.460395 MWIPS, геометрическое среднее 0.195537 MFLOPS;
нормализованная сумма секций 173.764 с. Полное модельное время запуска
190.31851726 с, фактическое 190.3188743 с. Это ниже опубликованных 0.809 MWIPS;
совпадение с исторической машиной не заявляется. N6/N7 остаются наиболее
заметным расхождением по сравнению с опубликованными временами.

Max сохранил 3.994408 MWIPS и 1.242504 MFLOPS, точный гостевой вывод,
конечное состояние, SHA-256 памяти и числа инструкций/табличных тактов.
Virtual дал 14.450867 MWIPS и 4.702231 MFLOPS; его рейтинг по-прежнему
зависит от скорости хоста. Проверено 1441 тест Runtime, 1615 Processor,
35 CLI и 89 Python-проверок инструментов. PowerShell недоступен в окружении:
изменённые `.ps1` напрямую не выполнялись; значения/формулы Whetstone
перепроверены независимо по сохранённым логам через Python.

## Калибровка к опубликованным 0.809 MWIPS

По прямому запросу пользователя добавлены два эмпирических коэффициента:
`ModelTimeFactor = 0.670839` для полного времени статистического календаря и
`MathFactor = 1.769005` для математических функций с базовой стоимостью больше
5 мкс. Таймеры и прочие сервисы не получают дополнительный MathFactor;
ModelTimeFactor применяется ко всему CPU-времени original. Частота и значения
книжной таблицы в источнике сохранены, но итоговое калиброванное время уже
нельзя интерпретировать как прямую сумму физических книжных задержек.

Фит выполнен по двум данным из одного опубликованного прогона: сумме всех
секций 98.856 с и сумме N5 + N8 = 34.448 с. Пробный однопроходный replay
экстраполирован на восемь проходов; окончательные коэффициенты уточнены по
полному прогону (короткая проба меняет раскладку скомпилированной программы
и не гарантирует точной экстраполяции). При неизменных базовых ценах функций
N5 содержит 14.336 с математических вызовов, N8 — 13.392 с. Сначала подобран
масштаб остальных шести секций, затем цена математических функций. Обе
коэффициентные оценки округлены до шести знаков.

Это явно выполненная подгонка, не независимая проверка исторической точности.
Один итоговый рейтинг не определяет параметры конвейеров, памяти или функций.
Секции, версия ФОРЕКС, ОС и численные результаты отличаются от публикации;
совпадение итогового MWIPS не означает совпадения всех секций или MFLOPS.
Параметры не зависят от имени задания, адресов Whetstone или распознавания
секций в production-коде: они действуют на все hosted-задания original.

Пробы сохраняются отдельно в `tests-run/whetstone-calibration-*`.
[`tools/calibrate_original_timing.py`](../tools/calibrate_original_timing.py)
позволяет повторить сравнение вариантов на общем функциональном исполнении.
Пример для окончательного профиля:

```bash
python3 tools/calibrate_original_timing.py --output tests-run/new-calibration \
  --operand-capacities 8 --math-factor 1.769005 --time-factor 0.670839
```

Требуется свежий каталог. Проба работает с одной восьмой нагрузки и не выдаёт
её за полноценный валидированный рейтинг; выбранные параметры дополнительно
проверяются обычным CLI на исходном восьмипроходном задании. Max/virtual
продолжают работать с прежними таймерами и не используют эти коэффициенты.

## Настройки коэффициентов

Оба коэффициента доступны через `Config`, `DubnaLoader` и JSON-файл `--config`:

```json
{
  "originalTimeFactor": 0.670839,
  "originalMathFactor": 1.769005
}
```

Они должны быть конечными числами больше нуля. По умолчанию используются
значения из калибровки выше. Значения `1` отключают соответствующий эмпирический
множитель, сохраняя остальные правила новой модели. Коэффициенты фиксируются
при начале запуска и не меняют max/virtual. Полный пример:
[`examples/original-timing.json`](../examples/original-timing.json).

```bash
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run \
  examples/whetstone-longbottom-forex.dub --config examples/original-timing.json --stats
```

Окончательный полный прогон: **0.809307 MWIPS**, 98.850 с нормализованного
времени; полное время модели 106.604398952 с, хоста 106.6049345 с. Все восемь
контролей и формулы прошли. Сравнение с данными, использованными для фита:

| Секция | Публикация, с | Калиброванная модель, с |
|---|---:|---:|
| N1 | 0.293 | 0.190 |
| N2 | 2.674 | 1.720 |
| N3 | 4.477 | 3.200 |
| N4 | 7.280 | 3.860 |
| N5 | 18.361 | 18.120 |
| N6 | 35.720 | 36.960 |
| N7 | 13.963 | 18.460 |
| N8 | 16.087 | 16.340 |

Геометрическое среднее MFLOPS 0.389304, в публикации 0.295. Таким образом,
цель 0.809 достигнута для округлённого общего рейтинга, а историческое совпадение
секций и MFLOPS не достигнуто. Проверка фита не является независимой валидацией.
