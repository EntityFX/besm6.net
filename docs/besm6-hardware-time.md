# Этап 5: отдельная шкала аппаратного времени

Срез: 10 октября 2026 года. Реализован первый инфраструктурный блок;
аппаратный конвейер CPU и временные задержки устройств ещё не включены.

## Подтверждённые данные

Источник — Салтыков/Макаренко, «Программирование на языке Фортран»,
1976: §4, печатная стр.21 и приложение1, стр.247–249. Проверены сканы
[21](../book/fortran-1976/original/page-021.png),
[247](../book/fortran-1976/original/page-247.png),
[248](../book/fortran-1976/original/page-248.png),
[249](../book/fortran-1976/original/page-249.png).
SHA256 и границы утверждений: [аудит](../reports/hardware-time-source-audit.json).

`BookTimingSpecification` хранит 47 опубликованных строк: времена УУ
и отдельные minimum/average/maximum АУ. Книжный такт этого источника —
110 нс. Среднее2,5 такта представлено точно как275 нс; у сдвигов среднее
отсутствует. Два значения условного перехода сохраняют порядок печати,
но их соответствие исходу перехода пока не задано.

Среднее АУ не является сроком конкретной команды. Времена УУ/АУ
не складываются автоматически; отсутствие строки не заменяется числом
по умолчанию. Например, STOP, необозначенные привилегированные операции
и экстракоды возвращают `TryGet=false`. 110 нс не объявляются тактом
каждой исторической конфигурации БЭСМ-6.

## API и единицы

- `HardwareInstant` — абсолютные наносекунды отдельной шкалы.
- `HardwareDuration` — длительность в наносекундах. Сложение проверяет
  переполнение; отрицательный интервал отклоняется.
- `HardwareTimeline` — детерминированный календарь без часов хоста.
  События упорядочены по времени и регистрации. Callback может добавлять
  и отменять события, включая событие текущего момента; вложенное
  продвижение времени отклоняется.
- `HardwareEventToken` принадлежит конкретному календарю. Чужой,
  отменённый, выполненный или пустой токен не отменяет событие.
- Ошибка callback оформляется как `HardwareCallbackException` с исходной
  причиной и временем; уже доставленное событие удалено, оставшаяся
  очередь сохранена. Время остаётся на границе ошибки; продвижение
  можно продолжить отдельным вызовом.
- `HardwareResourceCalendar` резервирует явно заданные независимые
  ресурсы: начало=max(самый ранний срок, готовность ресурса),
  конец=начало+занятость. Переполнение не изменяет резервирование.
  Отмена события не снимает резервирование; эта примитива не задаёт
  аппаратной политики отмены или арбитража.

Конструктор календаря ресурсов не создаёт скрыто восемь банков, АУ,
буферы или каналы. Топологию и длительности задаёт вызывающая модель.
Готовность данных и освобождение ресурса — отдельные величины:
цикл восстановления памяти нельзя автоматически выдать за задержку
возврата операнда. Проверки с синтетическими длительностями подтверждают
сам календарь, а не историческую схемотехнику.

```csharp
using Besm6.Runtime.Timing;

var timeline = new HardwareTimeline();
var au = new HardwareResource(HardwareResourceKind.ArithmeticUnit);
var resources = new HardwareResourceCalendar(new[] { au });
// Синтетический пример API, не расчёт длительности команды БЭСМ-6.
var reservation = resources.Reserve(au, timeline.Now, new HardwareDuration(550));
int published = 0;
timeline.ScheduleAt(reservation.Finish, () => published = 42);
timeline.AdvanceTo(reservation.Finish);
Console.WriteLine(published); // 42
```

## Совместимость и следующие блоки

Новые типы пока не подключены к `MachineCore` и общим обработчикам CPU.
`SimulationClock` сохраняет один тик на завершённый шаг, включая STOP.
`Besm6Timing`, его100 нс, pacing original, DATE*, лимиты и действующие
устройства не меняются. В календаре нет различия original/max:
он движется только по явно указанным гостевым временам.

| Блок этапа 5 | Статус | Необходимое подтверждение |
|---|---|---|
| Единицы времени и опубликованные диапазоны | Реализован | Сверенные сканы и независимые векторы |
| Календарь событий и ресурсов | Реализован как инфраструктура | Порядок, отмена, ошибки, переполнение, зависимости |
| Длительность АУ для конкретных операндов | Не реализован | Последовательности АУ, нормализация и округление по техническому описанию |
| Занятость и перекрытие УУ/АУ | Не реализован | Условия выдачи, блокировки зависимостей и моменты фиксации |
| Банки, БРС/БРЗ и запросы в полёте | Не реализован | Моменты получения/восстановления, сравнения адресов и арбитраж |
| Устройства и прерывания в наносекундах | Не реализован | Выбранные конфигурации и документированные задержки |
| Интеграция CPU, original/max и ОС | Не реализован | Побитовое состояние, порядок событий и контрольные временные диаграммы |

Следующий блок — спецификация последовательностей АУ/УУ по ТО-2 и ТО-3.
Начальный аудит закреплён в [матрице источников](besm6-hardware-time-sequences.md):
обнаружены различия шкал и диапазонов АУ; автоматическое объединение
таблиц исключено.
До подключения к CPU необходимо также задать запрет повторного запуска
машины из аппаратного callback и правила незавершённых запросов при
ошибке, STOP и ResetCpu. Нынешний календарь не владеет CPU и этих
неустановленных аппаратных правил не вводит.
