# Аппаратная память: первая часть этапа 3

Реализованы компоненты для базовой конфигурации 32K. Физическая память,
контроль и БРЗ/БРС доступны через выбранную модель `MachineCore`
([подключение](besm6-memory-models.md)). Приписка/защита пока остаются отдельными
компонентами. Профиль Dubna по умолчанию использует `CoreMemory`.
Это работа этапа 3, а не готовый аппаратный профиль.

Следом добавлена [функциональная модель БРЗ/БРС](besm6-memory-buffers-1967.md).
Для неё добавлен функциональный CPU-адаптер с прямыми адресами.
Аппаратные адресные теги и время фоновой пересылки остаются обязательствами
перед созданием аппаратного профиля.

## Проверенные источники

Основной источник — техническое описание БЭСМ-6, ИЫ1.700.000 ТО-8,
редакция 1–67, глава IV. Архив называет этот файл томом IX:
[скан системы команд](https://www.besm6.org/doc/БЭСМ6-ТО-IX-описание-системы-команд.pdf).
В данном скане номера PDF-страниц совпадают с напечатанными номерами листов.
Визуально проверены листы 100–109; текстовый слой отсутствует.

SHA-256 PDF:
`7412b2c1c90195e029fe5b0067e859ce6c6f846a780062de8ab6ab4f96b6c113`.

Дополнительная сверка геометрии: описание МОЗУ, ИЫ1.700.000 ТО-4,
редакция 1–66, лист 3 на PDF-странице 3
([скан МОЗУ](https://www.besm6.org/doc/БЭСМ6-ТО-V-МОЗУ.pdf)).
SHA-256: `01556ed62c5ce973707374a2798138e4e6b8416b192e1accbadb87f5e00956b3`.
МОЗУ имеет 52 позиции, из них 50 рабочих и две резервные. Резервные позиции
не включены в программную модель ячейки.

| Механизм | Источник | Реализация |
|---|---|---|
| 32768 слов, восемь банков, выбор банка младшими тремя битами | §4.1, лист 100; ТО-4, лист 3 | `PhysicalMemory1967`, строгий физический адрес без маскирования |
| 48 бит данных, бит 50 слева, бит 49 справа | §4.5, лист 101 | `MemoryWord50`; исходные контрольные биты сохраняются |
| Чётность левой команды, нечётность правой | §4.6, листы 101–102 | Проверяется только выбранная половина |
| Нечётность всего 50-разрядного операнда | §4.7, лист 102 | Командное слово также можно читать как операнд |
| Четыре режима образования контроля ПКЛ/ПКП | §4.8, лист 102 | `MemoryWord50.Form`; смешанные режимы дают неверный контроль операнда |
| 32 математические страницы по 1024 слова | §4.19, лист 105 | `PageAssignment1967`, сохранение десяти младших битов |
| Приписка команды только в математическом режиме | §4.22, лист 106 | `ResolveInstruction`; суперпрограмма использует прямой адрес |
| Приписка операнда управляется БлП независимо от защиты | §4.22, лист 106 | Явные параметры `assignmentBlocked` и `protectionBlocked` |
| Защита операнда относится к математической странице | §4.26, лист 108 | 32-битная маска; доступ отклоняется до выбора памяти |
| Нулевая приписка запрещает команду | §4.28, лист 109 | Отдельный сигнал защиты команды, независимо от маски операндов |
| Нулевой операнд, пультовые адреса 1–7 | §4.22, лист 106; §4.26, лист 108 | Результат разрешения различает память, нулевой операнд и пульт |

Нулевая приписка не запрещает доступ к операнду физической страницы 0,
если маска защиты его допускает. БлЗ не отключает защиту команд.
Супервизор освобождает адреса операндов 1–7 от защиты, но остальные адреса
проверяются согласно БлЗ. Пульт выбирается при прямой адресации; сами
пультовые регистры и правила записи в них здесь не реализованы.

## Контракт компонентов

`MemoryWord50` не заменяет `Word48`: АУ по-прежнему получает 48 бит.
Конструктор принимает исходный код с контрольными битами, включая неверные,
и отклоняет значения шире 50 бит. `Form(data, false, false)` формирует
командный контроль, `Form(data, true, true)` — числовой. Например, для
нулевых данных получаются соответственно `0x1000000000000` и
`0x2000000000000`. Это вывод из правил чётности, не напечатанные примеры.

`PhysicalMemory1967` предоставляет раздельные операции `FetchInstruction`
и `LoadOperand`, запись с явными ПКЛ/ПКП и прямой диагностический доступ
`ReadRaw`/`WriteRaw`. Контрольная ошибка не меняет ячейку. Адрес физической
ячейки 0 допустим; нулевой *математический операнд* обрабатывает будущий
адаптер по результату `ZeroOperand`, без обращения к физической ячейке.

`PageAssignment1967` допускает alias и немедленное изменение таблицы
через API хоста. Результаты разрешения — значения, которые нельзя кешировать
после изменения приписки без отдельного протокола. Настройка хоста не
претендует на семантику привилегированной команды записи регистра.

`MemoryControlException` и `MemoryProtection1967Exception` сохраняют адрес
и вид доступа. Это отдельные сигналы компонентов; аппаратные прерывания,
их приоритет и архитектурное состояние CPU при ошибке пока не реализованы.
Исключения не подключены к гостевому обработчику авостов Dubna.

Массивы первоначально заполнены нулями как обычные структуры данных C#.
Это не спецификация холодного сброса или содержимого реальной МОЗУ.
Доступ к этим компонентам предполагает один поток исполнения, как и у
нынешнего процессора. Ожиданий хоста и продвижения модельного времени нет.

## Что необходимо до подключения к CPU

1. Импорт полей РП/РЗ закреплён по таблицам листов 107–109
   ([формат](besm6-memory-registers-1967.md)). Дополнительные биты РП
   относятся к расширению 64K; компонент 32K отклоняет такой импорт целиком.
   Исполнение привилегированной ЗпР и конфигурация расширенной памяти
   ещё не реализованы.
2. Закрепить поведение БРЗ/БРС и границы видимости записей. Листы 100–104
   описывают отдельные буферы операндов и команд: команда может видеть
   прежнюю МОЗУ или прежний БРС после записи нового слова. Нынешняя
   немедленная самомодификация Dubna этим не заменяется.
   Функциональная часть уже реализована отдельно; остаются теги адресов,
   аппаратные операции пересылки и связь с очередями УУ/АУ.
3. Подключить разные пути ATX и CTX. Книга 1976 года,
   [§6](../book/fortran-1976/01-besm6.md), определяет CTX как экстракод 075:
   командный контроль и фактическая запись в МОЗУ, тогда как ATX оставляет
   запись в БРЗ. Образование контроля и ATX через БРЗ уже подключены к новому backend.
   Hosted CTX использует хостовую запись; историческая супервизорная
   последовательность ещё не реализована.
4. Связать математический режим, БлП/БлЗ, нулевой и пультовый доступ с CPU;
   определить точное состояние и порядок сигналов на ошибке по первоисточнику.
5. Выполнить проверки всей системы и одинакового состояния original/max
   после подключения. Защиту внешнего обмена и доставку прерываний развивать
   вместе с диспетчером и устройствами на этапе 4.

Аппаратный CLI-профиль появится после работоспособного выполнения программы
через эти механизмы. Ускорение и ожидания прежнего движка здесь не менялись.

## Проверки

73 проверки: пять буквальных кодов контроля, четыре режима формирования,
повреждение каждого из 50 битов, вся геометрия физических адресов и страниц,
alias/remap, контроль выбранной половины и всего операнда, независимость
приписки/защиты, прямой супервизорный доступ, нулевой и пультовые адреса,
строгие границы адресов и сохранение ячеек при ошибке.

```powershell
dotnet test tests/Besm6.Processor.Tests/Besm6.Processor.Tests.csproj -c Release --no-restore --filter TestCategory=HardwareMemory1967
```
