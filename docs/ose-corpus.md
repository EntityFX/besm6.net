**Дата:** 28.09.2026
**Инструменты:** `tools/besm6harvest.py` (сбор), `tools/besm6corpus.py` (карта),
`tools/besm6decomp.py` (декомпиляция)
**Артефакты:** `docs/ose-corpus.hl.txt` (15 459 строк псевдокода),
`docs/ose-corpus.regions.json` (карта участков по 14 заданиям)

Продолжение `docs/monsys-kernel.md` и `docs/monsys-kernel-hl.md`, где разбиралось
ядро. Здесь — что лежит **за пределами ядра**: компиляторы и подсистемы ОС.

## 1. Метод

Ленты смонтированы как диски, и все обращения к ним идут через экстракод E70.
При `BESM6_TRACE=1` эмулятор логирует каждое обращение с раскодированным словом
управления — это даёт **точную** карту «зона ленты → адрес ОЗУ»:

```
memAddr   = page << 10  (+ paragraph << 8 при sectIo)
diskZone  = tract + (drum − mappedDrum) * 32
длина     = 1024 слова, либо 256 при sectIo
```

Скрипт `besm6harvest.py` для каждого задания перебирает моменты снятия снимка
(`--dump-mem-at` 100000 / 300000 / 600000) и выбирает тот, где больше всего
ненулевых слов: **момент принципиален** — для `fortran.dub` это 12 626 слов при
N=300000 и всего 8983 при N=600000, потому что монитор к концу задания стирает
собственный образ.

```bash
python3 tools/besm6harvest.py --out /tmp/harvest <список .dub>
python3 tools/besm6corpus.py /tmp/harvest --json docs/ose-corpus.regions.json
```

## 3. Ядро ОС — общая подсистема

Участок `0o76000`, **880 слов**, присутствует и исполняется в **13 из 14**
заданий (все, кроме `name.dub`, где до баннера не доходит). Это подтверждает
карту из `docs/monsys-kernel.md` независимым способом.

## 4. Универсальные модули ОС

Эти участки исполняются в **большинстве** заданий, включая `name.dub`
(только баннер) — значит это не компиляторы, а обслуживание самой ОС:

| Адрес | Слов | Исполнений | Роль (по косвенным признакам) |
|---|---:|---:|---|
| `0o53401–0o53732` | 217 | 115–131 | **диспетчер псевдокоманд** — разбор `*NAME`, `*FILE`, `*COPY` |
| `0o01236–0o01520` | 178 | 97 | модуль обслуживания ввода-вывода |
| `0o01604–0o02227` | 275 | 102–229 | модуль работы с файлами/каталогами |
| `0o00770–0o01235` | 165 | 58–113 | низкоуровневые сервисы |
| `0o04000–0o04413` | 267 | 146–182 | загружается не через phys_io (см. ограничения) |

`0o53401` — самый интересный: он исполняется даже в задании, которое только
печатает баннер. Это интерпретатор директив монитора, то есть **вход ОС в
пользователя**.

## 6. Общий вид компилятора ФОРТРАН

Начало части 1 (`docs/ose-corpus.hl.txt`):

```
; ТОЧКА ВХОДА (адрес 0o20000)
0o20000 vtm 20000(12)      m10 = 0o20000
0o20000 ita 15             A = ptr
0o20001 atx (17)           0o53404 = A
0o20001 vtm 4406(13)       m11 = 0o4406
0o20002 vtm -2(14)         m12 = 0o77776
0o20002 vtm 5126(16)       link = 0o7064
0o20003 vjm 20026(15)      управление
/* CALL 0o20026, возврат в 0o20026 */
do {   /* цикл: 0o20026 */
    0o20026 utm 2(16)          link += 0o5130
    0o20026 ita 16             A = ptr
    0o20027 asn 56             A >>= 0o56
    0o20027 aox 32(12)         A |= 0o20032
    0o20030 utc (13)           C = 0o4406     ; УТА: база на 1 команду
    0o20030 atx (14)           0o4404 = A
    do { 0o20031 vlm 20026(14) } while (0o20026);
```

Видна та же архитектура, что и в ядре: позиционно-независимый код (база `C`),
обратный адрес в регистре `link`, цикл `vlm` как счётчик. Компилятор написан
в той же среде — это **собственный код ОС**, а не загруженный извне формат.

## 7. Объём полученного псевдокода

`docs/ose-corpus.hl.txt` — 15 459 строк, **1379 восстановленных тел**:
3 универсальных модуля ОС + 3 части компилятора ФОРТРАН + компилятор Паскаля +
БЕМШ/DISPAC + ассемблер МАДЛЕН.

## 8. Ограничения — существенно

1. **Имена нет нигде.** В образах нет символьных имён, только адреса. Все
   «названия» выше — по тому, какое задание исполняло этот участок.
2. **Ленты не различаются по имени.** Барабаны монтируются динамически через
   E57; в карте E70 фиксируется номер барабана (`drum21`, `drum16`, …), а не имя
   ленты. Привязка барабана к образу потребовала бы трассировки E57 — она
   не сделана.
3. **Покрытие — только исполненный код.** Из 10 208 слов компилятора Паскаля
   восстановлено 4018 (39 %). Остальное — холодные ветви, таблицы, данные.
4. **Часть кода грузится не через phys_io.** Участок `0o04000` исполняется, но
   не прослеживается в прочитанных зонах — есть путь загрузки помимо phys_io,
   не попавший в фильтр карты.
5. **Самомодификация.** Для ядра измерено 2.10 % команд, исполняющих не тот код,
   что в снимке. Для компиляторов эта доля не измерялась, но механизм тот же —
   значит и здесь снимок не полон.
6. **Два задания не дошли до конца** (`madlen.dub`, `e-2.dub` упёрлись в
   `--limit 3000000`), поэтому их покрытие занижено.

## 9. Как продолжить

- Повысить `--limit` для `madlen.dub` и `e-2.dub`.
- Трассировать E57, чтобы связать барабан с именем ленты.
- Снимать несколько снимков за задание и объединять — закроет самомодификацию.
- Гонять задания, реально использующие Алгол, эксфор, РЕФАЛ, `librar.*`:
  в текущем наборе их подсистемы почти не исполняются.
