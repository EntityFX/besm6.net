# Спецификация проектирования программного обеспечения (SDD)
# Симулятор ЭВМ БЭСМ-6

## 1. Введение

### 1.1 Назначение документа

Настоящий документ является полной спецификацией проектирования программного обеспечения симулятора ЭВМ БЭСМ-6. Документ описывает архитектуру, компоненты, интерфейсы, модели данных, порядок исполнения, режимы работы (включая режим супервизора), веб-приложение, стратегию тестирования и развертывания.

Спецификация абстрактна от конкретного языка программирования и платформы реализации. Все описания компонентов, интерфейсов и протоколов приведены в функциональной форме, не зависящей от выбранного стека технологий. Документ достаточен для независимой реализации системы на любом языке программирования.

### 1.2 Область применения

SDD охватывает все функциональные компоненты системы:

- Архитектурный слой — представление слов, команд, опкодов, состояний процессора.
- Слой процессора — семантика выполнения команд, выборка, декодирование, адресная модификация, арифметико-логическое устройство.
- Слой загрузки — ассемблирование, дизассемблирование, загрузка программ.
- Слой выполнения — композиция машины, владельцы исполнения, модель памяти, устройства, загрузка задач.
- Консольный интерфейс — интерфейс командной строки.
- Терминальный интерфейс — текстовый интерфейс пользователя.
- Веб-приложение — веб-консоль с удалённым управлением, загрузкой примеров и конфигураций.
- Графический визуализатор — представление чисел и команд.
- Инструментальные средства — бенчмарки, проверки пользовательского интерфейса, генераторы, скрипты приёмки.

## 2. Архитектурное описание

### 2.1 Общая схема компонентов

Система следует строгой иерархии зависимостей без циклов:

```
Архитектурный слой → Слой процессора → Слой загрузки → Слой выполнения → Интерфейсы пользователя
```

| Компонент | Назначение | Граница ответственности |
|-----------|------------|------------------------|
| Архитектурный слой | Представление 48-битных слов, 50-битных слов памяти, форматов команд, архитектурных состояний | Не выполняет загрузку, ввод-вывод или ожидание времени |
| Слой процессора | Выборка, декодирование, адресная модификация, диспетчеризация, арифметико-логическое устройство, фиксация результатов | Не владеет календарём устройств или системными лентами |
| Слой загрузки | Преобразование текстовых представлений команд и машинных слов | Не запускает машину |
| Слой выполнения | Композиция машины, владельцы исполнения, модель памяти, устройства, загрузка задач, системные обработчики | Не содержит независимой копии семантики команд |
| Консольный интерфейс | Ввод параметров, вызов слоя выполнения, представление результатов и диагностики | Не подменяет вычисления гостевой программы вычислениями хоста |
| Терминальный интерфейс | Текстовое взаимодействие поверх слоя выполнения | Аналогично консольному интерфейсу |
| Веб-приложение | Веб-консоль, удалённое управление, загрузка примеров и конфигураций, управление сессиями | Не меняет семантику исполнения |
| Графический визуализатор | Представление чисел и команд | Визуализация, не исполнение |

### 2.3 Основные архитектурные принципы

1. **Разделение владельцев исполнения**: одна машина поддерживает два взаимоисключающих владельца исполнения — функциональный и аппаратный. Переключение разрешено только на границе бездействия процессора.
2. **Единая семантика команд**: процессор использует общую семантику для функционального и аппаратного режимов; отличие только в механизме продвижения времени (тики против наносекунд).
3. **Изоляция загрузки**: загрузчик не смешивается с семантикой процессора; он только подготавливает состояние машины.
4. **Явное время**: функциональное время (тики инструкций) и аппаратное время (наносекунды) являются независимыми доменами.
5. **Отсутствие полного холодного сброса машины**: сброс процессора сохраняет память, часы, устройства и очередь событий.
6. **Валидация ресурсов**: ресурсы времени выполнения валидируются по контрольным суммам перед запуском процессора.

## 3. Детальное описание компонентов

### 3.1 Архитектурный слой

#### 3.1.1 Типы данных

**Слово 48 бит** — машинное слово с представлением мантиссы и порядка:
- Знак: 1 бит (старший)
- Порядок: 8 бит (смещённый)
- Мантисса: 39 бит (включая скрытую единицу)

**Слово памяти 50 бит**:
- Младшие 48 бит: данные или команда
- Старшие 2 бита: контрольные разряды (приписка, защита)

**Декодированная инструкция** — 24-битное полуслово:
- Регистр: номер индексного регистра M0–M15
- Операция: код операции
- Адрес: 15-битный адрес
- Формат: короткий или длинный

**Опкоды** — все коды операций БЭСМ-6 (000–0377 восьмерично):
- Короткий формат (000–037): арифметика, логика, индексные регистры
- Длинный формат (0200–0377): модификаторы, переходы, служебные команды, цикл
- Специальные: модификация индексного регистра, безусловный переход, останов, организация цикла, экстракоды 050–077

**Профили процессора**:
- Стандартный пользовательский профиль (по умолчанию)
- Профиль супервизора — с привилегированными регистрами, M17, прерываниями, экстракодами 050–077

#### 3.1.2 Интерфейсы архитектурного слоя

| Интерфейс | Назначение |
|-----------|------------|
| Процессор | Выполнение шага, старт по адресу, регистры, флаги |
| Состояние процессора | Только чтение состояния процессора |
| Регистры | Доступ к регистрам A, Y, R, C, M, K |
| Арифметико-логическое устройство | Выполнение арифметических и логических операций |
| Память хоста | Главная память системы |
| Память команд | Память для хранения команд |
| Память | Общий контракт доступа к памяти |
| Память операндов | Память для операндов |
| Управление супервизором | Специальные регистры, прерывания |
| Ввод-вывод супервизора | Регистры устройств, обмен данными |

| Регистр | Обозначение | Разрядность | Назначение |

### 3.2 Слой процессора

#### 3.2.1 Функциональная симуляция

Тактовое моделирование команд. Каждый успешный шаг соответствует одному тику (одна инструкция). Основные операции:
- Выполнение одной инструкции
- Блоковое выполнение с лимитом циклов
- Проверка границы функционального режима

#### 3.2.2 Аппаратная модель процессора

Поэтапная модель с наносекундным временем. Компоненты:
- Этапы арифметико-логического устройства с фиксированными и переменными завершениями
- Наносекундный календарь событий
- Календарь ресурсов устройств
- Порт памяти с банковым циклом и задержками
- Контроллер этапов арифметико-логического устройства

#### 3.2.3 Владелец исполнения

Механизм, гарантирующий взаимоисключение функционального и аппаратного режимов. Переключение разрешено только при:
- Отсутствии подготовленной инструкции
- Отсутствии активных обратных вызовов
- Отсутствии запущенного драйвера
- Отсутствии событий в очереди

#### 3.2.4 Исполнительный цикл

Цикл выполнения с следующими характеристиками:
- Лимит инструкций
- Лимит попыток шага (для профиля супервизора ограничивает попытки включая обработку ошибок)
- Скорость выполнения (максимальная, оригинальная, виртуальная)
- Сбор статистики
- Контрольные точки выполнения
- Лимит времени выполнения (в миллисекундах)
- Ограничение количества ошибок подряд, чтобы предотвратить бесконечное выполнение неудачных шагов


### 3.3 Слой выполнения (runtime)

#### 3.3.1 Ядро машины

Центральный компонент, Composing все части системы в единое целое.

**Публичный интерфейс:**
- Режим исполнения (функциональный / аппаратный)
- Главная память
- Память команд
- Аппаратная математическая память
- Буферная память
- Процессор
- Менеджер устройств
- Перфоратор
- Плоттер
- Контроллер ввода-вывода супервизора
- Выбор аппаратного исполнения с конфигурацией времени
- Выбор функционального исполнения
- Выполнение с лимитом инструкций, скоростью, статистикой, контрольными точками и лимитом времени
- Выполнение одной инструкции
- Непрерывное выполнение до условия остановки
- Проверка расширенного состояния машины

**Результат выполнения:**
- Итог (останов / останов по лимиту / ошибка)
- Статистика (инструкции, циклы, секунды, аллокация)

#### 3.3.2 Конфигурация автономного образа супервизор-машины

Описание образа супервизор-машины включает:
- Режим исполнения (функциональный / аппаратный)
- Скорость выполнения
- Конфигурация памяти (классическая 32K / расширенная 512K)
- Адрес входа
- Флаги управления
- Предел инструкций
- Слова памяти с адресами и исходными значениями
- Конфигурация времени (банковый цикл, задержки чтения/записи, устройства)
- Конфигурация устройств (образы дисков, перфоленты)

#### 3.3.3 Загрузчик программ

Отвечает за:
- Разбор задач в формате загрузчика (FORMAL, FORTRAN, ALGOL, ассемблер)
- Загрузку ресурсов времени выполнения (ленты, диски, барабаны)
- Установку системных обработчиков
- Выполнение скриптов с лимитами и статистикой

**Внутренняя организация загрузчика:**

- Модель загрузчика основана на пошаговом выполнении с сохранением состояния между шагами
- Загрузчик преобразует форматы задач (ассемблер, FORTRAN, FORMAL, алгол) в внутренний вид команды машин
- Экстракоды 050–077 обрабатываются специальным образом загрузчиком как системные команды
- Поддержка пресета веб-запуска: набор параметров запуска с программой и режимами выполнения
- Конфигурация памяти устанавливается при загрузке (классическая 32K или расширенная 512K)
- Адрес входа устанавливается на основе заголовка загружаемой задачи
- Системные обработчики регистрируются для устройств: терминал, принтер, перфокарты, перфолента, диски, барабаны
- Контрольные точки и статистика собираются с начала выполнения для последующего анализа

## 4. Режим супервизора (Supervisor Mode)

### 4.1 Обзор

Режим супервизора активируется через профиль процессора супервизора. Реализует системный/управляющий режим БЭСМ-6 с привилегированными регистрами, прерываниями, экстракодами 050–077 и отдельными устройствами ввода-вывода.

### 4.2 Ключевые механизмы

| Механизм | Реализованное правило | Источник |
|----------|----------------------|----------|
| Экстракоды 050–077 | Вектор 00500 + код, левая половина; Э20/Э21 = Э060/Э061 | ТО-8 §3.55 |
| Сохранение экстракода | M14 — адрес, M26 — следующее слово; A/Y/R сохраняются | ТО-8 §3.55 |
| Внутреннее/внешнее прерывание | Векторы 00500/00501, M27 и признаки в M23 | ТО-8 §6.16, §6.35 |
| Вход в управляющую программу | Установить БлП, БлЗ, БлПр, сохранив остальные M17 | ТО-8 §§6.16, 7.7–7.10 |
| ВЫПР | Три младших бита: 2/3 выбирают M26/M27 | ТО-8 §3.60 |
| Возврат | Восстановить режим, половину, модификатор; БлП/БлЗ/БлПр | ТО-8 §3.60 |
| M17 | Только гостевая запись; host-снимок допускается | ТО-8 §§7.7–7.8 |
| ПА/СА00 супервизора | Изменить лишь маску 0x403 | ТО-8 §7.8 |
| РЕГ/ОВУ | Раздельное чтение/запись регистров и устройств | ТО-8 §§3.56, 3.59 |
| 032/046/047 | В матрежиме недопустимы; в супервизоре 032 — ОВУ | ТО-8 §§3.62–3.64 |
| STOP | Кнопка останова; при отключении ПоК — NOP или Э063 | ТО-8 §3.61 |
| Адресные сравнения | M28 — команды, M29 — чтение/запись операнда | ТО-8 §§6.5–6.7, 7.19–7.21 |

### 4.3 Регистры супервизора

Наблюдаемые через снимок супервизора:
- Специальные регистры (M-регистры)
- Статус управления
- Внутренние прерывания
- Аппаратные наносекунды (в аппаратном режиме)
- Арифметические команды
- Страницы памяти и маска защиты операнда
- БРЧ (аппаратные буферы чтения, 4 слота)

### 4.4 БРЗ и память в супервизоре

- Отдельная функциональная граница завершения записи
- Заполнение последнего свободного БРЗ публикует старейшую запись
- Не более семи ожидающих публикации значений
- Запись адреса перестраивает старые записи

### 4.5 Исполнение в режиме супервизора

- Использует общий исполнительный цикл
- Для супервизора лимит ограничивает попытки шага (включая доставку ошибок)
- Неуспешный шаг не добавляет тик и счётчик
- Системный обработчик экстракодов не устанавливается
- Режим максимальной скорости без статистики не считает табличные такты ожидания

### 4.6 Аппаратный режим супервизора

Требует полной конфигурации времени:
- Банковый цикл, задержки чтения/записи, задержки устройств
- Переключение разрешено только на границе бездействия процессора
- Конфигурация неизменна после выбора
- Сброс процессора сохраняет выбранный владелец, память, часы, устройства

### 4.7 Пример запуска

```
Создать машину с профилем супервизора
Установить адрес входа процесса
Выполнить с лимитом инструкций, скоростью максимальной, сбором статистики
```

### 4.8 Проверки режима супервизора

- Проверка регистров и достижения остановки (функциональный и аппаратный, полный и отладочный режимы)
- Проверка реальных БРЧ в аппаратном режиме (4 буфера)
- Проверка модели исполнения (функциональный / аппаратный)

## 5. Модели памяти

### 5.1 Классическая модель (32K слов)

- Размер ядра памяти: 32768 слов
- Адресация: 15 бит
- Подходит для большинства пользовательских программ и стандартных задач

### 5.2 Расширенная модель (512K слов)

- Размер ядра памяти: 524288 слов
- Адресация: 19 бит
- Используется для супервизор-программ и больших задач

### 5.3 Буферная память

- БРЗ (буфер чтения операндов)
- БРС (буфер чтения инструкций)
- Буферная память адресуется отдельно от ядра памяти
- Включается/выключается конфигурацией

### 5.4 Математическая память

- Аппаратная математическая память для хранения констант
- Используется для реализации элементарных функций
- Конфигурируется через коэффициент математических функций originale

### 5.5 Адресная модификация

- Базовая модификация через индексные регистры M0–M15
- Длинный формат команды позволяет модифицировать адрес
- Адресные сравнения через M28 (команды) и M29 (чтение/запись операнда)
- Маска защиты операнда для контроля доступа

### 5.6 Семантика памяти

- Каждое слово — 50 бит (48 бит данных + 2 бита контроля)
- Чтение и запись через единый интерфейс
- Порт памяти в аппаратном режиме учитывает банковый цикл и задержки
- Память сохраняется при сбросе процессора

## 5.7 Программная система Dubna

**Dubna** — советская программная система и язык программирования, разработанный в Объединенном исследовательском центре Дубна (ИРЦ Дубна) для ЭВМ БЭСМ-6 в 1960–1980-х годах.

### 5.7.1 Цели и задачи системы Dubna

- Предоставление унифицированной среды для разработки и выполнения вычислительных программ
- Автоматическое управление ресурсами системы (память, peripherals, Devices)
- Поддержка пакетной обработки задач и многократного использования вычислительных ресурсов
- Интерфейс для взаимодействия между пользователем и вычислительной машиной

### 5.7.2 Компоненты системы Dubna

- **Язык программирования Dubna** — расширение языка ALGOL с элементами FORTRAN, оптимизированное для численных вычислений на БЭСМ-6
- **Система компиляции** — компиляторы FORTRAN, ALGOL, FORMAL и ассемблера с генерацией кода для БЭСМ-6
- **Загрузчик задач** — программа загрузки, подготовки и запуска задач в режиме супервизора
- **Диспетчер задач** — управление очередью задач, приоритеты, временные лимиты
- **Система файлов** — иерархическая структура хранения программ и данных на лентах и дисках
- **Обработчик ввода-вывода** — унифицированный доступ к устройствам перфокарт, перфоленты, принтеров, плоттеров
- **Диагностическая система** — инструменты для отладки, профилирования и тестирования программ

### 5.7.3 Язык программирования Dubna

**Синтаксис**: 기반 на алгоритмическом языке с influences от FORTRAN и FORMAL.

**Основные особенности**:
- Числовые типы данных: целые, вещественные (48-битная мантисса БЭСМ-6)
- Символьные строки и массивы
- Массивы с индексами, отображающиеся на индексные регистры M0–M15
- Операции ввода-вывода, подпрограммы, рекурсия (с ограничениями)
- Управляющие структуры: условие, цикл, переход

**Типы данных**:
- **Целые числа**: знак + 39-bit мантисса (в коде БЭСМ-6)
- **Вещественные числа**: знак + 8-bit порядок + 39-bit мантисса (50-bit слово памяти)
- **Логические значения**: истина/ложь
- **Символьныеconstants и переменные**

**Конструкции языка**:
- Объявление переменных и констант
- Арифметические операции: +, -, *, / (с учетом переполнения)
- Операции сравнения: =, ≠, <, >, ≤, ≥
- Присваивание значения переменной
- Условные конструкции: IF, THEN, ELSE
- Циклы: DO, WHILE
- Подпрограммы и функции
- Ввод-вывод: чтение/запись через устройства ВВО

### 5.7.4 Поддерживаемые языки программирования

Симулятор БЭСМ-6 поддерживает следующие языки программирования через соответствующие компиляторы и загрузчики:

| Язык | Компилятор/Преобразующее | Особенности |
|------|-------------------------|-------------|
| **FORTRAN** | Компилятор FORTRAN БЭСМ-6 | Числовые вычисления, матричные операции, подпрограммы; наиболее largement используемый язык科学技术ных вычислений |
| **ALGOL** | Компилятор ALGOL БЭСМ-6 | Структурное программирование, блоки, процедуры; академический и образовательный язык |
| **FORMAL** | Компилятор FORMAL | Математическое моделирование, спецификация, доказательства корректности; используется для критических систем |
| **Ассемблер** | Ассемблер БЭСМ-6 | Прямая работа с опкодами, регистрами, адресным модификацией; полный контроль над железом |
| **Dubna** | Система Dubna | Собственный язык с расширениями ALGOL/FORTRAN, специальные возможности для научных вычислений |

- Поддержка форматов входных данных для каждого языка
- Автоматическое преобразование в внутреннее представление команд машин
- Экстракоды 050–077 обрабатываются специальным образом как системные команды

### 5.8 Форматы задач загрузчика

- **FORMAL** — формат задач, написанных на языке FORMAL
- **FORTRAN** — формат задач, написанных на языке FORTRAN
- **ALGOL** — формат задач, написанных на языке ALGOL
- **Ассемблер** — формат задач, написанных в коде ассемблера БЭСМ-6

**Внутренняя организация загрузчика**:
- Загрузчик преобразует форматы задач (ассемблер, FORTRAN, FORMAL, ALGOL) в внутренний вид команды машины
- Экстракоды 050–077 обрабатываются специальным образом загрузчиком как системные команды
- Поддержка пресета веб-запуска: набор параметров запуска с программой и режимами выполнения
- Конфигурация памяти устанавливается при загрузке (классическая 32K или расширенная 512K)
- Адрес входа устанавливается на основе заголовка загружаемой задачи
- Системные обработчики регистрируются для устройств: терминал, принтер, перфокарты, перфолента, диски, барабаны
- Контрольные точки и статистика собираются с начала выполнения для последующего анализа

## 6. Устройства ввода-вывода

### 6.1 Терминал

- Текстовый ввод/вывод — посимвольный и строковый ввод/вывод через контроллер терминала
- Поддержка ввода с клавиатуры и вывода на экран (монитор) в реальном времени
- Используется в режиме супервизора для взаимодействия с пользователем: ввод команд, вывод результатов, отладка
- Кодировка: 6-битный код БЭСМ (обратная связь с ASCII/KOI8 преобразованиями)
- Регистр состояния: флаги готовности к приему/передаче, ошибки переполнения
- Протокол обмена: параллельный пакет данных 6 бит + контрольные разряды
- Подписка на события: хост-приложение может регистрировать callback на ввод символа

### 6.2 Принтер

- Печать текста и данных — посимвольная печать на линии принтера
- Поддержка форматированного вывода: переносы строк, табы, числовой формат с выравниванием
- Используется для отладки и вывода результатов вычислительных программ
- Устройство может работать в режимах: однократная печать, партия распечаток, непрерывная печать
- Кодировка печати: 6-битный код БЭСМ на ленте принтера
- Регистр команд: код команды печати, адрес буфера данных, длина записи
- Сигнал готовности: устройство сообщает о готовности принять следующий пакет символов

### 6.3 Перфокарты

- Чтение и запись перфокарт — устройство ВУ-700 series (ВУ-700, ВУ-701 и compatibles)
- **Кодбук перфокарт (таблица кодирования)**: 80-колоночный формат, кодировка БЭСМ-6 на перфленных картах
  - **Столбцы 1-5**: знак и 5 разрядов мантиссы (бит знака в столбце 1, биты мантиссы 1-5 в столбцах 2-6)
  - **Столбцы 6-11**: порядок (цифры и знаки) — определяет степень сдвига и знак результата
  - **Столбцы 12-79**: данные (6 бит на колонку) — содержит биты мантиссы и порядка данных
  - **Столбец 80**: признак конца записи — маркер, указывающий последний столбец записи
- **Схема кодирования**: каждая колонка перфкарты кодирует 6 бит информации в коде БЭСМ
- **Генерация перфокарт из текста**: автоматическое преобразование памяти машины в формат перфокарт
  - Преобразование 50-битного слова памяти в набор колонок перфокарты
  - Упаковка знака, порядка и мантиссы в соответствующие столбцы
  - Формирование маркера конца записи (столбец 80)
- **Поддержка стандартных форматов**: чтение/запись файловых образов перфокарт (.card, .punch formats)
- **Механизм обработки ошибок**: проверка чек-суммы строки, обнаружение порванных карт
  - Чек-сумма рассчитывается как модульное сложение всех 6-битных кодов колонок
  - Обнаружение ошибок при mismatch суммы
- **Регистр устройства**: статус наличия карты, код последней операции, количество прочитанных колонок
- **Регистр команд**: код команды (чтение/запись), адрес буфера памяти, длина записи в колонках

### 6.4 Перфолента

- Чтение и запись перфолент — магнитные ленты произвольной длины с кодированием БЭСМ-6
- Поддержка лент с различными кодировками: 6-битный код, 9-битный расширенный код, ASCII-совместимый режим
- Используется для загрузки программ: форматы задач загрузчика (FORMAL, FORTRAN, ALGOL, ассемблер) хранятся на ленте
- Каталог лент: директория с файлами лент содержит мета-информацию (название задачи, дата создания, размер, контрольная сумма)
- Форматы файлов лент: .tape, .image, .dub задания с заголовками
- Длина ленты: адресуется по блокам по 50 бит (одно слово памяти) или по 48-битным словам
- Ошибки чтения: дефекты ленты, контрольные суммы, синхронизация
- Регистры устройства: текущая позиция головки, статус конца ленты, код последней ошибки, режим блокировки

### 6.5 Плоттер

- Графический вывод — устройство для построения графиков, диаграмм и технических рисунков
- Различные типы плоттеров с разными форматами данных:
  - Линейные плоттеры: движение пером по линиям (X,Y координаты)
  - Точечные плоттеры: точка в точку, штриховка, закрашивание областей
- Поддержка линейных графиков: построение прямых линий, кривых, множества точек
- Поддержка точечных графиков: растровая графика, сетки, оси координат, подписи
- Форматы данных: векторный формат (массив точек (X,Y)), растровый формат (битапмап 48-bit words)
- Данные передаются через события сервера: изменения изображения генерируются как события, браузер/консоль обновляет отображение
- Регистр команд: тип операции (начать линию, провести линию, переместить перо, закрасить), цвет/толщина, координаты
- Разрешение: зависит от типа плоттера,abstractly: целочисленные координаты в диапазоне слова памяти

### 6.6 Ленты (магнитные)

- Чтение и запись магнитных лент — внешнее запоминающее устройство на магнитной ленте
- Каталог лент — директория с файлами лент, каждая запись содержит:
  - Название задачи/данных
  - Дата создания
  - Объем памяти (количество слов 50-бит)
  - Контрольная сумма заголовка
  - Флаг защиты от записи
- Поддержка стандартных форматов лент БЭСМ-6:
  - Формат FORMAL (ассемблер задачи)
  - Формат FORTRAN (программы и данные)
  - Формат ALGOL
  - Пользовательские форматы
- Способы организации: линейная лента с адресацией по блокам, бэкхоу администрация лент
- Длина ленты: неограниченная (ограничена только емкостью файловой системы хоста)
- Блоковый доступ: операции чтения/записи whole 50-bit words по логическому адресу
- Скорость передачи: зависит от оборудования, abstractly: words per second parameter
- Регистры устройства: текущая позиция, количество прочитанных слов, статус EOF/EOD, код ошибки

### 6.7 Диски

- Образ диска — файл с образом диска на файловой системе хоста, представление диска как коллекции секторов
- Поддержка операций чтения/записи блоков: чтение/запись 50-битных слов по 8-битному или 16-битному адресу блока
- Используется для хранения программ и данных: системы задач, библиотеки, файлы пользователей
- Формат образа диска: последовательность блоков 50-битных слов, заголовок диска с геометрией (треков, секторов)
- Объем диска: зависит от конфигурации,abstractly: количество слов 50-бит (32K = 32768 слов, 512K = 524288 слов и более)
- Файловая структура: поддержка иерархической файловой системы или плоский набор файлов образов
- Дисковые файлы: .disk image files, сохраняющие состояние после выключения
- Справочник дисков: таблица монтированных дисков с путями к файлам и флагами защиты
- Ошибки доступа: файл не найден, диск не монтирован, превышение квоты, защита от записи
- Регистр устройства: текущий диск, текущий адрес, статус монтирования, количество секторов

### 6.8 Барабаны

- Образ барабана — файл с образом барабана, быстрозапамячивающее устройство с быстрым доступом к данным
- Быстрый доступ к данным: барабан имеет меньшую задержку обращения по сравнению с дисками, abstractly: задержка в несколько тактов процессора
- Используется для системных задач: хранение операционной системы, frequent access data, буферы ввода-вывода
- Конструкция: циклическое хранилище с быстрым доступом по адресу (очень быстрая램дом доступ)
- Объем барабана: конфигурируется при запуске,typical: дополнительные 1K–4K слов 50-bit сверх базовой памяти
- Формат: непрерывный массив слов, адресация по:index в барабане (очень быстрая доступность)
- Файл образа барабана: .drum image файл, сохраняющий состояние между сессиями
- Сравнение с дисками: быстрее дисков, медленнее регистров/памяти процессора
- Регистры устройства: текущая позиция головки, количество слов, статус готовности, код последней операции

### 6.9 Контроллер ввода-вывода супервизора

- Регистры устройств — специальные регистры, управляющие всем комплексом устройств ВВО:
  - Регистр режима устройства: текущий режим работы каждого устройства (онлайн, оффлайн, ожидание, ошибка)
  - Регистр статуса: флаги готовности, ошибок, условий завершения операций
  - Регистр адреса: текущий адрес передачи данных для очередной операции
  - Регистр счетчика: количество слов, переданных с последнего инициализирования
  - Регистр маски прерываний: битовая маска разрешения/запрещения прерываний от каждого устройства
  - Регистр календаря событий: таблица событий с временными метками (наносекунды) для аппаратного режима
- Обмен данными через DMA — прямой доступ к памяти без участия процессора при больших объемах данных
  - DMA инициация: процессор или устройство запрашивает DMA-менеджер
  - Область памяти: физический адрес начала блока в памяти хоста
  - Длина блока: количество слов 50-bit для передачи
  - Завершение DMA: установка флага завершения и генерация прерывания (по необходимости)
- Календарь событий для аппаратного режима — хронологическая таблица событий, определяющая порядок исполнения инструкций и реакцию на внешние стимулы
  - Список запланированных событий: время ( nanotik ), тип события, источник, данные
  - Обработка прерываний: при наступлении события происходит переход в обработчик
  - Переключение контекста: сохранение текущего состояния и загрузка следующего
- Поддержка прерываний от устройств — внешние устройства могут генерировать запросы на прерывание
  - Типы прерываний: устройственное, таймер, сбой, запрос от супервизора
  - Очередь прерываний: порядок обработки если несколько устройств запрашивают одновременно
  - Обработчик прерываний: переход по адресу в векторе прерываний, сохранение регистров, выполнение обработки, возврат
  - Флаги блокировки: возможность блокировки определенных классов прерываний регистром M17

### 6.10 Менеджер устройств

- Единый интерфейс управления всеми устройствами — программный слой, абстрагирующий различия между конкретными устройствами
- Монтирование и размонтирование носителей: устройство становится активным/неактивным, файлы образов загружаются/выгружаются
- Чтение и запись данных: унифицированный вызов interface для чтения/записи слов 50-bit независимо от типа устройства
- Копирование данных в память: DMA-операции, инициация с одного устройства на другое или в память хоста
- Управление состоянием: включение/выключение, сброс ошибок, сброс устройства к начальному состоянию
- Запрос конфигурации: возврат информации о всех устройствах (типы, модели, состояние, параметры)
- Список устройств: регистр/таблица всех подключенных устройств с их текущим состоянием и адресами
- Обработка ошибок устройства: кодирование ошибок, диагностика, автоматическое восстановление при возможностях
- Виртуализация: возможность создавать виртуальные устройства на базе физических (например, виртуальная перфолента, виртуальный диск)
- API интерфейс: набор команд для инициализации, конфигурирования, управления и мониторинга всех устройств ВВО в унифицированном виде

## 12. Ограничения и допущения

### 12.1 Ограничения

1. **Точность аппаратной модели**: аппаратная модель приближает поведение реальной БЭСМ-6, но не воспроизводит её на наносекундном уровне с полной точностью.
2. **Поддержка устройств**: не все устройства БЭСМ-6 реализованы; поддерживаются только перечисленные в разделе 6.
3. **Совместимость**: программы, использующие недокументированные особенности, могут работать некорректно.
4. **Производительность**: аппаратный режим работает медленнее функционального.
5. **Память**: классическая модель ограничена 32K слов; расширенная — 512K слов.

### 12.2 Допущения

1. **Изоляция сессий**: каждая веб-сессия изолирована и не влияет на другие.
2. **Валидация ресурсов**: ресурсы проверяются по контрольным суммам перед запуском.
3. **Сохранение состояния**: сброс процессора сохраняет память и устройства.
4. **Единая семантика**: функциональный и аппаратный режимы используют общую семантику команд.
