# Восстановление кода ОС «Дубна» — указатель

Индекс по материалам дизассемблирования лент и разбора ядра/компиляторов.
Каждый документ самодостаточен; здесь — что где лежит и в каком порядке читать.

## Порядок чтения

| № | Документ | О чём | Артефакты |
|---|---|---|---|
| 1 | `ose-tape-decompilation.md` | Ленты: инвентарь, формат SIMH, текст на лентах | — |
| 2 | `monsys-kernel.md` | Ядро: где находится, точки входа, соглашение о вызовах, таблицы | `monsys-kernel.listing.txt` — машинный листинг, 1023 строки |
| 3 | `monsys-kernel-hl.md` | Ядро: высокоуровневый псевдокод и устройство ОС | `monsys-kernel.hl.txt` — 385 строк |
| 4 | `ose-corpus.md` | Корпус: компиляторы и подсистемы ОС за пределами ядра | `ose-corpus.hl.txt` — 15 459 строк, 1379 тел; `ose-corpus.regions.json` — карта участков |
| 5 | `monsys-kernel-c.md` | Всё то же на уровне C: модель памяти и числа, ограничения | `monsys-kernel.c.txt` — 21 функция, 681 строка; `ose-corpus.c.txt` — 243 функции, 5333 строки |

## Инструменты

| Скрипт | Назначение |
|---|---|
| `tools/besm6tape.py` | Дизассемблер образов SIMH: `info`, `dis`, `text`, `strings`, `zones` |
| `tools/besm6kernel.py` | Анализ ядра по снимку + трассе: `structure`, `listing`, `calls`, `where`, `selfmod` |
| `tools/besm6decomp.py` | Декомпиляция в структурированный псевдокод или в C-подобный вид (`--lang c`, `--routine 0oNNNN`) |
| `tools/besm6harvest.py` | Сбор образов ОЗУ и трасс по заданиям `.dub` + разбор карт E70 |
| `tools/besm6corpus.py` | Сводная карта участков ОЗУ по собранным заданиям |

## Типичный цикл работы

```bash
# 1. снять снимок работающей ОС и трасс
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/copy.dub \
     --limit 400000 --dump-mem /tmp/kernel.img \
     --dump-mem-at 300000 --trace-regs /tmp/trace.txt

# 2. карта ядра
python3 tools/besm6kernel.py structure /tmp/kernel.img /tmp/trace.txt

# 3. псевдокод всего ядра или одной подпрограммы
python3 tools/besm6decomp.py /tmp/kernel.img /tmp/trace.txt
python3 tools/besm6decomp.py /tmp/kernel.img /tmp/trace.txt --routine 0o77661

# 4. собрать корпус по всем заданиям
python3 tools/besm6harvest.py --out /tmp/harvest <список .dub>
python3 tools/besm6corpus.py /tmp/harvest --json /tmp/corpus.json
```

## Три особенности, без которых анализ врёт

1. **Регистр C одноразовый.** После `utc`/`wtc` база действует ровно на одну
   следующую команду. Ядро позиционно-независимо, статически цели переходов
   не восстанавливаются — нужна трасса.
2. **Две команды в одном слове.** Если левая передаёт управление, правая не
   исполняется. «Две мнемоники на строку» — иллюзия.
3. **Правила адресации у команд разные.** `uj`/`uza`/`u1a` идут по
   `адрес + M[i]`, а `vjm`/`vzm`/`v1m`/`vlm` — по голому адресу.

Плюс: номера индексных регистров всюду **восьмеричные** (`(16)` = M[14]),
в трассе `M17` = M[15] = стек.
