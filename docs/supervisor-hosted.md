# Функциональный Supervisor с hosted-сервисами «Дубны»

## Как запускать

В веб-консоли выберите **Supervisor — functional (.dub / .json)**, затем обычный
пример `.dub` из списка и **«Запустить пример»**. Можно также вставить исходник
в редактор и нажать **«Запустить текст»**. По умолчанию выбран полный запуск;
режим отладки включается явно. Выбранная машина не переключается обратно на Dubna.

В CLI:

```powershell
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/fortran.dub --supervisor-hosted --limit 0 --stats --machine-state
```

Эквивалентная настройка конфигурации — `"supervisorHostedServices": true`.
Она несовместима с `bufferedMemory`: это разные backend памяти.

В расширенном состоянии выдаются проверяемые признаки:

```json
{
  "processorProfile": "Supervisor",
  "memoryModel": "Mapped",
  "executionModel": "Functional",
  "serviceRuntime": "HostedDubna"
}
```

## Что это моделирует и чего не моделирует

Это **гибрид**: команды монитора, транслятора и задания исполняет настоящий
супервизорный профиль существующего процессора с существующим MappedMemoryBackend.
Экстракоды обслуживают hosted-сервисы runtime. Это не загрузка исторического
диспетчера с его драйверами и не полная аппаратная модель ОС.

Исходники `src/Besm6.Processor` и `src/Besm6.Architecture` для этого режима
не изменены. Реализация находится в runtime, загрузочной фабрике и веб-обвязке.

Native Supervisor для машинных `.json` остаётся отдельным режимом без hosted-моста.
**Supervisor — hardware пока не принимает `.dub`**. Попытка переключить гибридную
машину на аппаратного владельца исполнения явно отклоняется, а не подменяет модель.
Сам каталог не фильтруется по модели: `.dub` можно выбирать, просматривать
и редактировать также при выбранном аппаратном Supervisor. Выбор `.dub` или
переключение модели не заменяет задание готовым JSON и не включает другую машину
молча. Неподдерживаемый аппаратный запуск останавливается понятным сообщением.

## Память и загрузка

Задание получает математическое пространство **32К слов**. Его страницы 0–31
отображаются на физические страницы 1–32 в уже существующем явно расширенном
backend `Simh512K`. Так математическая страница ноль не закрывается для команд
и не совпадает с пультовыми регистрами физических адресов 1–7.

Это выбранная программная конфигурация размещения, не заявление об исторической
геометрии банков. Для hosted-сервисов используется математическое host-view;
native физическое host-view не меняется.

В обвязке подготавливаются математический режим, адресное отображение, настройки
контроля записи и останов при неожиданных аппаратных нарушениях. Внешние аппаратные
прерывания в этом hosted-профиле заблокированы. Пользовательский код не получает
разрешения исполнять привилегированные команды.

MONSYS и трансляторы создают команды через обычные записи. Перед выборкой такого
слова мост использует существующий `StoreCommand`: публикует запись и согласует
буфер команд. Это явная совместимость нетипизированного hosted toolchain, а не
изменение исторического значения ATX в native Supervisor. Контрольные разряды
при публикации формируются существующим API; сами проверки ядра не выключаются.
Слово с нарушенным контролем и команд, и операнда не «чинится» молча.

## Экстракоды и возврат

1. Неизменённый процессор исполняет экстракод и выполняет штатный супервизорный вход.
2. Существующий механизм сохраняет управляющий контекст и адрес возврата.
3. Runtime-мост восстанавливает контекст через `ReturnFromInterrupt(2)` и передаёт
   типизированный запрос существующему hosted-сервису.
4. Сервис может работать с гостевой памятью, печатью, математикой и лентами.
5. Выполнение продолжается на супервизорном процессоре в математическом режиме.

Пошаговая веб-отладка останавливается после обслуживания команды задания;
низкоуровневое CPU-наблюдение может видеть сам штатный вход в экстракод.
Лимиты, отмена, гостевые часы и статистика принадлежат общему runtime-loop.
Нулевой лимит команд не отключает независимый лимит времени и ручную остановку.

Для явно вооружённого hosted-перехвата арифметической ошибки обвязка переводит
соответствующий сигнал останова в уже существующий контракт перехвата. Нарушения
памяти, защиты и запрещённые инструкции таким способом не скрываются.

## БРЗ, БРС и БРЧ

| Объект | Функциональный гибрид | Native hardware |
|---|---|---|
| БРЗ | Существующие восемь физических регистров и native политика очереди записей | Собственная аппаратная организация обмена |
| БРС | Существующий буфер команд MappedMemoryBackend; выборка его заполняет | Выборка через аппаратного владельца |
| Публикация сгенерированной команды | Runtime вызывает StoreCommand, который публикует данные и инвалидирует соответствующий буфер команд | Hosted-мост отсутствует |
| БРЧ | Не создаются; фиктивных значений нет | Четыре регистра операндов арифметического тракта |
| Аппаратные наносекунды | Отсутствуют | Есть при явной конфигурации задержек |

Физическое содержимое БРЗ не следует путать с текущими валидными адресованными
записями MRU: после публикации физические регистры могут сохранять старое содержимое.

БРЧ — не общий кеш для любого чтения. В существующей модели обычная `XTA` может
загрузить A, не заполнив БРЧ арифметического тракта. Отдельная native hardware
проверка `XTA; AAX` передаёт операнд 12345 через БРЧ. После приёма операнда значение
остаётся в регистре, но признаки `ready`/`active` снимаются.

## Проверка

```powershell
dotnet test tests/Besm6.Runtime.Tests -c Release
dotnet test tests/Besm6.AspNetCore.Web.Tests -c Release
python tools/verify_hosted_supervisor.py
```

Сценарий сравнивает **весь гостевой вывод** пар Dubna / Supervisor-hosted, включая
листинги исторических трансляторов. Отдельно проверяются реальный профиль CPU,
backend, отображение страниц, данные буферов и native hardware БРЧ.

Результаты: [23 пары в max](../reports/hosted-supervisor-verification.json),
[Фортран и MLP в original](../reports/hosted-supervisor-original-verification.json).
В каждой серии отдельно выполнена проверка native hardware БРЧ.

Unit-тесты дополнительно проверяют запись через БРЗ, выборку через БРС,
самомодифицирующийся код, настоящий вход в экстракод, возврат, отсутствие
hosted-сервисов у native Supervisor, испорченный контроль, привилегированные
команды, арифметический перехват, отмену и отсутствие двойного учёта выхода.

`original` и здесь остаётся статистической моделью времени. Совпадение вывода
не доказывает аппаратную, потактовую или историческую точность времени гибрида.
