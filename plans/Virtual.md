# Режим virtual: производительность машины на хосте

Отдельный план, добавленный по запросу пользователя. База — `25c2c80`.

## Контракт

- Добавить `ExecutionSpeed.Virtual`, CLI `--speed virtual` и JSON `"speed":"virtual"`. По умолчанию остаётся `max`; CLI имеет приоритет над JSON.
- Исполнение без pacing, через существующие общие обработчики и быстрые пачки. Регистры, память, события и модельное время совпадают с max для программ без чтения гостевого таймера.
- Гостевой таймер включается явно через `--guest-clock` или `guestClock:true`. В virtual CTIME/STIME возвращают фактическое время исполнительного цикла на хосте; в max/original — прежнее табличное время. Разрешение сохраняется: 20 мс.
- Начало отсчёта — перед первой командой каждого RunLoaded, после загрузки и подключения диагностики. Проверки и печать вне измеряемого тела бенчмарка не входят в разность двух CTIME. Повторный запуск и исключение освобождают прежнюю сессию часов.
- При выключенном таймере сохраняются нулевые ответы. Только virtual с гостевым таймером не требует табличного счётчика; `--stats` включает модельный учёт для сравнения с хостом.
- DATE*, лимиты и диагностические параметры независимы. Диагностика во время измеряемого тела входит в затраты хоста; для рейтинга её следует отключать.
- Инструкционные тики и аппаратные наносекунды не переводятся в часы хоста. Аппаратный virtual исполняется как max; аппаратные таймеры ОС остаются модельными. Hosted CTIME не подменяет таймеры аппаратной ОС.
- Гостевой рейтинг virtual зависит от хоста; он может быть выше или ниже рейтинга модели. `modelToWallRatio` показывает отношение модельного времени к фактическому. Численное совпадение таймерных программ между скоростями не требуется: CTIME намеренно различается.

## Команда

```powershell
dotnet build src/Besm6.Cli/Besm6.Cli.csproj -c Release
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/dhrystone-dmips.dub --speed virtual --guest-clock --stats --no-wall-clock
```

Рейтинг — `N / hostSeconds / 1757`. Не умножать напечатанный DMIPS на коэффициент и не изменять модель задержек устройств. Старые исходники нетаймированных тестов не менять; исторические материалы и пользовательские изменения сохранять.

## Сравнение с SIMH

Режим virtual опубликован коммитом `b8d83e8`, SHA проверен против origin/main. По дополнительному запросу SIMH собран локально в WSL/GCC, без панели SDL, на закреплённой ревизии `9e318d16a203a3efae3420ea3f5700a8d7e3bec3`. Использованы уже закреплённые образы DISPAK; сначала выполнено штатное задание простых чисел. Бинарные файлы, копии образов, сторонний checkout и полный вывод остаются локально.

Под DISPAK поданы те же FORTRAN-тела: Dhrystone N=5000, MPMFLOPS kpart=3/9000/30 и Whetstone NRUNS=100. Изменён только пакетный конверт, регистр управляющих карт и отключено печатание листинга. Независимые численные контроли прошли. Формулы проверены по реально напечатанным строкам, без листинга компилятора; для SIMH учтено округление времени в F12.4 (половина последнего разряда). Кириллические ГОСТ-гомоглифы переведены в латиницу, численные поля не исправлялись.

Однократные гостевые показатели разных сред, **не доказательство отношения скоростей одинакового машинного кода**:

| Тест | besm6.net virtual | SIMH / DISPAK | Единица |
|---|---:|---:|---|
| Dhrystone 5000 | 8.892999 | 20.236514 | DMIPS |
| Whetstone 100 | 29.387037 | 53.453474 | MWIPS |
| MPMFLOPS 3 | 13.090909 | 50.269091 | MFLOPS |

Различаются ОС/окружение компилятора и механизм гостевого учёта времени. В SIMH таймер калибруется по хосту; этот запуск не доказывает тактовую точность или скорость исторической БЭСМ-6. Для строгого сравнения эмуляторов нужны одинаковый машинный образ, подтверждённый источник времени и последовательные повторные серии. Длительность полного процесса включает загрузку/компиляцию/печать и не используется вместо времени тела теста. Короткое ядро MPMFLOPS 1 в SIMH правильно отказалось выводить рейтинг; ядро 3 измерилось.

Pascal MPMFLOPS в besm6.net virtual достиг STOP, численный контроль ALL SAME: YES выполнен; собственного рейтингового таймера в этом нетаймированном задании нет. В DISPAK штатный запуск потребовал FICMEMORY; попытка с документированной картой дала ошибку доступа к чужому листу. Pascal-рейтинг SIMH и успешное выполнение его тела не заявляются.

Проверка по [справочнику FORTRAN, раздел об учёте времени](../book/fortran-1976/02-fortran-dubna.md): первый выход таймера коммерческий, второй — счётный CPU. MPMFLOPS, Memspeed и Whetstone исправлены на разность RT1-RT0, как Dhrystone. После исправления повторно прошли **72/72** гостевых сценария в трёх скоростях и **84/84** Python-проверки; код CPU/Runtime после полного Release-гейта не менялся.

## Pascal Dhrystone и Whetstone

Добавлены examples/dhrystone-pascal.dub и examples/whetstone-pascal.dub. Прежний нетаймированный Pascal Dhrystone сохранён. Новый Dhrystone использует native Pascal записи, указатели, строки, процедуры и функции, включая Func3; проверяет 18 основных величин/отношений и четыре строки. Whetstone использует Pascal массивы и процедуры с var-параметрами, восемь секций, те же независимые эталоны и нормировку 15869*10 WIPS на проход. Данные восстанавливаются перед каждым полным проходом.

Таймер CTIME подключён из гостевой библиотеки через PROCEDURE ... FORTRAN; CPU-время — второй выход. Компиляция, выделение памяти, подготовка, контроль и печать вне измеряемого интервала. Оба задания требуют явного --guest-clock; разрешение 20 мс и минимальный интервал 40 мс сохраняются. Число проходов задаётся в Pascal CONST, а проверочные варианты создаются отдельно.

Приёмка: **33/33** сценария в max/original/virtual — Dhrystone N=5000/10000/0/1, Whetstone 100/0/1, выключенный таймер и намеренно неверные эталоны. Проверены STOP, код возврата, независимые численные/строковые контроли, формулы и защитные сообщения. Между модельными скоростями совпали вывод, конечное состояние, память, инструкции и такты. Python **89/89**, golden **3/3**. Код CPU и Runtime не менялся; полный прежний CERN-гейт не повторялся для добавления гостевых исходников.

Одиночные контрольные рейтинги на текущем хосте (со статистикой, не повторная серия измерения ускорения):
