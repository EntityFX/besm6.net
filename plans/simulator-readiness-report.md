# Готовность симулятора БЭСМ-6

**Актуально на:** 31.08.2026

**Проверенная ревизия кода:** `dfcd35b3ed4e1195556a9599583e4106acc55d1f`

Проверенная ревизия предшествует коммиту этого отчёта: численные результаты ниже
получены на `dfcd35b3`, а не на документационном коммите.

**Назначение:** единый актуальный источник статуса. Старые отчёты сохраняют историю
диагностики, но их численные результаты и выводы следует сверять с этим документом.

## 1. Краткий итог

На проверенной ревизии полный автоматизированный набор проходит без падений.
Из корня developer checkout штатно находятся конфигурация и MONSYS-ресурсы,
raw-программы выполняются без загрузки MONSYS, а `name.dub`, `algol.dub` и
`bemsh.dub` завершаются штатным STOP. Отсутствующий обязательный ресурс вызывает
понятную ошибку до исполнения инструкций.

Эта проверка не доказывает самодостаточность установленного пакета. В рабочем дереве
`ref/dubna` является локальным junction на игнорируемый reference checkout с образами
лент. Образы не копировались и не добавлялись в поставку.

## 2. Свежие результаты проверки

Все команды в этом разделе запущены из корня worktree на ревизии `dfcd35b3`.

### Сборка и автоматизированные тесты

| Проверка | Результат |
|---|---|
| `dotnet build src/besm6.net/besm6.net.sln -c Release --no-restore` | exit 0; 0 ошибок, 64 существующих предупреждения |
| `dotnet test src/besm6.net/besm6.net.sln -c Release --no-build --no-restore` | exit 0; 448 passed, 0 failed, 3 skipped; всего 451 |
| `py -3 -m unittest discover -s tools/tests -v` | exit 0; 7 из 7 passed |

Три пропуска MSTest: документированный бесконечный `W303_LoopsForever` и два
диагностических trace-теста (`DumpAtDivergence`, `TraceAlgol_Last30Instructions`).
Raw hello-тест больше не пропущен и входит в зелёный прогон. 64 предупреждения сборки
существовали до этой проверки; они зафиксированы как незакрытый долг, а не выданы за
новые ошибки.

### CLI и примеры из корня worktree

`help` завершился с exit 0 и напечатал список команд.

| Пример | Exit | Проверенный результат |
|---|---:|---|
| `examples/name.dub` | 0 | `Halted by STOP at 0118 after 209176 instructions` |
| `examples/algol.dub` | 0 | компиляция и исполнение; `HELLO, WORLD!`; `Halted by STOP at 0118 after 787665 instructions` |
| `examples/bemsh.dub` | 0 | компиляция без ошибок; `ПPИBETИK! ЭTO ABTOKOД БEMШ.`; `Halted by STOP at 0118 after 1042999 instructions` |

Для отрицательной проверки использована отдельная временная конфигурация
`{"tapes":"missing"}`. Запуск `name.dub` завершился с exit 1 и диагностикой
`Cannot mount MONSYS tape`; строки с числом исполненных инструкций и `Halted by`
отсутствовали. Таким образом, ошибка обязательного ресурса обнаруживается до начала
исполнения, а явно заданный ошибочный путь не маскируется поиском fallback-ресурса.

## 3. Исправленный тракт исполнения

- Неявный поиск штатной конфигурации и каталога `tapes` воспроизводим для developer
  checkout и больше не зависит от запуска из `ref/dubna`.
- Относительные пути явно указанной конфигурации проверяются по порядку: каталог
  конфигурации, текущий каталог и каталог приложения. Для неразрешённого
  нестандартного пути не включается checkout-discovery, предназначенный только для
  conventional `tapes`; исходный путь сохраняется в диагностике загрузчика.
- Обязательные MONSYS и запрошенные job-картами ленты проверяются до исполнения;
  фиктивный пустой образ не считается успешно смонтированным обязательным ресурсом.
- Raw-words и локальный `*assem` без `*execute` идут по минимальному тракту и не
  требуют MONSYS. Ошибка старта raw `hello.dub`, `math.dub` и `io.dub` через
  `*trans-main` исправлена и покрыта тестами.
- ALGOL и BEMSH теперь компилируются, печатают ожидаемый текст и доходят до штатного
  STOP на проверенных примерах.
- `check` возвращает ненулевой код при ошибке загрузчика/исполнения и при достижении
  лимита инструкций. Успешный `check` подтверждает только штатное завершение
  исполнения; он не доказывает семантическую эквивалентность напечатанного результата.

## 4. Границы текущей готовности

### Ресурсы и поставка

Проверен developer checkout с локальным `ref/dubna` junction. Это механизм обнаружения
ресурсов для разработки, а не решение installed packaging. Для самостоятельной
поставки ещё требуется лицензированный, документированный способ установки образов
лент; этот отчёт не утверждает, что ленты входят в пакет.

### CERNLIB

Сейчас портированы только два контрольных CERNLIB beacon-теста. Полная активная
матрица из 420 тестов не пройдена и является следующим отдельным проектом.
`w303` остаётся документированным бесконечным тестом и не относится к активной
конечной матрице.

### Устройства и прерывания

Текущий поддерживаемый тракт ввода-вывода достаточен для проверенных MONSYS/Dubna
workload, но не является аппаратно точной моделью. Асинхронное завершение устройств,
каналы готовности и полноценная модель прерываний остаются отдельным проектом.

### Качество

- Устранить 64 существующих предупреждения сборки.
- Расширить end-to-end и дифференциальное покрытие загрузчика, экстракодов и устройств.
- Автоматизировать проверку ожидаемого семантического вывода примеров поверх проверки
  их штатного завершения.

## 5. Следующие проекты

1. Портировать и проверить активную CERNLIB-матрицу из 420 тестов.
2. Подготовить самодостаточную и лицензированную поставку runtime-ресурсов без
   developer-only junction.
3. Отдельно спроектировать аппаратно точные асинхронные устройства и прерывания.
4. Добавить semantic-output oracle для `check` или отдельного regression runner;
   текущий `check` намеренно проверяет только завершение исполнения.
