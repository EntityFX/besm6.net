# Готовность симулятора БЭСМ-6

**Актуально на:** 30.08.2026

**Проверенная ревизия кода:** `b48d9b0`

**Назначение:** единый актуальный источник статуса. Старые отчёты сохраняют историю
диагностики, но их численные результаты и выводы следует сверять с этим документом.

## 1. Краткий итог

Симулятор уже выполняет ядро БЭСМ-6, загружает MONSYS, компилирует и запускает
FORTRAN, MADLEN и Pascal-примеры. Процессорный тракт и основные экстракоды имеют
регрессионные тесты. Полной работоспособности пока нет: запуск зависит от текущего
каталога, полный набор тестов не зелёный, ALGOL и BEMSH расходятся с ожидаемым
потоком, а часть загрузчика и устройств недостаточно покрыта.

### Примеры

При запуске из `ref/dubna`, где относительный путь `tapes` разрешяется в каталог
с образами:

| Пример | Результат |
|---|---|
| `name.dub` | STOP, exit 0, 209174 инструкций |
| `fortran.dub` | `HELLO, WORLD!`, STOP, exit 0, 1365272 инструкции |
| `assem.dub` | `HELLO, WORLD!`, STOP, exit 0, 4799369 инструкций |
| `madlen.dub` | `HELLO, WORLD!`, STOP, exit 0, 4799346 инструкций |
| `pascal.dub` | `HELLO, WORLD!`, STOP, exit 0, 1600092 инструкции |
| `forex.dub` | `HELLO, WORLD!`, STOP, exit 0, 1365240 инструкций |
| `pi.dub` | процесс завершается, но исходник отвергается старым FORTRAN-компилятором; функционального результата нет |
| `algol.dub` | ошибка `Unimplemented extracode *50 70226` в PC `01441` |
| `bemsh.dub` | ошибка `E57: unimplemented extracode *57 6` в PC `02403` |

Из корня репозитория все MONSYS-примеры завершаются `Jump to zero`: конфигурация
указывает каталог `tapes`, которого в корне нет; реальные образы лежат в
`ref/dubna/tapes`. Ошибка монтажа не останавливает загрузку достаточно рано.

Raw-words: `hello-assem.dub` проходит; `hello.dub`, `math.dub` и `io.dub` начинают
исполнение с PC=0 и падают с `Jump to zero`. Общий признак — путь `*trans-main`.

## 3. Что уже реализовано

- 48-разрядная память, регистры, адресация и основной набор команд БЭСМ-6.
- Арифметика, режимы РАУ, стековая коррекция и перехват арифметических ошибок.
- Правильное завершение слова после экстракода и сохранение ACC/RMR/RAU.
- Одноразовые fetch/read/write watchpoints экстракода `*67`.
- Загрузка MONSYS, ленты/диски/барабаны и синхронные операции `*70`.
- Основные операции `*57`, включая режим записи и реализованную часть файлового
  протокола `*57 77777`.
- Форматы вывода `*64`, терминальный/перфорационный путь `*71`, сервисные запросы
  `*63`, `*65`, `*72`, `*75`, `*76` в объёме эталонной реализации.
- Разбор и форматирование `*50 014/017` присутствуют в коде, но пока не подтверждены
  покрытием и end-to-end тестами.

## 5. Критерии полной готовности

Симулятор можно считать полностью рабочим для выбранной области MONSYS/Dubna, когда:

1. Чистая сборка имеет 0 ошибок и 0 предупреждений.
2. Полный MSTest-набор проходит без падений; допустимые пропуски перечислены и
   обоснованы.
3. Все 420 активных CERN-тестов запускаются и совпадают с ожидаемым выводом; `w303`
   остаётся документированным бесконечным тестом.
4. Все поддерживаемые примеры запускаются из корня репозитория без зависимости от CWD.
5. ALGOL и BEMSH доходят до штатного STOP и дают ожидаемый вывод.
6. Ни один поддерживаемый workload не попадает в необъяснённый `Unimplemented`.
7. Raw-words, MONSYS, дисковый I/O и интерактивный ввод имеют end-to-end тесты.
8. Для каждого сознательно неподдерживаемого аппаратного режима есть явная
   диагностика и запись в документации.

## 6. Рекомендуемый порядок работ

1. Пути ресурсов и три инфраструктурных падения тестов.
2. Полный CERN-прогон как основной регрессионный барьер.
3. Дифференциальная локализация ALGOL, затем BEMSH.
4. Raw `*trans-main` и тесты E50/E57/E64.
5. Аппаратная точность устройств и рост покрытия.
