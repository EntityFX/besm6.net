## Найденные и исправленные баги (21.08.2026, сессия тестов)

1. **`Word48.ToDouble()`** — использовал НЕверный знако-модульный формат
   (`[47 знак][46-41 порядок][40-1 мантисса]`, мантисса сдвинута на 1),
   а не канонический БЭСМ-6 two's complement. Для `1.0` возвращал `-0.00390625`.
   Исправлен на точный порт `besm6_to_ieee` (sign-extension мантиссы через `<< 23`).
   Активный потребитель — `ExtracodeHandler.E50Format`.
2. **`Word48.FromDouble()`** — был несовместим с `ToDouble()` (round-trip ломался).
   Заменён на порт `ieee_to_besm6`.
3. **`Word48.FromOctal()`** — для строк длиннее 16 цифр обрезал МЛАДШУЮ цифру,
   а не старшую. 17-символьное `"04050000000000000"` (каноническая запись 1.0)
   парсилось неверно. Теперь берём младшие 16 цифр (старший ведущий 0 — бит 48).

Эти баги выявлены новыми юнит-тестами (`Word48Tests.cs`, `NumberConversionTests`,
`TapeIdTests`). Полный набор: **96/96 зелёных**.

## Корневые причины

### 1. КРИТИЧНО: неверный путь к лентам
`src/besm6.net/besm6.json` задаёт `"tapes": "dubna/tapes"`, но каталога `dubna/` в репозитории нет — ленты лежат в `tapes/` (корень):

```
tapes\monsys.9    1 769 472 байт   (288 зон × 1024 слова)
tapes\librar.12   1 966 080
tapes\librar.37   2 605 056
tapes\bemsh.739     172 032
tapes\b.7           141 312
```

`Config.ResolvePath("dubna/tapes")` возвращает несуществующий путь →
`File.Exists` всегда `false` → MONSYS не монтируется. **Главный блокер.**

### 2. Искажены константы tape-id в `TapeImage.cs`
Текущие (неверные) → канонические (из C++ `machine.h`, TEXT + номер):

| Константа | Текущее (hex) | Каноническое (hex) |
|-----------|--------------|-------------------|
| TapeMonsys   | `0x2E2F2E333734000B` | `0xB6FBB3E73009` |
| TapeLibrar12 | `0x2C29222E212E0012` | `0xB298B2872012` |
| TapeLibrar37 | `0x2C29222E212E0037` | `0xB298B2872037` |
| TapeBemsh    | `0x24292F2E21232339` | `0x929CF08636D9` |
| TapeB        | `0x2200000000000007` | `0x880000000007` |

Проверено Python: `int("5557566371630011", 8) == 0xB6FBB3E73009` и т.д.

### 3. ALU уже исправлен (по `plans/fix-alu.md`)
`MantissaExponent` использует `long`, маску `0x7F`, sign-extension; `Alu.cs` —
точный порт `arith_add/normalize/multiply/divide/nrdiv`; тесты на 17-символьных
кодировках. Не блокер.

### 4. Непокрытые места (выявил сравнительный анализ)
- E57: в C# реализован только `addr==1/2/3` (упрощённый монтаж), отсутствуют
  `e57_tape` (ASSIGN/RELEASE/FIND/BYNAME/WRITE/READ по битовым маскам) и
  `e57_file` (FILE_SEARCH/OPEN/SCRATCH).
- E50 parse: буфер идентификатора 16 вместо 128; нет «длинный идентификатор».
- Проверить `Besm6Math` (IEEE↔БЭСМ-6) побитово против `ref/besm6_arch.cpp`.
- Проверить таблицы кодировок против `ref/encoding.cpp`.
