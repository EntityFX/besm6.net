# План исправления ALU (арифметического устройства) БЭСМ-6

## Диагностика проблем

Проанализирован C# код (`src/Core/MantissaExponent.cs`, `src/Core/ArithmeticUnit.cs`),
C++ референс (`dubna/arithmetic.cpp`, `dubna/besm6_arch.h`) и тесты
(`tests/Besm6.Tests/AluTests.cs`, `dubna/tests/alu_test.cpp`).

Прогон тестов подтвердил: `5` из `7` тестов АЛУ падают.

### Корневые причины

1. **`Mantissa` хранится как `ulong` (беззнаковый) вместо `long` (со знаком)**
   - C++: `int64_t mantissa; // Note: signed value`
   - C#: `public ulong Mantissa;`
   - Ломает АРИФМЕТИЧЕСКИЙ сдвиг: для отрицательных мантисс `>>` в C# на `ulong`
     даёт 0-fill вместо 1-fill (в C++ на `int64_t` — 1-fill).

2. **Неверная маска извлечения экспоненты**: `0x3F` (6 бит) вместо `0x7F` (7 бит)
   - C++: `exponent = (val >> 41) & BITS(7)` (7 бит)
   - C#: `Exponent = (int)((val >> 41) & 0x3F)` (6 бит) ← BUG

3. **Отсутствует sign-extension при создании из Word48**
   - C++: `mantissa <<= 23; mantissa >>= 23;` (sign extend из бита 40 → 64 бита)
   - C#: просто хранит `val & BITS41` как unsigned.

4. **Неправильная финальная упаковка результата в `ArithNormalizeAndRound`**
   - C# использует знак-модуль + отдельный бит знака 47:
     `(Exponent & 0x3F)<<41 | magnitude<<1`, и `| (1L<<47)` при отрицательном.
   - C++ пакует напрямую в two's complement:
     `(exponent & BITS(7))<<41 | (mantissa & BITS41)` (бит 40 — знак мантиссы).

5. **Неверные (заглушечные) восьмеричные значения в тестах `AluTests.cs`**
   - В C++ значение записывается как 17-символьный литерал, где ведущий `0` — это
     префикс восьмеричной системы: `04050000000000000` = окт. цифры `4050000000000000`.
   - В C# строка `"0405000000000000"` (16 символов) трактует ведущий `0` как
     значимую цифру, что сдвигает все разряды вниз. В итоге:
     - `"0405000000000000"` (16) → крошечный денормализованный (~5·2⁻⁶⁰), а НЕ 1.0;
     - `"0402000000000000"` (16) → **НОЛЬ** (экспонента 9, мантисса 0), а НЕ −1.0.
   - Поэтому тесты не пройдут даже после исправления АЛУ — нужны корректные
     17-символьные кодировки.
   - `Word48TestExtensions.FromOctal` усекает строку до 16 символов (`if (len > 16)`),
     из-за чего теряется 17-я (старшая) цифра.

### Формат числа БЭСМ-6 (0-based биты, подтверждён C++ референсом)

```
Биты 47-41 (7 бит): экспонента (bias = 64)
Бит 40:            знак мантиссы (two's complement)
Биты 39-0 (40 бит): мантисса
Value = signed_41bit_mantissa / 2^40 * 2^(exponent - 64)
```

Константы (значения соответствуют C++): `BITS40 = 2^40-1`, `BITS41 = 2^41-1`,
`BITS42 = 2^42-1`, `BIT40 = 1<<40`, `BIT41 = 1<<41`, `BIT42 = 1<<42`.

Проверка на примере: `04050000000000000` (17) = `2^47 + 5·2^39`.
- exponent = `(V>>41) & 0x7F` = 65;
- мантисса = `V & (2^41-1)` = `2^39` (положительная);
- value = `2^39/2^40 · 2^(65-64)` = `1.0` ✓
