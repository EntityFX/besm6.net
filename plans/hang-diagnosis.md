## 2. `pascal.dub` — БЕСКОНЕЧНЫЙ ЦИКЛ (главный «зависание»)

### 2.1 Симптомы

```
PASCAL COMPILER. 14.(24.12.79)
00001    1 PROGRAM MAIN (OUTPUT);
******49 CЛИШKOM MHOГO KOMAHД B БЛOKE
[затем: бесконечный цикл PC в зоне 04CDA-04FA6, 200M+ инструкций]
```

### 2.2 Корневая причина

**Исходный текст PASCAL-программы не полностью загружен в память.**

C# симулятор показывает, что компилятор прочёл **только 1 строку** из 4:

| # | Строка в .dub | Видел компилятор? |
|---|---------------|-------------------|
| 1 | `program main (output);` | ✅ Да |
| 2 | `_(` | ❌ Нет |
| 3 | `    writeln('Hello, World!');` | ❌ Нет |
| 4 | `_).` | ❌ Нет |

Компилятор видит только `PROGRAM MAIN (OUTPUT);` и выдаёт ошибку
**49 — «слишком много команд в блоке»**, потому что `OUTPUT` без тела
невозможно распарсить. После ошибки компилятор **зацикливается** —
это **ошибка самого PASCAL-компилятора** (ошибка в обработке ошибки,
не в симуляторе).

### 2.3 Сравнение с эталоном C++

`ref/tests/expect_pascal.txt` (63 строки) показывает:

```
PASCAL COMPILER. 14.(24.12.79)
00001    1 PROGRAM MAIN (OUTPUT);
00007    2 _(
00007    3     WRITELN(′HELLO, WORLD!′);
00024    4 _).
[таблица символов]
≠
HELLO, WORLD!
```

C++ компилятор **успешно** компилирует все 4 строки, выводит
таблицу символов и `HELLO, WORLD!`. **Ошибки 49 нет.**

### 2.4 Гипотезы (по убыванию вероятности)

1. **JobParser → DubnaLoader: SourceLines теряются.**
   JobParser корректно собирает `job.SourceLines`, но `DubnaLoader`
   при записе текста в память (COSY-кодек) обрезает после первой строки,
   либо не записывает все строки подряд.

2. **E64 print — ограничение по endAddr.**
   Если pointer-слово задано как `endAddr = 0`, E64 читает до
   терминатора `0x7A`. Но если терминатор отсутствует (текст
   обрезан при загрузке), E64 зацикливается.

3. **Загрузка в память по адресу.**
   Паскаль-компилятор ожидает текст на определённом адресе, но
   DubnaLoader записал его в другое место.

### 2.5 Следующие шаги (для диагностики)

```
1. Добавить трассировку в DubnaLoader:
   - Сколько строк в job.SourceLines для pascal.dub.
   - Какой COSY-код получен.
   - Куда (какой адрес) записан текст в памяти.

2. Сравнить с C++ machine.cpp → load_source():
   - Какой адрес используется.
   - Как записываются строки (каждый байт = 8 бит, паковка 6 байт/слово).
   - Где ставится COSY_END_FILE (0x1A или 0x7A).

3. Прогнать pascal.dub с --limit 1000 и dump памяти:
   - Прочитать область, где должен быть исходный текст.
   - Проверить, что там COSY-кодек всех 4 строк + терминатор.
```

## 3. `algol.dub` — Illegal instruction 002 рег/mod

### 3.1 Симптомы

```
Error at 02001: Illegal instruction 002 рег/mod
```

### 3.2 Корневая причина

Инструкция `002 рег/mod` — **привилегированная** (режим супервизора).
**Ни C++, ни C# не реализуют её** — оба бросают `throw`.
Это **известный общий gap** (описан в `plans/monsys-kernel-support.md`).

C++ `processor.cpp:178`:
```cpp
case 002:
    throw Exception("Illegal instruction 002 рег/mod");
```

C# аналогично бросает `ProcessorException`.

### 3.3 Что это значит

ALGOL-компилятор (BEMSH) требует режим супервизора. Пока эта
инструкция не реализована, **ALGOL-программы не будут работать ни
в C++, ни в C#**. Это не баг C#-порта — это общий лимит референса.

## 4. Не-баги (известные ограничения)

| Экстракод | Статус | Комментарий |
|-----------|--------|-------------|
| E61 (VT-340/plotter) | no-op в C# | C++: `core.ACC = 0` для addr ≠ 077777. Нет влияния на логику. |
| E72 (страницы памяти) | no-op в C# | ОС Дубна не использует в наших примерах. |
| E65 (выключатели) | Частично | Некоторые addr не реализованы → ProcessorException. |

## 5. Итоговый вердикт

**Симулятор НЕ «виснет глобально».** 6 из 8 примеров работают штатно.

Два не работают:

1. **`pascal.dub`** — исходный текст не полностью загружен в память →
   компилятор PASCAL выдаёт ошибку 49 → зацикливается.
   **Баг в загрузке текста (DubnaLoader/COSY-кодек).**
   Это **баг C#-порта**, а не общий gap.

2. **`algol.dub`** — не реализована инструкция `002 рег/mod`
   (привилегированная). **Общий gap** C++ и C#.
   Требует реализации режима супервизора.
