# Новая серия: масштабирование задач ИИ на одной Linux-машине

**Все данные этого набора получены на одном Linux-хосте. Windows-пилоты в итоговые
измерения не включены.** В Git хранятся только компактные итоговые данные,
исходники и текст статьи. Предыдущие редакции доступны в истории Git;
полные выводы и промежуточные материалы сохранены отдельно от репозитория.

## Окружение

- Intel Xeon E5-2680 v3, базовая частота 2,50 ГГц; частота не фиксировалась.
- Linux / ALT, CPython 3.12.7, GNU Fortran 13.2.1, .NET 8.0.21.
- Современные тайминги выполнены последовательно, на одном логическом CPU (`0`),
  без одновременно работающих функциональных экспериментов.
- Базовый Runtime: `737349e10e87f339cec369340be384a531edfb8a`.
- SIMH: `698dc8a1b2135ab03f1da0be9ee44b5f1beeadc6`.

Сведения об окружении: [`environment.json`](environment.json).

Для целочисленных итогов требуется точное равенство. Для вещественного результата
`x` используется допуск `1e-5 + 1e-7*abs(x)`, а не утверждение о побитовом равенстве.
Проверяются итоговые значения и контрольные суммы, не все промежуточные состояния.
У наивного Байеса одинаковое относительное правило ничьей `1e-5` задано явно:
меньший порог `1e-8` округлялся к единице в выражении `1+epsilon` при `REAL` IEEE 32.

## Что измерено

Время БЭСМ-6 — **расчётная оценка исполнения на советской ЭВМ**, не измерение
действующей БЭСМ-6 и не скорость работы приложения C#.

Границы модели:

1. Начало исполнения MONSYS → вход программы `01000`: подготовка, включая
   монитор, трансляцию, листинг, подключение библиотек и размещение.
2. Вход программы → первый вызов `BCDWRIT*`: генерация и инициализация данных,
   алгоритм и контрольные итоги без печати.
3. Первый вывод → остановка: форматирование, вывод и завершение.

На всех границах читается один и тот же `HostedOriginalTiming`. Старый
`OpcodeProfiler.ModeledSeconds`, считающий другую таблицу тактов, не подменяет его.

Искусственное ожидание темпа отключено для ускорения серии. На том же Linux-хосте
выполнены **12 точных парных проверок** против обычного `original`: совпали модельное
время, число команд, вывод, вычислительный интервал и хеш конечной памяти.
См. [`original-mode-validation.json`](original-mode-validation.json): обе стороны
каждой пары содержат времена, счётчики и хеши вывода и памяти без самих полных выводов.

В Python используется процессорное время `process_time_ns`, в Фортране —
`CPU_TIME`. Для каждого ядра взята медиана пяти серий с адаптивным числом вызовов,
чтобы серия занимала около 0,15 с или больше. Генерация текста на Фортране и
компиляция не входят в Python-ядро. Нативный драйвер и подпрограмма компилируются
раздельно с `-O0`, без LTO; возвращаемый контрольный скаляр используется драйвером.

Полные процессы измерены отдельно десять раз, компиляция и связывание GNU Fortran —
три раза, по реальному времени хоста. Проверки массивов и переполнения включались
для функциональной проверки, но не в сборке для таймингов.

## Основные результаты

У десяти больших вариантов счёт занимает **91,2–98,0 %** полного модельного времени.
У контрольного MLP — около 58 %. Модельное время счёта превышает процессорное
время Python примерно в **156–678 раз**, кода GNU Fortran `-O0` — в **3990–13084 раза**.
Это результаты конкретных реализаций и настроек, не универсальные коэффициенты
быстродействия языков или оценка чистого аппаратного прогресса.

Параметры: [`manifest.json`](manifest.json). Все размеры: [`all-sizes.json`](all-sizes.json).
Итоговые 11 программ: [`comparison.json`](comparison.json).

## Почему раньше расходился SIMH

Карта `*FTN` выбирает Фортран-ГДР 10.06.84; `*FORTRAN` — Фортран-Дубна, используемый
также в основной модели. В дополнительной серии ГДР совпали **27/41** вариантов,
а 14 вариантов перцептрона, kNN, Байеса и A* дали другие итоги.

Смена только управляющей карты на `*FORTRAN` дала **41/41**, без изменения тел
программ. Это показывает зависимость результата от выбранной цепочки трансляции
и исполнения, но само по себе не доказывает ошибку конкретного компилятора или CPU.
Малые диагностические примеры воспроизводятся сценарием
`tools/diagnose_simh_scaling.py`; итоговые проверки — в `diagnostic-results.json`.

Основная серия: [`simh-fortran-results.json`](simh-fortran-results.json).
Отдельная серия ГДР: [`simh-gdr-results.json`](simh-gdr-results.json).
Полные листинги обеих серий не включены в Git.

## Структура данных

- [`examples/ai/scaled/`](../../examples/ai/scaled/) — точные входные тексты.
- `all-sizes.json` — модельные времена, счётчики и доли для 41 варианта.
- `native-results.json` — проверки GNU Fortran всех 41 вариантов.
- `host-benchmark-results.json` — исходные числовые серии таймингов без консольных выводов.
- `simh-fortran-results.json`, `simh-gdr-results.json` — сводки двух разных трансляторов.
- `image-sha256.txt` — хеши публичных образов ОС; сами образы не дублируются в Git.
- `sha256.json` — хеши компактных экспортированных файлов.
- `comparison.csv` — плоская итоговая таблица для внешней обработки.

Стенды и измерительные ядра воспроизводятся опубликованными сценариями;
генерируемые листинги, консольные логи, исполняемые файлы и образы ОС не хранятся в Git.

## Воспроизведение

Сценарии находятся в `tools/` репозитория. Использовать отдельный каталог `RUN`
на Linux и стандартные образы проекта:

```bash
dotnet build src/Besm6.Cli/Besm6.Cli.csproj -c Release -o "$RUN/cli"
dotnet build tools/AiScalingProbe/AiScalingProbe.csproj -c Release -o "$RUN/probe"
python3 tools/benchmark_ai_scaling.py --work "$RUN" --levels 0,1,2,3
python3 tools/check_ai_scaling_native.py --work "$RUN"
# Выполнять отдельно, когда закончились другие тяжёлые эксперименты:
python3 tools/benchmark_ai_scaling_host.py --work "$RUN"
```

Для SIMH нужны `RUN/simh-source`, `RUN/images` и сохранённые INI-конфигурации;
описание сборки: https://www.besm6.org/wiki/Building,
образы: https://www.besm6.org/download/.
Не использовать системные диски других проектов: сценарий создаёт частные копии.

```bash
python3 tools/check_ai_scaling_simh.py --work "$RUN" --translator fortran
```

Стенд использует внутренний объект времени версии `737349e`; при изменении Runtime
может потребоваться адаптация. Соответствие времён действующей советской ЭВМ
не проверялось: её доступного работающего экземпляра нет в эксперименте.
