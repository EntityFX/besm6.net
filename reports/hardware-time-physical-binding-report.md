# Подключение физического контроля АУ к общему CPU

Блок принят относительно `576ce39`: явная политика ошибок при связывании команды CPU со стадиями АУ,
отмена принадлежащих запросу событий с сохранением поднятых сигналов, выдача общего A/Y без повторного
авоста Dubna. Деление без проверенного результата не публикует вымышленное A/Y; при подавленных
сигналах продолжение явно неподдержано. Это интеграция владельцев исполнения, а не завершение модели АУ.

Проверки: 2983 теста Release, CERN 397/397, golden 3/3; три прежних пропуска.
25 новых случаев проверяют оба полуслова, четыре политики, переполнение, отмену, reset и неверный делитель.
В первой серии новые проверки не получили арифметическую команду: стенд записывал адрес 1 в физическую
память вместо пультового регистра. Исправлена загрузка стенда, правила адресации CPU не менялись.

Худшая регрессия RunLoaded: 3.891%; полного CLI: 2.143%, допуск 5%.
Максимальная ошибка original: 7.988 мс.
Последовательные Release-прогоны: один прогрев, пять измерений, фиксированный DATE*,
baseline Dhrystone/MPMFLOPS; исходный вывод хранится локально с SHA256-манифестом.
Функциональные CERN/бенчмарки подтверждают совместимость; аппаратный запуск ОС ими не подтверждается.

Принято 5 оценочных часов интеграции драйвера: остаток 135 → 130 ч, этап 5 — 70/200 ч (35%).
Впереди: переменное время АУ, MRAM/буферы, устройства/прерывания, единый драйвер/CLI и общая приёмка.
[Данные и манифест](hardware-time-physical-binding-results.json).
