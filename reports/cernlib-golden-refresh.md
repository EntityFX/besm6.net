# Исправление трёх ложных отказов CERNlib

9 октября 2026 года. Случаи `lib2/i312a`, `lib2/j531a`, `lib2/j531b`
сравнивались с устаревшими ожидаемыми файлами из локального `ref/tests`.
Исполнение C# соответствует документации и независимому C++-эмулятору;
изменять процессор или форматтер для воспроизведения старого вывода не требуется.

## Документация и независимые подтверждения

В учебнике 1976 года [§52](../book/fortran-1976/03-madlen.md#section-52)
описана PRINTE, а в [§29](../book/fortran-1976/02-fortran-dubna.md#section-29)
указано округление младшей цифры при выводе E/F/D. Форматтер экстракода
E64 добавляет половину единицы последнего разряда перед извлечением цифр.
Такой алгоритм закреплён в
[исправлении C++ от 10 апреля 2025 года](https://github.com/besm6/dubna/commit/5dfe4ea42eb08464df42030a465306fe2c12c7c4).

Код ГОСТ 0020 — знак десятичного порядка, Unicode U+23E8 `⏨`.
Это печатный символ, а не form-feed U+000C. Таблица и вывод есть в
[encoding.cpp](https://github.com/besm6/dubna/blob/9cc404f4241e00c2d98e386a85cdf56eca7a74a9/encoding.cpp)
и [e64.cpp](https://github.com/besm6/dubna/blob/9cc404f4241e00c2d98e386a85cdf56eca7a74a9/e64.cpp).
Старая гипотеза отчёта `cernlib-matrix-a1.md` о лишнем `\f` не подтвердилась:
в фактическом UTF-8 выводе стоит именно U+23E8.

Upstream самостоятельно обновил все три expected-файла 7 октября 2026 года:
[коммит 9cc404f](https://github.com/besm6/dubna/commit/9cc404f4241e00c2d98e386a85cdf56eca7a74a9).
Файлы источников и эталонов скопированы из этого коммита без изменения байтов.
Исходники совпали с локальным корпусом; эталоны точно совпали с C#-выводом.
Это закрепление исправленных эталонов вывода для существующей реализации,
а не импорт последующих изменений арифметики из upstream.

| Случай | Что устарело в expected |
|---|---|
| i312a | `e` вместо `⏨` и последние цифры до исправления округления E64 |
| j531a | ASCII `e` вместо знака десятичного порядка в двух подписях осей |
| j531b | То же представление порядка в двух подписях осей |

Примеры обновления i312a: `922337203683799` → `922337203683800`,
`838860799999999` → `838860800000000`,
`2660426260233305` → `2660426260233306`. Это ровно изменения upstream,
а не численный допуск в сравнении.

Все три задания независимо выполнены `ref/dubna_ref.exe` версии
`0.1.418-rebuild`. Их вывод совпал с закреплёнными expected после исключения
первой строки с реальными часами и четырёх строк статистики самого C++ CLI.
Такое исключение использовано только для дополнительной сверки C++:
CERN-тесты C# продолжают сравнивать весь детерминированный вывод.
Хеш исполняемого файла C++, хеши шести импортированных файлов и результат
сверки сохранены в [JSON](cernlib-golden-refresh.json).

## Изменение тестового раннера

В `examples/cernlib/lib2` закоммичены три полные пары `.f`/`expect_*.txt`.
Для каждого случая раннер сначала выбирает полную закоммиченную пару,
затем необязательный локальный корпус. Таким образом старый git-ignored
`ref/` не подменяет закреплённый эталон, а эти три проверки доступны в CI.
Заданный `BESM6_CERN_DATA` сохраняет высший приоритет.

Неполная пара не смешивается с файлами другой версии. Генерация трасс
использует тот же источник, что и запуск теста. Строгое сравнение сохранено:
нормализуются только CRLF/CR; символы, цифры, пробелы и управляющие коды
не игнорируются. Допусков, исключений и принудительного Pass не добавлено.

Проверены приоритет полной пары, отсутствие смешивания неполной пары,
переход к полному корпусу для других имён и авторитет явного каталога данных.
Изолированные проверки раннера: 18/18. Три исходных отказа: 3/3 прошли.
Полный прогон: **397 из 397 активных CERN-случаев прошли**.
Вся Integration-сборка: **426 passed, 0 failed, 3 skipped** из 429.
Пропущены прежние диагностические DumpAtDivergence/TraceAlgol и W303.
Счётчики и имена пропусков сохранены в JSON.

```powershell
dotnet test tests/Besm6.Integration.Tests/Besm6.Integration.Tests.csproj -c Release
```

Список активных случаев остаётся равным 397; `w303` сохраняет прежний пропуск
из-за эталонного бесконечного цикла. Исходный локальный `ref/` не изменялся.
Исполнительный путь машины не менялся, поэтому её замеры производительности
предыдущего этапа сохраняют свою область применимости.
