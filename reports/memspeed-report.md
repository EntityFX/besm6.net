# Гостевой тест памяти MemSpeed-style

Актуальная серия `092634f` сравнивает предыдущий max (`fbeb315`) и текущий
код последовательно в одной среде. По разности медиан RunLoaded с baseline:

| Ядро | Предыдущий max, МБ/с | Текущий max, МБ/с | Прирост |
|---|---:|---:|---:|
| `X = Y` | 35,809 | **39,006** | +8,9% |
| `X = X + Y` | 44,479 | **48,057** | +8,0% |
| `X = X + 0.5·Y` | 38,654 | **40,906** | +5,8% |

Модельные показатели и условия теста не изменились. Один прогрев и пять
измерений, все четыре варианта прошли проверки результата, регистров,
памяти, инструкций и тактов между сборками.
[Закоммиченные результаты и диапазоны](processor-tier1-results.json),
[полная локальная серия JSON/CSV](../tests-run/tier1-memspeed/results.json),
[итоговый отчёт](processor-optimization-report.md#итоговое-ускорение-оптимизированный-jit-для-общих-обработчиков).

Ниже сохранены первоначальная серия и подробная методика. Её времена
не используются для расчёта прироста актуальной серии.

В `max` получены 28,70 МБ/с для копирования, 33,97 МБ/с для сложения массивов
и 31,29 МБ/с для `X = X + S·Y`. Измеряется логический поток данных гостевой
БЭСМ-6 с 48-битными словами.

| Ядро | Модель, МБ/с | Хост, max, МБ/с | Разность времени RunLoaded с baseline, с |
|---|---:|---:|---:|
| `X = Y` | 5,214 | 28,704 | 1,712352 |
| `X = X + Y` | 6,916 | 33,971 | 2,170333 |
| `X = X + 0.5·Y` | 5,449 | 31,294 | 2,355974 |

Два массива по 4096 элементов занимают 49 152 гостевых байта (48 КиБ).
Каждое ядро выполняется 1000 раз. Одно слово содержит 6 гостевых байт;
копирование учитывает чтение и запись — 12 байт на элемент, два остальных
ядра — два чтения и запись, 18 байт. Всего учитывается 49 152 000 байт для
копирования и 73 728 000 для каждого арифметического ядра. МБ = 1 000 000 байт.
Выборка инструкций, временные значения и физический размер `Word48` на хосте
не входят в числитель. Эти показатели не являются пропускной способностью
физической памяти компьютера.

## Методика

Один прогревочный и пять последовательных Release-запусков с фиксированным
`DATE*`, без профиля, статистики и подписчиков в исполнительном цикле.
Отдельный Runtime probe загружает задание до секундомера и измеряет `RunLoaded`,
включая вход/выход и завершение буферизованного вывода. Затем снимаются
контрольное состояние и хеш памяти. Из медианы каждого ядра вычитается медиана
`kpart=0`, пропускающего рабочий цикл. Таким образом исключается общая часть
компиляции, инициализации, проверки и вывода; это оценка времени ядра по
разности запусков, а не измерение между внутренними маркерами гостевой программы.

Медианы RunLoaded: baseline 0,283405 с; копирование 1,995757 с;
сложение 2,453738 с; триада 2,639379 с. Модельные времена по разности
табличных тактов: 9,426527 / 10,659838 / 13,529497 с соответственно.
Задержки устройств и конвейер дополнительно не моделируются.

Это самостоятельная адаптация трёх ядер семейства MemSpeed для FORTRAN-GDR
и 48-битного REAL БЭСМ-6. Она не воспроизводит исходный PC-тест с его
типами float/double/int32. Описание семейства — у
[автора MemSpeed](https://roylongbottom.github.io/royRepository/).

## Проверка корректности

Гостевая программа проверяет все 4096 элементов относительно аналитического
эталона. Запускатель независимо проверяет первый и последний элементы,
контрольную сумму, объём данных, число проходов, отсутствие ошибочных элементов,
STOP и код возврата. Листинг компилятора исключён из проверки результата.
Аналитические суммы: baseline 4096; копирование 2048,5;
сложение 2 052 596; триада 1 028 346.

Во всех четырёх вариантах конечные регистры, SHA-256 всей памяти и число шагов
голого исполнения совпали с диагностической калибровкой. Все измеряемые
запуски прошли проверки. Вариант с неподдерживаемым компилятором IF/THEN был
отклонён при подготовке; окончательный исходник использует условные переходы
Fortran 66.

## Повторный запуск

```powershell
dotnet build src/Besm6.Cli/Besm6.Cli.csproj -c Release -t:Rebuild
python tools/benchmark_processor_stages.py --variant max=src/Besm6.Cli/bin/Release/net8.0/besm6.dll --jobs mem0 mem1 mem2 mem3 --runtime-probe --output tests-run/memspeed
```

Запускатель задаёт лимит 100 миллионов инструкций и отклоняет усечённые прогоны.
Рабочие варианты завершают примерно 55,5 / 63,7 / 67,8 миллиона инструкций;
при отдельном запуске исходника нужен соответствующий лимит.
