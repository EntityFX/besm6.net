# Продолжение оптимизации общего пути процессора

Исторический отчёт этапа `fbeb315`. Более поздняя контрольная серия и принятый
код `092634f` описаны в [итоговом отчёте JIT-оптимизации](processor-tier1-report.md).

Этот этап продолжает работу после `a6d801e`. Цель — подтвердить ускорение
машины минимум в три раза относительно кода до оптимизаций (`c0c7989`).
Изменения измерялись отдельно, затем выбранное сочетание сравнивается в одной
серии с первым кодом и предыдущим `max`. Ускорение отдельных этапов не
перемножается для получения итогового результата.

## Изменения

Подготовка следующего полуслова и завершение команды встроены JIT в общий
цикл. Небольшие общие обработчики `XTA`, `ATX`, `NTR`, `UTC`, `VTM`, `UTM`,
`UJ`, `VLM` и STOP также допускают встраивание. Остальные инструкции вызывают
общие обработчики семейств. Семантика каждой инструкции находится в одном
месте; оригинальный темп, диагностика и голый `max` используют эти обработчики.

Выборка команды из обычной `CoreMemory` допускает прямой вызов и встраивание
чтения. Выборка из пользовательской реализации или наследника `CoreMemory`
сохраняет вызов через `IMemory`. Исключение перехода по нулевому адресу вынесено
из горячего метода. Доступ к данным и watchpoints сохраняют прежний путь.
Чтение слова команды и проверка фактических битов кеша выполняются на каждом
полуслове, поэтому самомодифицирующийся код не требует уведомлений о записи.

## Изолированные измерения

Один прогрев и пять измерений, последовательные Release-процессы с чередованием
сборок; фиксированный DATE*, без диагностических подписчиков внутри измеряемого
RunLoaded. Калибровка проверяет конечные регистры, память, инструкции и модельные
такты; каждый голый запуск дополнительно сверяется с калибровкой.

В таблице — сокращение времени RunLoaded, проценты; отрицательные числа означают
замедление. Это разные серии с разным состоянием хоста. В частности, большой
выигрыш первой строки Dhrystone при выделении коротких обработчиков имеет
заметный разброс исходных запусков; итог нужно оценивать по общей серии.

## Проверки

Release-сборка решения: без предупреждений и ошибок. Основной .NET-набор:
748 тестов пройдено, 2 прежних диагностических пропуска. Добавлены проверки
побочных эффектов интерфейсной выборки у наследника CoreMemory и состояния
при ошибках выборки, с кешем и без него. Пройдены существующие проверки
самомодификации, watchpoints, округления, STOP, перехватов и повторного запуска.
Фиктивные часы проверяют прежнюю логику выдерживания темпа.
Дополнительные проверки покрывают изменение A/Y пользовательской памятью
для XTA/ATX/AEX/XTR и совпадение результатов ALU на обычной и пользовательской
памяти. CERN: 394/397, три прежних расхождения и сообщения совпали после
исключения elapsed; golden: 3/3. Проверенный Processor совпадает со снимком
контрольного CERN-прогона по SHA-256.

[Сравнение CERN](../tests-run/hot-path-final-runtime/cern-failure-comparison.json).

На DH10000 и MPMFLOPS-3 проверен оригинальный темп: один прогрев и пять
измерений каждого задания. Абсолютное отклонение от модели во всех измерениях
не больше 7,623 мс, ниже допуска `max(20 мс, 2%)`. Конечное состояние,
инструкции и такты совпали с max.
[Проверка темпа](../tests-run/hot-path-original-pacing/results.json).

## Профиль следующего шага

Нативный sampling-профиль собран на этой же DLL без гостевых профиля/статистики.
Собственная доля записанного времени основного потока:

| Метод | DH10000 | MPMFLOPS-3 |
|---|---:|---:|
| ExecuteUnobservedBlock | 55,33% | 46,33% |
| MemoryInstructionExecutor.ExecuteOther | 9,02% | 21,27% |
| AdditiveOperations.Add | 2,93% | 3,33% |
| MultiplicativeOperations.Multiply | 0,65% | 3,35% |

Доля самого цикла выросла после встраивания в него обработчиков; это не
замедление. Встроенные методы учитываются у вызывающего метода. Профиль
включает весь процесс и лишь статистически оценивает стоимость методов.

JIT-дизассемблирование подтверждает отсутствие отдельных вызовов Dispatch,
AdvanceInstructionHalf, FinalizeInstruction и обычной MemFetch внутри цикла;
общие обработчики прочих команд остаются вызовами. Размер кода цикла —
1801 байт. Прямая выборка CoreMemory встроена, интерфейсный вызов сохранён
в ветке пользовательской памяти.

Выявлена дополнительная проверка границ массива после проверки адреса
CoreMemory.Read: JIT не исключил её после вызова холодного ThrowAccessViolation.
Это конкретный следующий эксперимент наряду с арифметическими командами
в ExecuteOther. Изменение требуется подтвердить отдельно по коду JIT,
производительности и прежним ошибкам адресов/банков.
