# Этап 4: диспетчер и устройства

## Этап 4: функциональный супервизор и выбранные устройства

Срез: 10 октября 2026 года. Реальная задача ДИСПАК выполнена нашим CPU
в экспериментальной Simh512K, без hosted-экстракодов, подмены гостевых
регистров или исправления загрузочного образа. Original/max совпали
по итоговому состоянию и истории обмена. Функциональная приёмка этапа 4 и допуск скорости пройдены в выбранной области.

### Исполнение и память

Dubna остаётся профилем по умолчанию. Supervisor включается явно через API;
обычные команды и АУ используют общие обработчики. Добавлены специальные
регистры, режимы, входы/возвраты экстракодов и прерываний, признаки M17,
ЗпР/ЧтР, ОВУ, сравнение адресов и правила STOP. Внутренняя ошибка CPU
не начисляет тик и не превращается в hosted-авост. Завершённая команда
остаётся учтённой при последующей ошибке callback.

Прежняя Classical32K сохранена. Simh512K — отдельный экспериментальный
контракт закреплённого SIMH: 512 физических страниц, математические
адреса по-прежнему 15-разрядные, перевод через RP. Для него есть
независимые векторы расширенных полей, предельных адресов, защиты,
alias/remap, контроля и видимости БРЗ/БРС. Это не доказательство
исторической геометрии банков расширенной машины.

В Supervisor публикация старейшей записи при заполнении восьмого БРЗ
соответствует ТО-2, книга 2, §4.19–4.20. Прежний отдельный Mapped-контракт
сохранён. При DMA контроллеры используют физические raw50-слова,
обходят RP/RZ и CPU-буферы и не очищают БРС.

### Устройства и ОС

Выбранный функциональный комплект: два канала МБ/КМД, дисковые носители,
телеграфные линии, консоли, ФС1500 и АЦПУ. Обмен асинхронный,
через общий планировщик. Периоды обозначают логические тики, а не
аппаратные микросекунды. Ленты, карты, неизвестные форматы и невыбранные
варианты контроллеров не объявляются реализованными.

Bootstrap и носители закреплены по SHA256 и ревизиям в
[аудите источников](supervisor/supervisor-source-audit.json). Образы не включены в Git.
Собственный запуск сохраняет дату образа; время задаёт настоящая команда
оператора ВРЕ. Независимый SIMH также выполнил исходную задачу, но его
штатная автоматизация непосредственно исправляет YEAR — это различие
явно сохранено в [результате эталонного запуска](supervisor/supervisor-reference-job.json).

Гостевой Fortran напечатал девять ожидаемых значений:
9433, 19081, 29147, 39631, 50359, 61297, 72467, 83701, 95101.
Проверка использует только фактический вывод результата между заголовком
и временем, исключая листинг компилятора. Напечатан конец задачи;
следующая операторская команда получила ответ ОС.

При 180 миллионов разрешённых попыток выполнено 179999977 команд;
23 неуспешных шага не начислены. Диагностический запуск заканчивается
лимитом после выполнения задания, а не STOP ОС. Итоговый SHA состояния
`13741684af90f6f230be2394cb7a1940e67aa70464823bb8f1ade07dbee84a0c`
одинаков у обоих режимов. Хеш включает CPU, RP/RZ, raw50 физической
памяти, БРС/БРЗ, изменённые носители, часы, ближайшее событие и историю I/O.
[Проверки ОС-гейта](supervisor/supervisor-os-gate.json) сохранены отдельно.

### Проверки и производительность

Полный набор после изменения горячего пути: **2510 passed, 0 failed**,
только три прежних диагностических пропуска. **CERN397/397**,
сравнения не ослаблены. [Результаты тестов](supervisor/supervisor-tests.json)
содержат счётчики и SHA TRX, без заголовков с данными хоста.

RunInstructions использует общий pacing и ограничивает в Supervisor
также неуспешные попытки шага, предотвращая бесконечный цикл обработчика
ошибок. Снимаются только собственные подписки запуска; hooks,
установленные callback, сохраняются. Проверены повторный запуск,
нулевой UTC/WTC, STOP, ошибки, watchpoints и события на границах.

Измерения Release идут последовательно: один прогрев, пять измерений,
фиксированный DATE*, нулевые задания для baseline, RunLoaded и полный
CLI раздельно. Сохраняются все серии, включая не прошедшие допуск:
в предварительной серии MP2 имел +13,41%, CLI MP1 +6,82%; следующая
RunLoaded MP3 +5,21%, отдельные 15 измерений MP3 +5,06%.
Это не принятые результаты. После обнаружения проверки нулевого
модификатора в горячем Dubna-блоке её параметр сделан константой false
для этого пути; семантика супервизора и общие обработчики сохранены. Этот первый
эксперимент не принят: MP3 +5,57%. Затем дополнительное поле удалено
из ExecutionFrame, а нулевой модификатор определяется при завершении
обычного шага по профилю и opcode. В изолированной серии из 15
измерений MP3 получил +1,75%; итоговая регрессия RunLoaded не более 3.44%, полного CLI
не более 3.82% (для MP3 все 20 измерений). Допуск 5% пройден.
[Приёмка производительности](supervisor/supervisor-performance.json), исходные серии
JSON/CSV сохранены в каталоге `supervisor/` (объёмные «сырые» выводы тестов не хранятся в репозитории).
Golden3/3, Python66/66 подтверждены на итоговом коде.

Диагностический ОС-запуск итоговой сборки с hook каждой команды занял 65.69 с
в max и 65.30 с в original при модельных 35,15 с. Хост здесь не выдержал
темп; функциональный успех не объявляется приёмкой времени. Original
проверяется отдельно на свободном хосте без тяжёлой диагностики.

### Границы и следующий этап

Сохранены прежние алгоритмы деления, округления и R после hosted-экстракодов.
Известные расхождения АУ из этапа 2 остаются классифицированными;
готовность этапа 4 не означает полной точности исторической машины.
Аппаратное перекрытие, банковые задержки и запросы в полёте — этап 5.
Компиляция гостевых блоков/JIT остаётся за границами принятого плана.

Спецификация и API: [функциональный супервизор](../docs/besm6-commands.md).

Воспроизведение ОС-пары:

```powershell
python tools/stage4_boot_probe.py --output tests-run/stage4-boot-source --runtime-dll src/Besm6.Runtime/bin/Release/net8.0/Besm6.Runtime.dll --memory-configuration Simh512K --instruction-limit 180000000 --timer-period 10000 --serial-period 1000 --submit-job --light-probe --speed max --timeout 240
# Сохранить runtime-probe.json как os-max.json перед вторым запуском.
```

### 2. Матрица команд процессора (ISA БЭСМ-6)

*Легенда:*
- `- [x]` — Полностью реализовано и покрыто автоматическими тестами.
- `- [ ]` — Не реализовано (вызывает исключение `ProcessorException: Illegal instruction` или не поддерживается аппаратно).

#### 2.1. Короткий формат: арифметика, логика, пересылки (000–037 oct)
**Прогресс группы:** `[██████████████████░░]` 90.6% (29 / 32)

- [x] `000` **ЗП** (*Atx*) — Запись аккумулятора в память.
- [x] `001` **ЗПМ** (*Stx*) — Запись аккумулятора в память и извлечение операнда из стека (M[15]).
- [ ] `002` **РЕГ** (*Mod*) — Изменение привилегированных регистров режима (*Illegal instruction 002 рег/mod*).
- [x] `003` **СЧМ** (*Xts*) — Укладка аккумулятора в стек (M[15]) и чтение операнда в аккумулятор.
- [x] `004` **СЛ** (*APlusX*) — Сложение операнда с аккумулятором (плавающая запятая БЭСМ-6).
- [x] `005` **ВЧ** (*AMinusX*) — Вычитание операнда из аккумулятора.
- [x] `006` **ВЧОБ** (*XMinusA*) — Обратное вычитание (Операнд − Аккумулятор).
- [x] `007` **ВЧАБ** (*Amx*) — Вычитание модулей чисел.
- [x] `010` **СЧ** (*Xta*) — Чтение слова из памяти в аккумулятор.
- [x] `011` **И** (*Aax*) — Поразрядное логическое И (48 бит).
- [x] `012` **НТЖ** (*Aex*) — Поразрядное логическое исключающее ИЛИ / неравнозначность (48 бит).
- [x] `013` **СЛЦ** (*Arx*) — Циклическое сложение (в кольце 48 бит с учетом бита переноса).
- [x] `014` **ЗНАК** (*Avx*) — Умножение знака операнда на знак аккумулятора (41-й бит).
- [x] `015` **ИЛИ** (*Aox*) — Поразрядное логическое ИЛИ (48 бит).

#### 2.2. Короткий формат: работа с индексными регистрами (040–047 oct)
**Прогресс группы:** `[███████████████░░░░░]` 75.0% (6 / 8)

- [x] `040` **УИ** (*Ati*) — Пересылка младших 15 бит аккумулятора в индексный регистр `M[addr + M[reg]]`.
- [x] `041` **УИМ** (*Sti*) — Запись младших разрядов A в индекс-регистр и извлечение из стека в A.
- [x] `042` **СЧИ** (*Ita*) — Чтение индекс-регистра `M[addr + M[reg]]` в аккумулятор с переходом в логический режим.
- [x] `043` **СЧИМ** (*Its*) — Запись аккумулятора в стек ОЗУ (M[15]) и чтение индекс-регистра в A.
- [x] `044` **УИИ** (*Mtj*) — Пересылка значения одного индекс-регистра в другой (`M[addr] = M[reg]`).
- [x] `045` **СЛИ** (*JPlusM*) — Сложение индексных регистров (`M[addr] = (M[addr] + M[reg]) mod 32768`).
- [ ] `046` **СОП** (*Op46*) — Специальное обращение к памяти (*Illegal instruction 046 соп*).
- [ ] `047` **Э47** (*Op47*) — Зарезервированная неиспользуемая инструкция (*Illegal instruction 047*).
