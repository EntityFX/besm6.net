# CPU и календарные передачи памяти

CPU резервирует общий запрос до возврата командного слова из БРС/MRAM.
Декодирование, trace и watchpoints используют прежний процессор; приём происходит
на границе календаря, а не через повторную выборку backend.
Приём арифметического операнда использует неизменяемое слово передачи.
Общие обработчики формируют адрес/стек и выполняют ПВР с прежними проверками,
A/Y, округлением и модификацией. Функциональные чтения не проверяют новый
флаг передачи на каждой инструкции.

Гостевая смена РП уведомляет об устаревших чтениях, сохраняя прежнее требование
публикации БРЗ самой программой. Сброс, загрузчик и явная отмена не публикуют
устаревшую команду. Ошибка trace-hook при приёме —HostFailure вне callback
с освобождённым запросом; guest-control fault получает прежний гостевой вектор.

25 новых случаев: STOP, обе половины всех14 арифметических операций памяти,
принятый операнд при изменении MRAM после начала цикла, reset/загрузчик,
контроль слова, РП, явная отмена, исключение hook и ошибки аппаратных watchpoints.
Предварительные серии 3031 и 3033/CERN397 сохранены локально.
Затем исправлена доставка ошибок допуска памяти: аппаратный watchpoint
проходит общую гостевую границу CPU; добавлено сравнение со Step, включая стек.
Окончательная сборка:3036 тестов, CERN397/397, golden3/3; три прежних пропуска.
Первая серия сохранена локально и не подменяет проверку окончательной сборки.

Основные задания dh5000/dh10000/mp1/mp2/mp3: худшая регрессия RunLoaded
1.837%, CLI 1.757%; допуск5%. Максимальная ошибка original 5.813 мс.
Release: один прогрев, пять последовательных измерений, fixedDATE*, baseline,
раздельные RunLoaded/CLI. Все серии сохранены; исходный вывод локальный с SHA256.

Это подключение выборки и принятого арифметического операнда, а не завершённый
сквозной аппаратный драйвер. Неарифметические обращения к данным, автоматическое
завершение всех команд, входной контроль АУ сырых50 бит, адресуемые БРЧ и
устройства ещё требуют интеграции. Аппаратный запуск ОС этим корпусом не доказан.
