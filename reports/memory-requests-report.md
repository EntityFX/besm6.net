# Этап 3: запрос памяти и координация приписки

После переименования компонентов добавлен отдельный блок:

- `MemoryRequestAddress`: 15-битный адрес и физический признак разряда 16.
- `PageAssignment.TranslateRequest`: перевод по текущей приписке на границе
  запроса, с обходом замены для физического адреса.
- `MemoryMappingController`: проверка изменения, публикация отложенных
  физических записей БРЗ, затем обновление страницы или группы РП.

Источники, номера печатных листов и границы контракта закреплены в
[спецификации](../docs/besm6-memory-requests.md). Проверены обе части
скана УУ редакции 1–65 и правило смены приписки в ТО-8 редакции 1–67.
Различия описания очередности не объединены в предполагаемую конфигурацию.

Новый код не подключён к CPU. Тип запроса не объявляется доказательством
ключей сравнения всех БАЗ/БАС. Хостовый контроллер работает с уже выбранными
физическими адресами действующих буферов; он не выполняет ЗпР и не моделирует
завершение команд в АУ. Отдельный аппаратный профиль по-прежнему отсутствует.

## Проверки

10 новых случаев, в том числе исчерпывающий перебор всех 32768 адресов
для обоих состояний физического признака. Проверены поздний перевод после
смены таблицы, сохранение младших десяти битов, независимость трансляции
от проверки допуска, публикация в прежнюю физическую ячейку, сохранение БРС
и порядка буферов, отсутствие повторной публикации чистых копий и полный
отказ без побочных эффектов для неверного изменения приписки.

Release: **2198 passed, 0 failed, 3 прежних пропуска**. CERN: **397/397**
активных случаев в профиле Dubna. Golden: **3/3**, прежние счётчики инструкций.
Новый компонент не претендует на прохождение CERN как аппаратный профиль.
Тесты и эталоны не ослаблены.

```powershell
dotnet test Besm6.sln -c Release --no-restore --logger 'trx;LogFileName=stage3-memory-requests.trx'
python tools/run_all_examples.py --dll src/Besm6.Cli/bin/Release/net8.0/besm6.dll --suite fast --only algol,bemsh,name --limit 20000000 --timeout 120 --output tests-run/stage3-memory-requests-golden
```

Производительность не перемерялась: новые API не вызываются на активном
пути CPU. Источники выборки, исполнения, буферов и RunLoaded совпадают
с 3407eb2 после нормализации переводов строк; хеши сохранены в
[JSON](memory-requests-results.json). Предыдущие измерения сохранены
отдельно, новый прирост скорости не заявляется.

[CSV](memory-requests-results.csv) содержит результаты по наборам.
Отчёты обезличены; полные TRX остаются в игнорируемых каталогах.
