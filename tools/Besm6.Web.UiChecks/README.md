# Проверка веб-консоли в браузере

Запускайте команды из корня репозитория. Нужны .NET 8+ и Chromium для Playwright.

В одном терминале запустите локальное приложение:

```powershell
dotnet run --project src/Besm6.AspNetCore.Web -c Release --urls http://127.0.0.1:5186
```

В другом установите браузер и выполните проверки:

```powershell
dotnet build tools/Besm6.Web.UiChecks
dotnet build src/Besm6.Cli -c Release
pwsh tools/Besm6.Web.UiChecks/bin/Debug/net8.0/playwright.ps1 install chromium
$env:BESM6_WEB_BUILD_CONFIGURATION = 'Release'
dotnet run --project tools/Besm6.Web.UiChecks
```

Проверяются загрузка `.dub` через выбор файла и drag & drop, границы размера файла, отладка, пауза и остановка, полный запуск, восстановление соединения, независимость нескольких машин, параллельные исходные программы, Guest Clock, обновления памяти и регистров, плоттеры, терминал, перфокарты и накопители. Проверка вёрстки использует шесть ширин от 320 до 1440 пикселей. Проверка доступности использует axe-core 4.10.3, который загружается в каталог результатов при первом запуске.

Реальные задания `examples/grafor/{watanabe,calcomp,tektronix,cardioide}.dub` проверяются до получения линий на canvas. `examples/libpunch.dub` проверяется до получения перфокарт: размеры строк, наличие отверстий и совпадение с `punch.out`. Отдельные сценарии проверяют переключение автообновления во время выполнения и поступление вывода плоттера и перфоратора с отключённым обновлением регистров и памяти.

Дополнительно проверяются Statistics, Reset, все три системы счисления с 48-битными значениями, равная ширина 256 символов Braille, просмотр и выполнение встроенных примеров. Генератор сравнивается с runtime-кодеком, проверяются ручная пробивка, нечётность, физическая геометрия SVG, PNG 4425 × 1950 и метаданные 600 dpi.

Сценарии `source-editor`, `terminal-input`, `punch-formats`, `media-mount-and-disassembly` проверяют подсветку без интерпретации HTML, правку и запуск текста, ожидание и отмену ввода, доставку через терминал и телетайп, четыре представления реальных перфокарт, гостевое чтение `*70` со смонтированного образа, дизассемблирование, копирование в память и независимость образов в разных машинах. Доступность проверяется во всех новых вкладках.

`cli-performance-parity` запускает одинаковые задания в CLI и вебе, сопоставляет число инструкций и модельные циклы, сохраняет времена в `cli-performance-parity.json`. Веб и CLI должны быть собраны в одной конфигурации; укажите её в `BESM6_WEB_BUILD_CONFIGURATION` (по умолчанию Debug). Это диагностический замер; время зависит от JIT, прогрева и загрузки компьютера.

`machine-models-and-registers` проверяет буферную память и оба режима supervisor, шаги, полный запуск и реальные БРЧ аппаратной модели. `memory-decode` проверяет переключение расшифровки без изменения слов памяти. `instruction-codec` проверяет три синтаксиса, ограничения адресов, точность 48 бит, ручное переключение битов и сохранение соседней половины слова. Вкладка Instructions включена в проверки доступности и адаптивной вёрстки.

`dhrystone-modes` выбирает готовые JSON из Examples: Maximum, Original, Virtual и Debug/Resume. Проверяются реальные результаты 5000 проходов после листинга компилятора, все 18 числовых и 4 строковых контроля, гостевой DMIPS, число инструкций и модельные циклы. Дополнительные запуски Maximum включают Auto-refresh и Decode. Три запуска Maximum сравниваются с тремя CLI той же сборки: сохраняются времена, медианы и отношение в `dhrystone-modes.json`. Диагностический порог замедления веба — 15% плюс 150 мс; сравнение следует выполнять без параллельных сборок и тестов. Hosted-буферный режим должен успешно завершить то же задание с теми же инструкциями и циклами. Отдельный `dhrystone-buffered` проверяет готовый JSON buffered без повтора остальных замеров.

`json-machine-examples` выполняет оба самостоятельных образа supervisor. `supervisor-default-template` проверяет выбор Supervisor в пустой сессии и полный запуск одним нажатием Run, с автоматической загрузкой подходящего образа. `json-preset-upload` проверяет выбор настроек из файла и текста, сохранение исходного задания и отсутствие запуска при загрузке.

Результаты, вывод программ и скриншоты сохраняются в `tests-run/web-ui-checks/`. При ошибке программа возвращает ненулевой код. Приложение и проверки должны работать на одной машине, поскольку проверяется также изоляция и очистка временных каталогов сессий.

Для другого локального порта задайте `BESM6_WEB_URL`. Можно выполнить отдельные сценарии:

```powershell
dotnet run --project tools/Besm6.Web.UiChecks -- multiple-sessions running-session-isolation live-updates-full live-updates-debug
```
