# БЭСМ-6: восемь примеров для презентации

Порядок: арифметика → логика → ветвление → индексные регистры → массивы →
циклы → функции → устройства. В каждом примере показаны начальные данные,
исполняемые команды и ожидаемый результат.

## Как читать примеры

- `A` — 48-разрядный аккумулятор; `M1`, `M2` — 15-разрядные индексные регистры.
- Формат команды: `метка: индекс,операция,адрес`. Пустое поле индекса обычно
  означает отсутствие индексирования.
- `REAL` размещает вещественную константу, `LOG` — битовое слово в восьмеричной
  записи. Это **директивы транслятора**, а не действия процессора.
- Начальные слова данных попадают в память при загрузке программы.
  `RESULT:,REAL,0.` явно инициализирует результат нулём. В отличие от этого,
  `BSS,1` только резервирует слово: начальное значение нельзя считать заданным.
- `VTM` и `XTA` — уже исполняемые команды: они инициализируют регистры во время
  работы. `NTR,0` разрешает нормализацию и округление; следующие операции
  устанавливают признаки своей группы.
- Числа в обычных адресных выражениях десятичные. Числа в `LOG` восьмеричные.
  Например, `LOG,12` — двоичный код `1010`, а не вещественное число 12.
- В полных `.dub`-файлах данные стоят после команд завершения. Порядок блоков
  ниже выбран для объяснения: **не запускайте исполнение с директив данных**.
- Кодовые блоки взяты из соответствующих `.dub`-файлов. Для запуска используйте
  полный файл: в нём добавлены оформление задания, самопроверка и вывод `OK`/`FAIL`.

## 1. Арифметика

**Задача:** `RESULT = X + Y`, то есть `2.0 + 3.0 = 5.0`.

### Инициализация данных

```text
 X:       ,REAL,2.
 Y:       ,REAL,3.
 RESULT:  ,REAL,0.
```

### Команды

```text
          ,NTR,0
          ,XTA,X
          ,A+X,Y
          ,ATX,RESULT
```

| Шаг | Что делает процессор | A после команды |
|---|---|---:|
| `XTA,X` | Читает содержимое X | 2.0 |
| `A+X,Y` | Прибавляет содержимое Y | 5.0 |
| `ATX,RESULT` | Записывает A в RESULT | 5.0 |

**Для выступления:** «Первое число загружается в аккумулятор. Второе приходит
из памяти как операнд сложения. Результат остаётся в аккумуляторе, затем
сохраняется в памяти. ATX не очищает A».

[Полное задание](01-arithmetic.dub). Самопроверка читает записанный `RESULT`
и сравнивает с точно представимым числом 5.0.

## 2. Логика

**Задача:** применить битовую маску: `1010 AND 1100 = 1000`.
Показаны младшие четыре бита; старшие биты равны нулю.

### Инициализация данных

```text
 FLAGS:   ,LOG,12
 MASK:    ,LOG,14
 RESULT:  ,LOG,0
```

| Восьмеричная запись в LOG | Двоичный код | Смысл |
|---|---|---|
| `12` | `1010` | Исходные признаки |
| `14` | `1100` | Маска |
| Ожидаемое `10` | `1000` | Результат |

### Команды

```text
          ,NTR,0
          ,XTA,FLAGS
          ,AAX,MASK
          ,ATX,RESULT
```

**Для выступления:** «AAX оставляет единицу только в тех позициях, где единицы
были и в исходном слове, и в маске. Это операция над битами, а не сложение
вещественных чисел. Так можно выделять признаки состояния».

[Полное задание](02-logic.dub). Проверяется записанный код `0000000000000010`
в восьмеричной записи.

## 3. Ветвление

**Задача:** выбрать большее число: `RESULT = max(X, Y)`.

### Инициализация данных

```text
 X:       ,REAL,7.
 Y:       ,REAL,3.
 RESULT:  ,REAL,0.
```

### Команды

```text
          ,NTR,0
          ,XTA,X
          ,A-X,Y
          ,U1A,LESS
          ,XTA,X
          ,UJ,SAVE
 LESS:    ,XTA,Y
 SAVE:    ,ATX,RESULT
```

| Условие | Путь программы | Результат |
|---|---|---|
| X = 7, Y = 3 | Разность положительна; выбирается X | 7.0 |
| X = 3, Y = 7 | Разность отрицательна; переход на LESS | 7.0 |
| X = 7, Y = 7 | Разность нулевая; выбирается X | 7.0 |

**Для выступления:** «После вычитания U1A проверяет знак результата.
Отрицательная разность означает X < Y. Затем выбранное число загружается
заново: само вычитание оставило в A разность, а не максимум».

Именно **после A-X** здесь проверяется отрицательная мантисса. В логической
группе U1A имеет другой смысл — ненулевой битовый код.

[Полное задание](03-branches.dub). Дополнительные запуски меняют исходные
числа местами, делают их равными и проверяют пару отрицательных чисел.

## 4. Индексные регистры

**Задача:** прочитать два соседних слова через адрес в M1.

### Инициализация данных

```text
 DATA:    ,REAL,10.
          ,REAL,20.
 FIRST:   ,REAL,0.
 SECOND:  ,REAL,0.
```

### Команды, включая инициализацию M1

```text
          ,NTR,0
         1,VTM,DATA
         1,XTA,
          ,ATX,FIRST
         1,UTM,1
         1,XTA,
          ,ATX,SECOND
```

| Команда | Действие |
|---|---|
| `1,VTM,DATA` | M1 получает **адрес** DATA, а не число 10 |
| `1,XTA,` | A получает слово по адресу M1: 10.0 |
| `ATX,FIRST` | FIRST = 10.0 |
| `1,UTM,1` | M1 указывает на следующее слово |
| `1,XTA,` | A получает следующее число: 20.0 |
| `ATX,SECOND` | SECOND = 20.0 |

**Для выступления:** «Адрес и значение — разные вещи. M1 указывает, где лежит
число; XTA получает само число. Прибавление единицы к адресу переводит нас
к следующему 48-разрядному слову».

Вместо произвольного абсолютного адреса 1000 используется метка DATA:
фактическое размещение определяет загрузчик, и код не портит чужую память.

[Полное задание](04-index-registers.dub). Проверяются обе сохранённые величины.

## 5. Работа с массивами

**Задача:** удвоить третий элемент: `[10,20,30,40] → [10,20,60,40]`.

### Инициализация данных

```text
 ARRAY:   ,REAL,10.
          ,REAL,20.
          ,REAL,30.
          ,REAL,40.
 SCALE:   ,REAL,2.
```

### Команды

```text
          ,NTR,0
         1,VTM,2
         1,XTA,ARRAY
          ,A*X,SCALE
         1,ATX,ARRAY
```

**По шагам:** M1 = 2 → адрес ARRAY+2 → A = 30.0 → A = 60.0 → запись в ARRAY+2.

**Для выступления:** «Массив — соседние слова памяти. Здесь M1 содержит
смещение, а начало ARRAY задано в команде. У третьего элемента смещение 2,
потому что первый находится по смещению 0. Чтение и запись используют один адрес».

[Полное задание](05-arrays.dub). Проверяются **все четыре элемента**:
измениться должен только третий.

## 6. Циклы

**Задача:** сложить три элемента: `10.0 + 20.0 + 30.0 = 60.0`.

### Инициализация данных и константы длины

```text
 COUNT:   ,EQU,3
 ZERO:    ,REAL,0.
 ARRAY:   ,REAL,10.
          ,REAL,20.
          ,REAL,30.
 SUM:     ,REAL,0.
```

`EQU,3` задаёт константу времени трансляции: COUNT означает число 3,
а не адрес ячейки с числом 3. Никакого чтения длины из памяти здесь нет.

### Команды

```text
          ,NTR,0
         1,VTM,0
         2,VTM,COUNT
          ,XTA,ZERO
 LOOP:   2,VZM,DONE
         1,A+X,ARRAY
         1,UTM,1
         2,UTM,-1
          ,UJ,LOOP
 DONE:    ,ATX,SUM
```

| После прохода | M1 — следующий индекс | M2 — осталось | A — сумма |
|---:|---:|---:|---:|
| Начальная установка | 0 | 3 | 0.0 |
| 1 | 1 | 2 | 10.0 |
| 2 | 2 | 1 | 30.0 |
| 3 | 3 | 0 | 60.0 |

**Для выступления:** «A накапливает сумму, M1 выбирает элемент, M2 хранит
остаток. VZM проверяет счётчик до чтения массива. Поэтому нулевая длина
не приводит к лишнему чтению, а длина один даёт ровно один проход».

[Полное задание](06-loops.dub). Проверяются SUM и конечные значения M1/M2;
отдельно запускаются длины 0 и 1. Здесь намеренно используется прозрачный
цикл VZM/UTM/UJ, а не более необычная по семантике VLM.

## 7. Вызов функций

**Задача:** вызвать `TWICE(3.0)` и получить 6.0.

### Инициализация данных

```text
 ARG:     ,REAL,3.
 FACTOR:  ,REAL,2.
 RESULT:  ,REAL,0.
```

### Вызывающий код

```text
          ,NTR,0
          ,XTA,ARG
        13,VJM,TWICE
          ,ATX,RESULT
```

### Подпрограмма

```text
 TWICE:   ,A*X,FACTOR
        13,UJ,
```

**Для выступления:** «Аргумент 3 приходит в A. VJM сохраняет адрес продолжения
в M13 и переходит на TWICE. Подпрограмма получает 6 в A, а UJ через M13
возвращает нас к записи результата».

Это учебное соглашение: A — аргумент и результат, M13 — адрес возврата.
VJM не сохраняет все регистры и не создаёт стековый кадр. Вложенный вызов
через тот же регистр требует сохранения старого адреса. Возврат ведёт
на левую команду следующего слова; MADLEN обеспечивает размещение продолжения.

[Полное задание](07-functions.dub). Отдельно проверяются аргументы 0 и −3.

## 8. Работа с устройствами: печать вычисленного числа

**Задача:** вычислить `20.0 + 40.0` и передать результат сервису печати.
Печатается содержимое RESULT, а не заранее подготовленная строка «60».

### Инициализация данных

```text
 X:       ,REAL,20.
 Y:       ,REAL,40.
 RESULT:  ,REAL,0.
```

### Команды

```text
          ,NTR,0
          ,XTA,X
          ,A+X,Y
          ,ATX,RESULT
          ,*64,HEADINFO
          ,*64,VALINFO
```

### Инициализация текста и управляющих слов печати

```text
 HEADINFO:,    ,TEXT
          ,    ,TEXT
          ,001,
         8,    ,
 TEXT:    ,GOST,6HRESULT
          ,GOST,6H'231'
 VALINFO: ,    ,RESULT
          ,    ,RESULT
         3,    ,10
         8,024,
```

Эти строки задают **данные**, а не выполняемые команды:

- HEADINFO указывает область текста и формат GOST; TEXT содержит заголовок.
- `GOST,6H'231'` — управляющая последовательность завершения текстового вывода.
- Первое слово VALINFO содержит адреса области числовых данных: RESULT.
- Следующее слово выбирает вещественный формат: код формата 3, параметр digits 10,
  поле ширины 20 и признак окончания списка. Каждые две строки записи полуслов
  образуют одно 48-разрядное управляющее слово.

**Число выводится в научном формате экстракода**, не в формате Фортрана F5.1.
Мантисса `600000` с порядком `+02` означает `0.600000 × 10² = 60.0`.

Фактический вывод при проверке:

```text
RESULT
+600000?+02
OK 08
```

Знак порядка в текущей консольной кодировке заменяется на `?`.
Это не знак ошибки вычисления; проверяются мантисса и порядок напечатанного числа.

**Для выступления:** «Экстракод получает описание вывода. Он читает результат
из памяти, преобразует его в печатное представление и передаёт системе вывода.
Для текста и вещественного числа используются разные описания».

**Граница проверки:** запуск `.dub` проверяет интерфейс *64 в hosted-runtime.
Он не доказывает физическую печать на АЦПУ, гостевой драйвер, прерывание
контроллера или полную аппаратную модель устройства.

[Полное задание](08-devices.dub). Проверяются и вычисленный RESULT, и реально
выведенная числовая строка.

## Запуск и проверка

Из корня репозитория:

```powershell
dotnet build src/Besm6.Cli/Besm6.Cli.csproj -c Release --no-restore
dotnet src/Besm6.Cli/bin/Release/net8.0/besm6.dll run examples/presentation-madlen/01-arithmetic.dub --speed max --stats --guest-clock --no-wall-clock
python tools/verify_madlen_presentation.py
```

Сценарий проверяет восемь заданий в max и original, граничные случаи,
отрицательные контроли самопроверок и пять ранее существовавших learning-примеров.
Учитывается только отдельная строка `OK nn` **после *EXECUTE**, а не наличие
этого текста в листинге транслятора. Требуются также завершение по STOP
и статистика реально выполненных команд.

Успешный код завершения CLI недостаточен: гостевая программа может напечатать
FAIL и штатно закончиться. Поэтому отрицательные контроли подставляют неверное
ожидаемое значение и должны получить FAIL, а не OK.

**Проверено 21.11.2026: 43 запуска прошли**, включая восемь намеренно ошибочных
ожиданий, которые правильно дали FAIL. Все восемь основных примеров прошли
в обоих режимах. Все 18 блоков кода и данных выше совпадают с файлами заданий.
