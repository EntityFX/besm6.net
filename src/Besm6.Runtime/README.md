# Besm6.Runtime

Исходники сгруппированы по ответственности внутри одной DLL.
Исполнители зависят от функционального и подготовленного протоколов Processor,
а не от конкретного класса CPU. `MachineCore` создаёт общий CPU и передаёт его
роли владельцам исполнения. Тики функциональной модели и наносекунды аппаратной
модели продвигаются независимо; координатор управляет внутренними запретами
вложенного исполнения.

| Папка | Назначение |
|---|---|
| `Configuration/` | настройки и выбор модели |
| `Devices/` | устройства и контроллер обмена |
| `Diagnostics/` | трассировка, снимки и watchpoints |
| `Encoding/` | кодировки и COSY |
| `Execution/` | исполнение команд и управление функциональной симуляцией |
| `Extracodes/` | гостевые услуги Dubna |
| `Loading/` | загрузка и запуск |
| `Machine/` | сборка единой машины и шина |
| `Properties/` | метаданные сборки |
| `Storage/` | образы носителей |
| `Timing/Arithmetic/` | модель стадий и времени АУ |
| `Timing/Arithmetic/Division/` | опережающий контроль и стадии деления |
| `Timing/Calendar/` | наносекундный календарь и занятость ресурсов |
| `Timing/Memory/` | временные границы MRAM |
| `Timing/Specifications/` | книжная спецификация времени |
| `Modeling/` | аппаратный владелец исполнения общего CPU |
| `Profiling/` | профиль команд и совместимая таблица тактов |

`ExtracodeHandler` сохраняет входной ABI и диспетчеризацию гостевых кодов.
Состояние числового парсера, печати и хранения принадлежит отдельным сервисам;
они получают роли регистров, памяти и нужные устройства, а не `MachineCore`.
Терминал явно завершает накопленную печать до ввода/вывода. Политика часов,
обнаружение зависания и файловая трассировка независимы от этих сервисов.

`MachineCore` выбирает роли памяти при сборке: `Memory`/`SystemBus` —
`IHostMemory`, CPU — `IOperandMemory`, hosted CTX — `CommandMemory`.
Шина не подменяет публикацию команды обычной записью. Runtime открывает
внутренние типы только Runtime.Tests и Integration.Tests; CLI использует
публичный парсер `ExecutionSpeedNames.TryParse`.
