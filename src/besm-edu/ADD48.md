# Пример: сложение двух 48-битных чисел в БЭСМ-6

Образовательный пример для учебного симулятора `Besm6.EduCpu`. Показывает, как
выполняется сложение 48-битного машинного слова побитно с переносом, что
происходит при переполнении 48 разрядов и как программа на самой машине
выполняет сложение по схеме «СЧ → СЛЦ → ЗП». Все числа — в восьмеричной
системе счисления (как в выводах симулятора и в отладочных выводах БЭСМ-6).

Полезно читать вместе с [`ARCHITECTURE.md`](ARCHITECTURE.md).

---

## 1. Слово и схема сложения

- Информационное слово БЭСМ-6 — **48 бит** = **16 восьмеричных цифр**.
  Младшая цифра восьмеричной записи соответствует младшим трём битам (0–2).
- Сложение выполняется **от младшего бита (разряд 0) к старшему (разряд 47)**.
  На каждом разряде суммируются два бита слагаемых и перенос из предыдущего
  разряда:

  ```text
  перенос i = 1, если bitA_i + bitB_i + carry_in >= 2
  bitSum_i  = (bitA_i + bitB_i + carry_in) mod 2
  ```

- Перенос из старшего разряда (в «49-й бит») — это переполнение:
  - в **модульном** сложении (по модулю 2^48) — он отбрасывается;
  - в **циклическом** сложении (СЛЦ, модель `Word48.CyclicAdd`) — прибавляется
    обратно к младшему биту (циклический перенос).
  Это единственное отличие двух схем; без переполнения результат одинаков.

> Историческая поправка: на реальном БЭСМ-6 «СЛЦ» (циклический сдвиг)
> участвовал в сложении **реальных** чисел с плавающей точкой (нормализация).
> Здесь — упрощённая учебная модель: «СЛЦ» = циклическое сложение целых слов.

## 2. Пример 1. 5 + 7 = 14 (восьмерично)

Восьмерично (16 цифр):

```text
   0000000000000005   (5)
 + 0000000000000007   (7)
 ---------------------
 = 0000000000000014   (14)
```

Старшие 44 бита обоих слагаемых равны нулю, поэтому достаточно разобрать
младшие 4 бита. В двоичном виде:

```text
    A:           0 1 0 1        (5)
  + B:           0 1 1 1        (7)
    переносы:      1 1
    ---------------------
    S:           1 1 1 0        (14)
```

Разряд за разрядом (справа налево):

| Разряд | bitA | bitB | Перенос в | Сумма (битA+битB+перенос) | Бит суммы | Перенос из |
|-------:|:----:|:----:|:---------:|:-------------------------:|:---------:|:----------:|
| 0 | 1 | 1 | 0 | 2 | **0** | 1 |
| 1 | 0 | 1 | 1 | 2 | **0** | 1 |
| 2 | 1 | 1 | 1 | 3 | **1** | 1 |
| 3 | 0 | 0 | 1 | 1 | **1** | 0 |

Чтение результата от старшего разряда: `1 1 1 0` = `14` в восьмеричной системе
(12 в десятичной). Переноса за разряд 3 нет — переполнения 48-битного слова
не случилось.

## 3. Пример 2. Цепочка переноса: 7 + 1 = 10

Классический «бегущий перенос» — каждый разряд «выдаёт» единицу дальше:

```text
  A:  1 1 1      (7)
+ B:  0 0 1      (1)
  ----------------
  S:  1 0 0 0    (10)
```

| Разряд | bitA | bitB | Перенос в | Бит суммы | Перенос из |
|-------:|:----:|:----:|:---------:|:---------:|:----------:|
| 0 | 1 | 1 | 0 | 0 | 1 |
| 1 | 1 | 0 | 1 | 0 | 1 |
| 2 | 1 | 0 | 1 | 0 | 1 |
| 3 | 0 | 0 | 1 | 1 | 0 |

Перенос прошёл три разряда подряд (0 → 1 → 2 → 3) и остановился на первом
нулевом бите. Именно длина такой цепочки переноса на реальном железе
определяет время сложения устройства.

## 4. Пример 3. Переполнение 48 разрядов

Складываем максимальное слово и единицу — перенос проходит **все 48 разрядов**:

```text
   7777777777777777   (2^48 - 1)
 + 0000000000000001
 ---------------------
```

- **Модульное** сложение (перенос из 49-го бита отбрасывается):

  ```text
  = 0000000000000000
  ```

- **Циклическое** сложение СЛЦ (перенос складывается в младший бит):

  ```text
  = 0000000000000001
  ```

  то есть `(2^48 - 1) + 1 ≡ 1 (циклически)`, а не `0`.
  Аналогично `(2^48 - 1) + 2 = 2` и `(2^48 - 1) + (2^48 - 1) = 2^48 - 1`.

В модели `Word48.CyclicAdd` это реализовано явно: сначала обычная сумма двух
слов, затем к младшему биту добавляется бит 48 (перенос) и результат
маскируется обратно в 48 бит.

## 5. Сложение в программе машины (СЧ → СЛЦ → ЗП)

Демонстрационная программа `DemoProgram` делает ровно это:
снимает число в аккумулятор (**СЧ**, `xta`), прибавляет к нему другое
(**СЛЦ**, `arx`) и кладёт результат в память (**ЗП**, `atx`).

Состояние памяти до исполнения (восьмеричные адреса):

```text
АДР.   СОДЕРЖИМОЕ        РОЛЬ
0100   0000000000000003  неиспользуемые данные
0101   0000000000000005  первое слагаемое  (5)
0102   0000000000000007  второе слагаемое (7)
0110   0000000000000000  ячейка результата (0)
```

Фрагмент программы (половины слова L/R) с комментариями:

```text
000010L  vtm 000001(01)   УИА: M01 = 1      (для СЧ: адрес = 0100 + 0001 = 0101)
000010R  xta 000100(01)   СЧ:  ACC = mem[0101]   (там лежит 5)
000011L  arx 000102       СЛЦ: ACC += mem[0102]  (5 + 7 = 14)
000011R  atx 000110       ЗП:  mem[0110] = ACC   (14)
```

Трасса симулятора для этих четырёх шагов (подлинный вывод программы):

```text
ШАГ    АДРЕС   КОМАНДА           АДР.ИСП    ACC ДО           -> ACC ПОСЛЕ         ДАЛЬШЕ   ЭФФЕКТ
1      000010L  vtm 000001(01)    eff ----   0000000000000000 -> 0000000000000000  000010R  УИА: M01 = 000001
2      000010R  xta 000100(01)    eff 000101  0000000000000000 -> 0000000000000005  000011L  СЧ: ACC = mem[000101]
3      000011L  arx 000102        eff 000102  0000000000000005 -> 0000000000000014  000011R  СЛЦ: ACC += mem[000102] (циклический перенос)
4      000011R  atx 000110        eff 000110  0000000000000014 -> 0000000000000014  000012L  ЗП: mem[000110] = ACC
```

Шаг 3 — это и есть сложение из разделов 2–4: ACC содержал `…0005`,
в ячейке `0102` лежало `…0007`, побитная сумма с переносом дала `…0014`,
старшие 44 бита не изменились.

Дамп памяти после выполнения подтверждает результат:

```text
dotnet run --project src/besm-edu/Besm6.EduCpu -- --dump 0100 0110
...
ДАМП ПАМЯТИ
000100  0000000000000003
000101  0000000000000005
000102  0000000000000007
...
000110  0000000000000014
```

## 6. Где это в коде и как проверить

| Что | Где |
|-----|-----|
| Сложение 48-битных слов (циклическое) | `Besm6.EduCpu/Word48.cs` → `CyclicAdd` |
| Команда «СЛЦ» (`arx`) | `Besm6.EduCpu/Cpu.cs` → `Execute`, оператор `Op.Arx` |
| Тест: сумма без переноса (3 + 5 = 8) | `Word48Tests.CyclicAdd_WithoutCarry_IsSum` |
| Тест: перенос из 49-го бита (max + 1 = 1, max + 2 = 2) | `Word48Tests.CyclicAdd_CarryFoldsIntoLowBit` |
| Тест: СЧ + СЛЦ с циклическим переносом | `CpuTests.Arx_CyclicCarry` |

Запуск проверок:

```text
dotnet test src/besm-edu/Besm6.EduCpu.Tests          # все 49 тестов
dotnet run --project src/besm-edu/Besm6.EduCpu       # полный прогон с трассой
dotnet run --project src/besm-edu/Besm6.EduCpu -- --dump 0110 0110   # финальное состояние ячейки 0110
```

## 7. Краткое резюме

1. Сложение 48-битного слова идёт побитно, от бита 0 к биту 47, с переносом.
2. Без переноса за 48-й разряд результат — просто 16 восьмеричных цифр.
3. При переполнении 48 разрядов:
   - модульная схема — результат `sum mod 2^48` (перенос теряется);
   - циклическая схема (СЛЦ) — перенос прибавляется к младшему биту.
4. Программа машины выполняет сложение как последовательность
   «СЧ (в ACC) → СЛЦ (прибавить) → ЗП (записать)», что наглядно видно
   в трассе учебного примера.
