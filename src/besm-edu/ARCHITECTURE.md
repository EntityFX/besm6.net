# Структура кода учебного демонстратора БЭСМ-6

Документ описывает, как устроен код: что за что отвечает, как реализован
«пайплайн» одного шага процессора (выборка → декодирование → адресация →
исполнение → коммит → трасса) и как связаны основные, тестовый проект и консоль.
Исторический контекст и список сознательных упрощений — в
[`Besm6.EduCpu/README.md`](Besm6.EduCpu/README.md).

## 2. Зависимости модулей

```text
Oct ──┐
Op ───┼──► Instruction ──► Trace ──► TraceFormatter ──► Program.cs
Word48 ┘         ▲              ▲
      ┌──────────┘              │
Memory ─────────► Cpu ─────────┘
      └──────────► DemoProgram
```

Правило слоя: «нижние» типы не знают об «верхних».
`Oct`, `Op`, `Half`, `Word48` — чистые значения без зависимостей;
`Instruction` кодирует/декодирует 24 бита; `Memory` хранит слова;
`Cpu` собирает их в процессор; `Program.cs` и `DemoProgram` — обвязка.
Обратных ссылок нет, циклических зависимостей нет.

## 3. Пайплайн одного шага (`Cpu.Step()`)

Ядро модели — метод `Step()`. Один вызов = один цикл мини-пайплайна:

```text
┌─────────────── Step(): один цикл процессора ────────────────┐
│  0. Врата   STOP уже выполнен? → StepAfterStopException     │
│             снимок «до»: адрес, половина, ACC               │
│  1. FETCH   word = memory.Read(pc); raw24 = половина L/R    │
│  2. DECODE  Instruction.Decode(raw24) → Op, регистр M,      │
│             базовый адрес, мнемоника                        │
│  3. ADDR    EffectiveAddress: base + M[регистр] по mod 2^15 │
│             (для VTM поле — значение регистра, адрес мимо)  │
│  4. EXEC    Execute: ACC ← ACC op mem / mem ← ACC /         │
│             M[рег] ← адрес / переход / STOP                 │
│  5. COMMIT  pc ← (nextAddr, nextHalf); steps++              │
│  6. TRACE   неизменяемая запись Trace                       │
└─────────────────────────────────────────────────────────────┘
```

Ключевые инварианты (все покрыты тестами):

- **Атомарность проверки**: пока команда не прошла ваты 1–2
  (выборка + декодирование), архитектурное состояние не меняется.
  `UnsupportedOpcodeException` и `InvalidInstructionException` не оставляют
  частичных изменений.
- **Коммит после исполнения**: новая позиция и счётчик шагов фиксируются
  только после успешного `Execute`; переходы (`uj`/`uza`) перезаписывают
  позицию в этапе 4, а не «на лету».
- **Два снимка ACC в трассе**: запись хранит ACC до и после, поэтому
  детерминированность вывода проверяется полным сравнением строк
  (`DemoAndTraceTests`).

`Run()` — лишь обёртка-цикл: `Step()` до STOP, ошибки или лимита шагов.
Сама модель безвредна: нет потоков, нет внешних эффектов, нет `async`.

### Полный прогон: от холодного старта до STOP

**1. Холодный старт (до первой выборки).**
`Program.Main` собирает машину: `Memory` создаётся (32 768 слов, все нули),
`DemoProgram.Load` записывает программу (слова 000010–000014, 000020) и данные
(000100..000102), `new Cpu(mem, 000010)` выставляет командную позицию в 000010L.
Состояние: ACC = 0, M01..M15 = 0, счётчик шагов = 0. Машина полностью
детерминирована: одинаковая начальная память даёт одинаковую трассу
(проверяется в `DemoAndTraceTests`).

**2. Поток шагов (8 шагов встроенной программы).**

| # | Позиция | Команда | Что происходит | Следующая позиция |
|---|---------|---------|----------------|-------------------|
| 1 | 000010L | `vtm 000001(01)` | длинный формат; M01 = 1 | 000010R |
| 2 | 000010R | `xta 000100(01)` | адрес = 0100 + M01 = 0101; ACC = 5 | 000011L |
| 3 | 000011L | `arx 000102` | ACC = 5 + 7 = 14 (циклически) | 000011R |
| 4 | 000011R | `atx 000110` | mem[0110] = 14 | 000012L |
| 5 | 000012L | `aex 000110` | ACC ^= 14 → 0 | 000012R |
| 6 | 000012R | `uza 000020` | ACC == 0 → переход; слова 000013/000014 пропущены | 000020L |
| 7 | 000020L | `xta 000110` | ACC = mem[0110] = 14 | 000020R |
| 8 | 000020R | `stop` | выставлен флаг STOP | — |

На этом прогоне видно сразу несколько механизмов: оба формата команд
(шаг 1 — длинный, остальные — короткие), индексный регистр (шаг 2),
поток L→R внутри слова и переход между словами (шаги 1→2, 5→6),
переход, «перескакивающий» недостижимую ветвь (шаг 6), и запись,
а затем чтение одной и той же ячейки (шаги 4 и 7).

**3. Остановка и состояние после STOP.**
После шага 8 `_stopped = true`. Повторный вызов `Step()` упирается в врата
и бросает `StepAfterStopException`; цикл `Run()` завершается штатно.
Консольный фронт читает ячейку результата 000110 (14), печатает трассу
и сводку, процесс завершается кодом 0. Память при этом остаётся
доступной — можно читать, что получилось.

**4. Альтернативные окончания.**

- *Ошибка* — диагностическое исключение (адрес, широта команды, чужой код
  операции) пробрасывается наружу из `Run()` с контекстом позиции; машина
  не «восстанавливается» сама, состояние на момент ошибки сохраняется.
- *Лимит шагов* — `--max-steps N` / `Run(N)`: если за N шагов STOP не
  выполнен, бросается `StepLimitExceededException` (защита от зацикливания).
- *Пошаговый режим* — `--step`: каждый `Step()` делается вручную, Enter
  между командами; сам пайплайн при этом не меняется.

## 4. Кодирование команды (24 бита)

```text
Короткий формат (бит 19 = 0):
  23     20  19  18  17          12  11              0
 ┌─────────┬───┬───┬──────────────┬───────────────────┐
 │ 017 рег.│ F │ X │ 006 код оп.  │ 030 адрес (12 б.) │
 └─────────┴───┴───┴──────────────┴───────────────────┘
   4 бита  1 1    6 бит        12 бит   X=1 → адрес дополнен 070000

Длинный формат (бит 19 = 1):
  23    20  19         12  14              0
 ┌─────────┬────────────┬───────────────────┐
 │ 017 рег.│ 007 код оп.│ 077777 адрес (15)│
 └─────────┴────────────┴───────────────────┘
   4 бита   7 бит      15 бит
```

- **Флаг формата** (бит 19) читается первым — именно от него зависит
  разбор остальных бит (`Instruction.Decode`).
- **Расширенный адрес** (X, бит 18): у настоящих БЭСМ-6 «всплывает» битовый
  шаблон; здесь — константа `070000`, упрощение (см. README).
- **Коды операций** собраны в `Op` (`Op.cs`): значения = восьмеричные коды,
  поэтому `Enum.IsDefined(typeof(Op), …)` — естественная проверка
  «свой ли это код».
- **Односторонние коды**: у `vtm` и переходов адрес не применяется, но поле
  всё равно кодируется — так устроены учебные «длинные» слова
  0240/0260/0300/0330.

## 5. Данные машины

- `Word48` — 48 разрядов, побитовые `And/Or/Xor`, циклическое сложение
  (СЛЦ), модульное вычитание (2^48), умножение младших 24 бит. Все операции
  возвращают новый объект — тип неизменяемый.
- Память — 32 768 слов, адрес 15 бит (`Memory`), M0 при чтении всегда 0.
- Мнемоники — пары «английская/русская» (например `atx`/`ЗП`) — чтобы
  студент видел и современную, и историческую нотацию; исторический смысл
  слов см. в `book/` и `ref/`.

## 6. Ошибки (диагностика)

```text
CpuException  (адрес + половина команды)
├── OutOfRangeAddressException   адрес вне 0..077777   (Memory.Read/Write)
├── InvalidInstructionException  широта/состав полей    (Instruction)
├── UnsupportedOpcodeException   код не в Op            (Instruction.Decode)
├── StepAfterStopException       Step() после STOP      (Cpu.Step)
└── StepLimitExceededException   лимит шагов            (Cpu.Run)
```

Все исключения несут контекст позиции (адрес и половина), поэтому
сообщение об ошибке указывает, где именно остановился процессор.

## 7. Консольный фронт (`Program.cs`)

Отдельный «внешний пайплайн» — последовательность `Main`:

```text
разбор аргументов → DemoProgram.Load (заполнить память) → new Cpu(...)
→ листинг команд → исполнение (--step | до STOP | лимит)
→ печать трассы → дамп памяти (если задан --dump) → итог (причина, шаги, ячейка 0110)
```

| Режим | Что делает |
|-------|------------|
| без аргументов | полный прогон до STOP, трасса + итог |
| `--step` | один шаг, вывод только записи трассы |
| `--max-steps N` | не более N шагов; лимит — `StepLimitExceeded` |
| `--dump START END` | после выполнения печать «ДАМП ПАМЯТИ»: финальное содержимое диапазона адресов (восьмерично, включительно) |
| `--help` / `-h` | справка, exit 0 |

Коды выхода: `0` — STOP/успех; `1` — ошибка машины; `2` — некорректный
аргумент. Фронт никогда не трогает ACC/память напрямую — всё через `Cpu`.

## 8. Встроенная учебная программа (`DemoProgram.cs`)

```text
000010  L: vtm 000001(01)   R: xta 000100(01)   ← M01 = 1; ACC = mem[0101] = 5
000011  L: arx 000102       R: atx 000110        ← ACC = 5+7 = 14; mem[0110] = 14
000012  L: aex 000110       R: uza 000020        ← ACC ^= 14 → 0; переход (успех)
000013  L: uj 000014        R: —                 ← недостижимая «ветвь ошибки»
000014  L: atx 000111       R: uj 000014         ← (не исполняется)
000020  L: xta 000110       R: stop              ← ACC = 14; STOP
000100..102                данные: 3, 5, 7
000110 / 000111            результат / «ошибка»
```

Программа сознательно демонстрирует: оба формата, индексный регистр,
указательный адрес, ветвление и запись/чтение памяти. Итог проверяется
двумя способами: `Run()` возвращает состояние, а `DemoAndTraceTests`
сравнивает и строку трассы.

## 10. Ограничения и правила

- **1000 строк** — жёсткий потолок основного проекта
  (`LineBudgetTests`). Новые фичи обязаны «влезать» в потолок.
- **Ноль предупреждений** — `TreatWarningsAsErrors` в обоих csproj.
- **Ноль NuGet-зависимостей** — только .NET 8 BCL.
- **Один класс — один файл** (принято в репозитории).
- **Неизменяемость**: `Word48`, `Instruction`, `Trace` — `readonly`,
  мутации только у `Cpu` и `Memory`.
