# Справочник разработчика симулятора БЭСМ-6

Данный документ содержит краткое техническое описание реализации симулятора БЭСМ-6 на языке C#.

## 1. Архитектура системы

Симулятор построен по модульному принципу. Основным агрегатором является класс `MachineCore`.

### Основные компоненты:
- **`MachineCore`**: Точка входа, инициализирует все подсистемы и управляет жизненным циклом машины.
- **`ControlUnit` (CU)**: Реализует конвейер обработки команд (Fetch $\rightarrow$ Decode $\rightarrow$ Address Gen $\rightarrow$ Memory $\rightarrow$ Execute $\rightarrow$ Write Back).
- **`ArithmeticUnit` (AU)**: Выполняет все арифметические и логические операции. Поддерживает вычисления с плавающей точкой (40-битная мантисса, 7-битный порядок).
- **`Mmu`**: Модуль управления памятью. Преобразует математические адреса в физические, используя таблицу страниц (32 записи).
- **`RegisterBank`**: Хранит значения аккумулятора (A), счетчика команд (K), регистра режима (R) и 15 индексных регистров.
- **`BufferMemory` и `SuperOperationalMemory`**: Реализуют многоуровневое кэширование для ускорения доступа к памяти.
- **`SystemBus`**: Маршрутизирует запросы между процессором, основной памятью и периферийными устройствами.
- **`DeviceManager` и `DmaController`**: Управляют внешними устройствами и организуют прямой доступ к памяти для блочного обмена.

## 2. Формат данных: Word48

Все данные в системе представлены типом `Word48`, который эмулирует 48-битное слово БЭСМ-6.
- **Целочисленный режим**: 48-битное знаковое целое число.
- **Режим с плавающей точкой**:
    - 1 бит: Знак
    - 7 бит: Порядок (со смещением 64)
    - 40 бит: Мантисса

## 3. Система памяти и защита

Симулятор поддерживает разделение на режимы **Супервизор** и **Пользователь**.

### Механизм MMU:
- Математический адрес (15 бит) делится на номер страницы (5 бит) и смещение (10 бит).
- Таблица страниц определяет физический адрес и права доступа (`Read`, `Write`, `Execute`).
- Попытка доступа к памяти без соответствующих прав или выполнение привилегированной команды в пользовательском режиме вызывает системное исключение (`AccessViolationException`), которое обрабатывается переходом в режим супервизора.

## 4. Периферийные устройства

Реализованы следующие устройства:
- **`ConsoleDevice`**: Базовый вывод в консоль.
- **`DiskDevice`**: Эмуляция дискового накопителя (хранение в файле).
- **`MagneticDrumDevice`**: Эмуляция магнитного барабана с поддержкой блочного обмена.
- **`TeletypeDevice`**: Эмуляция телетайпа (символьный ввод/вывод).

## 5. Команды управления (Debugger)

Для взаимодействия с симулятором используется консольный отладчик:
- `step`: Выполнение одного такта.
- `run`: Запуск до остановки (K = -1) или прерывания.
- `regs`: Просмотр состояния всех регистров.
- `dump <addr>`: Просмотр содержимого памяти.
- `load <file>`: Загрузка бинарного образа программы.
