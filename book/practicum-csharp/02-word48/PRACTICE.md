# Практика к занятию 2. Реализация `Word48`

## Результат работы

Неизменяемый тип, который хранит ровно 48 бит, преобразуется в 16-значную
восьмеричную строку, выделяет командные половины и допускает целую и плавающую
интерпретации.

## Пошаговая работа

### Шаг 1. Закрепите инвариант 48 бит

```csharp
public readonly struct Word48 : IEquatable<Word48>
{
    public const ulong Mask = (1UL << 48) - 1;
    public ulong Value { get; }

    public Word48(ulong value) => Value = value & Mask;
}
```

Проверьте, что установка битов 48–63 не меняет сохранённое значение.

### Шаг 2. Реализуйте `ToOctal()`

Извлекайте 16 троек битов от младшей к старшей и заполняйте массив символов
справа налево. Нулевое слово обязано дать 16 нулей. Не используйте десятичное
форматирование как промежуточный шаг.

### Шаг 3. Реализуйте `ParseOctal(string)`

Уберите пробелы по краям, проверьте длину и каждый символ. Для очередной цифры
выполняйте `value = (value << 3) | digit`. Отклоняйте пустую строку, `8`, `9`,
минус и более 16 значащих цифр.

### Шаг 4. Добавьте знаковую целую шкалу

Реализуйте `ToSignedInt64()` и `FromSignedInt64(long)`. Если бит 47 установлен,
заполните единицами биты 48–63. Зафиксируйте тестами диапазон
`[-2^47, 2^47 - 1]`.

### Шаг 5. Выделите команды

Добавьте `LeftInstruction` и `RightInstruction` типа `uint`. Проверьте их на
слове, у которого половины различны и заранее вычислены вручную.

### Шаг 6. Добавьте плавающую интерпретацию

Сначала выделите порядок и знаковую мантиссу отдельными локальными величинами,
затем примените формулу из теории. Для обратного преобразования явно задайте
поведение нуля, переполнения, слишком малого числа, `NaN` и бесконечности.

### Шаг 7. Составьте таблицу интерпретаций

Для одного слова по очереди изменяйте бит порядка, знак мантиссы, младший бит и
бит левой команды. Записывайте шестнадцать восьмеричных цифр, целую шкалу,
`double` и обе команды.

## Обязательные тесты

1. Конструктор отбрасывает биты старше 47.
2. Ноль форматируется как `0000000000000000`.
3. Максимум форматируется как `7777777777777777`.
4. Парсер отклоняет недопустимые символы и лишнюю цифру.
5. Несколько слов проходят цикл `parse → format` без изменений.
6. Проверяются `0`, `1`, `-1`, минимум и максимум целой сетки.
7. Отрицательное значение правильно расширяет знак до `long`.
8. Из известного слова выделяются обе 24-разрядные команды.
9. Проверяются `0.5`, `1.0`, `2.0` и отрицательная степень двойки.
10. Обратное преобразование `double` сравнивается с допуском.
11. Равенство зависит только от 48 значащих бит.
12. Операции не изменяют исходный экземпляр.

## Типичные ошибки

- использовать `(1 << 48)` вместо `1UL << 48`;
- читать восьмеричную строку десятичным `Parse`;
- терять ведущие нули;
- путать знак целой шкалы со знаком плавающей мантиссы;
- менять местами левую и правую половины;
- сравнивать `double` через точное равенство.

## Критерии приёмки

- 4 балла — инвариант, восьмеричный формат и парсер;
- 2 балла — целая и командная интерпретации;
- 2 балла — плавающая интерпретация и границы;
- 2 балла — тесты и таблица влияния разрядов.
