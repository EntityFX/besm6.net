# Практическая работа 8. Минимальный процессор БЭСМ-6

Продолжительность: 2–3 часа.

## Цель

Интегрировать компоненты предыдущих работ и выполнить небольшую программу от
выборки первого слова до вывода результата и штатного останова.

## Поддерживаемое подмножество

Минимальный процессор должен поддерживать:

- чтение слова в ACC;
- запись ACC в память;
- сложение;
- `AND` либо `XOR`;
- установку M-регистра непосредственным значением;
- изменение M-регистра и цикл;
- безусловный переход;
- экстракоды `064` и `074`;
- команду STOP.

Конкретные коды операций выдаются преподавателем вместе с тестовой таблицей.

## Задание

Создайте `MiniBesm6Cpu` со следующими компонентами:

```text
Word48 + Registers
        ↓
InstructionDecoder
        ↓
Address generation
        ↓
Memory ↔ ALU
        ↓
Extracode handler / Device
```

Метод `Step()` должен:

1. выбрать командное слово по PC;
2. выбрать левую или правую половину;
3. декодировать команду;
4. заранее определить следующую позицию исполнения;
5. сформировать исполнительный адрес;
6. выполнить операцию;
7. сохранить изменённое состояние;
8. записать строку трассы;
9. вернуть признак продолжения или останова.

Метод `Run(int instructionLimit)` обязан завершаться при STOP, `074`, ошибке
или достижении лимита. Достижение лимита не считается штатным остановом.

## Итоговая программа

Процессор должен выполнить программу, которая:

1. проходит по небольшому массиву слов;
2. вычисляет сумму либо контрольную XOR-сумму;
3. сохраняет результат в память;
4. выводит сообщение через учебный `064`;
5. завершает задание через `074` или STOP.

Исходная программа может быть подготовлена преподавателем как массив
48-разрядных восьмеричных слов.

## Диагностическая часть

Преподаватель вносит одну ошибку:

- неверный код операции;
- неправильную половину командного слова;
- ошибочный номер M-регистра;
- адрес за пределами ожидаемой области;
- неверный переход;
- потерю ACC/RMR после экстракода;
- отсутствие останова.

Студент должен локализовать ошибку по трассе, сформулировать причину, исправить
её и продемонстрировать различие трасс до и после исправления.

## Обязательные проверки

- переход `L → R → L следующего слова`;
- правильное изменение PC при переходе;
- исполнительный адрес с M-регистром;
- чтение, запись и операция АЛУ;
- пропуск правой половины после экстракода слева;
- штатный и аварийный останов;
- ограничение бесконечного цикла;
- воспроизводимость трассы.

## Результат работы

- интеграционная модель процессора;
- выполняемая тестовая программа;
- автоматические тесты ключевых контрактов;
- трассы до и после исправления ошибки;
- защита продолжительностью 5–7 минут.

## Контрольные вопросы

1. На каком этапе определяется смысл 48-разрядного слова?
2. Почему следующую позицию исполнения полезно вычислить до операции?
3. Какие компоненты можно заменить, не изменяя остальные?
4. Как по трассе отличить ошибку декодирования от ошибки АЛУ?
5. Чем STOP отличается от превышения лимита команд?
